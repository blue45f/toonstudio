# Shaper 기능 대조와 실제 동작 연결 기록

상태: **current** (2026-10-29). 이 문서는 이번 변경의 근거와 검증 범위를 기록한다. 이전 집계는 [패리티 체크리스트](shaper-parity-checklist.md), 영역별 현재 동작은 [비전](parity/vision.md)과 [출력·페인트](parity/export.md)를 함께 읽는다.

## 1. 확인한 제품과 근거

[Shaper 공식 사이트](https://shaper.webtoons.com/)는 Windows·macOS 설치형 편집기의 소개와 사용법을 제공한다. 웹 주소 자체를 브라우저 편집기로 취급하지 않았다. [공식 사용법](https://shaper.webtoons.com/how-to/), [2026-04-23 공지](https://shaper.webtoons.com/notice/01/), [공개 라이선스 목록](https://shaper.webtoons.com/licenses/)과 공개 시연을 기능 근거로 사용했다.

공개 자료에서 확인한 흐름은 14개 파트 프리셋, 얼굴·머리·의상·체형·포즈 조절, 모델 표면 드로잉, 프리셋 재사용, 참고 이미지 추천, 사진·카메라의 전신·손 포즈 인식, 실시간 손 추적, 투명 데스크톱 창, 선·음영·밑색 PSD 출력이다. 특정 morph 개수·수치 범위, GLB·FBX·VRM 내보내기, 추론 정확도·지연·오프라인 동작은 공개 자료만으로 확정하지 않았다.

로컬 설치본은 런처 안에 편집기가 중첩된 구조였다. 런처의 Mach-O 분석은 REA의 **Ghidra** 제공자를 명시해 수행했고, 문자열의 중첩 앱 경로를 실제 파일로 대조했다. 편집기 `Assembly-CSharp.dll`은 실행하지 않고 REA의 관리 코드 메타데이터·멤버 서명만 읽었다.

## 3. 후속 고도화 목표

상태: **target**. 아래는 이번 변경으로 완료된 기능과 구분한다.

1. 설치형 Shaper의 실제 UI 조작을 확인하고 같은 입력 사진·포즈·카메라·출력 조건으로 비교한다. 정확도·latency·완성도 우위는 측정 뒤 판단한다.
2. 연속 IMAGE 손 인식의 실제 카메라 지연·장시간 메모리·관절 안정화를 검증한다. 현재 순차 처리와 취소를 유지하면서 VIDEO 모드·worker 분리는 별도 실증 후 도입한다.
3. 고품질 생성 캐릭터는 원본, 리토폴로지, 스켈레톤, 실제 변형 검사, 파츠 분리·피팅을 차례로 통과시킨다. 파일 이름이나 생성 프롬프트로 rig·morph·모듈식 기능을 있다고 판정하지 않는다.
4. 런타임에 반입할 캐릭터에는 체형·표정 morph, 공통 본 규약, 목·어깨 이음매, 손가락 변형, 의상 관통, 헤어 피팅, 얼굴과 손 근접 렌더 기준이 필요하다.
5. 고도화된 렌더 기능은 실제 셰이더·재질·PNG/PSD 결과를 함께 연결한다. UI에 수치만 추가해 기능을 대체하지 않는다.

첫 Character Lab 전체 병렬 실행에서는 물리 settle 한 사례가 기존 5초 제한으로 실패했다. 테스트 제한이나 소스를 완화하지 않았으며, 자체 의존성을 갖춘 뒤 작업자 수를 2로 제한해 두 설정의 전체 테스트를 다시 실행했다.

기본 키트 바디의 어깨·겨드랑이 형상은 원본 GLB를 Blender에서 직접 불러와도 재현됐다. 원천 A 포즈와 T 포즈 변환 단계를 비교하는 별도 후보 검수를 진행한다. 기능 테스트·픽셀 존재 검사를 통과했다는 이유로 이 형상을 미학적으로 승인하지 않는다. 생성한 Tripo 자산도 고밀도 원본과 리깅 파생물, 구조 통과와 변형·시각 승인을 분리해 기록한다.

어깨 후보는 거상 85°의 ROI 최대 간선 비율 3.299→2.176, 2배 초과 간선 77→5로 개선됐고 실제 import 뒤 목 공유 정점 115쌍은 검사한 6포즈 모두 틈 0mm였다. 기존 티셔츠를 그대로 쓰면 어깨 간격 P95가 22.20→52.13mm로 커지며 재피팅이 필요하다. 따라서 제작기 옵션과 표준 수정만 보존하고 현재 공개 바디·의상은 바꾸지 않는다. morph bounds는 [glTF 2.0 공식 명세](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html)의 accessor bounds·morph target 규약에 따라 normalized 여부와 무관한 실제 버퍼 성분을 기록한다.

웹 파일 출력 진단의 renderer는 SwiftShader WebGL2이며 pageerror는 0이었다. 로컬 Core API 4001번 포트 부재로 발생한 502 콘솔 오류는 별도로 남았다. 이 진단과 실제 파일 검사는 네이티브 포인터의 전체 동선, 실GPU 성능, 운영 서버 연결 검증을 대신하지 않는다. 기존 브라우저 verifier의 선택자·시간 제한·픽셀 허용 오차는 변경하지 않았다.

제작 패키지 표시 정리 뒤 Character Lab 타입·빌드를 다시 통과했고, PackagePanel 18개 회귀는 루트·앱 설정 모두 통과했다. 최종 브라우저 프로브도 11통과·0실패·1건너뜀으로 확인했으며 renderer 범위는 위와 동일하다.
