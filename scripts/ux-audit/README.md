# UI/UX 자동 측정 하니스 (`scripts/ux-audit`)

- 상태: **current** (2026-10-16 기준, 점수 규칙 버전 1.0.0)
- 목적: UI·UX 품질을 "측정 가능한 증거"로 평가하고 기준선 점수를 낸다. 이 도구는 제품 화면을 고치지 않는다.
- 운영 영향: **없음.** 실행 대상은 로컬 풀스택(127.0.0.1)이다. 로그인 자격증명은 loopback origin 에만 보내며, 읽기만 하고 어떤 출력·파일에도 남기지 않는다.
- 기준선 결과: [`docs/reports/ux-audit-baseline-2026-10-16.md`](../../docs/reports/ux-audit-baseline-2026-10-16.md) — 개발 서버 합계 95.12, 시간 지표를 최악으로 가정한 하한 89.71. 운영 빌드 재측정 전에는 "95점 달성"이라고 쓰지 않는다.

## 무엇을 재는가

라우트 34개(공개 22 · 로그인 필요 12) × 뷰포트 3종(모바일 390×844 · 태블릿 768×1024 · 데스크톱 1440×900)을 실제 Chromium 으로 열어
다음을 자동 측정하고, 핵심 여정 6개(새 작품 → 에디터, 예제 열기, 템플릿 → 작품, 로그인 → 로그아웃, 설정 변경 후 복귀, 오류 복구)를 실행한다.

## 실행

전제: 저장소 루트에서 `pnpm install` 완료, Node 24 이상, Chromium. 이미지에 고정된 Chromium 은 `PLAYWRIGHT_EXECUTABLE_PATH` 로 지정한다
(번들 Chromium 은 `pnpm exec playwright install chromium`). 로컬 풀스택 사용법은 [`scripts/local-fullstack/README.md`](../local-fullstack/README.md) 와
[`docs/operations/local-fullstack-verification.md`](../../docs/operations/local-fullstack-verification.md) 를 따른다.

```bash
# 1) 계획만 보기 — 라우트 목록과 측정 칸 수를 출력한다(브라우저·스택·자격증명을 쓰지 않는다)
node scripts/ux-audit/run.mjs --dry

# 2) 측정 도구 자체 점검 — 알려진 결함을 심은 내장 HTML 로 측정 코드를 확인한다(스택 불필요, Chromium 필요)
PLAYWRIGHT_EXECUTABLE_PATH=/opt/pw-browsers/chromium node scripts/ux-audit/run.mjs --self-check

# 3) 로컬 풀스택 시작(부작용: 임베디드 PostgreSQL·API·Vite 개발 서버 기동)
node scripts/local-fullstack/cli.mjs up

# 4) 전체 측정 — 약 30~40분. 결과는 artifacts/ux-audit/<UTC시각>/ 아래에 쓴다(git 무시)
PLAYWRIGHT_EXECUTABLE_PATH=/opt/pw-browsers/chromium node scripts/ux-audit/run.mjs

# 5) 끝나면 반드시 내린다
node scripts/local-fullstack/cli.mjs down

# 두 보고서의 점수 차이 비교
node scripts/ux-audit/run.mjs --compare artifacts/ux-audit/<A>/report.json artifacts/ux-audit/<B>/report.json
```

옵션: `--routes a,b` · `--viewports mobile,desktop` · `--auth public|user` · `--journeys 목록|all|none` · `--journeys-only` ·
`--base-url URL` · `--server dev|production` · `--out DIR` · `--no-screenshots` · `--no-warmup` · `--print-rubric` · `--json` · `--help`.
종료 코드: 0 성공(점수가 낮아도 0), 1 예기치 못한 오류·산출물에서 비밀값 발견, 2 사용법·스택 미기동.

## 산출물

`artifacts/ux-audit/<UTC시각>/` (저장소 `.gitignore` 의 `/artifacts/` 로 무시되며 **커밋하지 않는다**)

- `report.json` — 칸별 사실·점수, 화면별/영역별 요약, 최저점 화면, 위반 상위 유형, 여정 결과, 환경 정보

- `screens/<라우트>-<뷰포트>.jpg` — 칸마다 1장(뷰포트 크기)
- `journeys/<여정>-막힌지점.jpg` — 여정이 막혔을 때만

## 점수에 넣지 않는 것 (사람 판단·환경 한계)

- 시각 위계의 미적 완성도, 정보 구조의 직관성, 카피의 설득력은 점수에 넣지 않고 보고서의 "미측정" 표로 분리한다.
- 실제 스크린 리더·음성 제어, 실기기(iOS Safari·Android Chrome), 운영 빌드의 성능 체감은 이 도구가 재지 않는다.
- 자동 측정 점수 95점을 곧 사용성 95점이라고 부를 수 없다. 이 점수는 "자동으로 확인 가능한 결함이 적다"는 증거일 뿐이다.

## 해석할 때 알아둘 점

- 측정은 Vite 개발 서버(로컬 풀스택)에서 한다. React StrictMode 이중 마운트 경고(`[LEASE_BUSY]`)는 개발 서버 한정이라 점수에서 빼고 개수만 남긴다.
  운영 빌드(`--server production`)에서는 시간 지표도 점수에 들어간다.
- 로컬 DB 가 비어 있어 콘텐츠 화면은 "빈/오류 상태"로 측정된다. 운영 데이터의 화면 밀도와 다를 수 있다.
- 네트워크 오류·콘솔 오류 중 측정 환경 때문인 것(취소된 요청, 외부 origin, git 이 추적하지만 sparse 체크아웃으로 내려받지 않은 public 파일의 404)은 점수에서 빼고
  `performance.details.ignored` 에 개수를 남긴다.
- 카피 휴리스틱(번역 키 패턴, 3단어 이상 영어 문장)은 오탐·미탐이 있다. 보고서는 탐지된 문자열 원문(표본)을 함께 싣는다.
- 시각 일관성은 클래스 문자열 기반 휴리스틱이다. Tailwind 컴파일러로 유틸리티를 해석하지 않으므로 색이 아닌 값 이름은 허용 목록으로만 거른다.
  DESIGN.md 가 rgb()/hex 대신 OKLCH 를 요구하므로 OKLCH 리터럴은 위반으로 세지 않고 참고 값(`oklchLiteralClasses`)으로만 남긴다.
- 반응형 측정은 Chromium 에뮬레이션이다. 가로로 넘치는 문서는 모바일 에뮬레이션에서 `window.innerWidth` 가 늘어나므로 레이아웃 뷰포트 폭(`clientWidth`)을 기준으로 한다.

## 보안

- 자격증명은 `scripts/local-fullstack/lib/harness-env.mjs` 와 같은 방식(프로세스 환경변수 → `.env.infrastructure.local`)으로 읽는다. 값은 비공개 필드에만 두고 로그·JSON·예외 메시지에 싣지 않는다.
- 로그인 대상 origin 이 loopback 이 아니면 자격증명을 보내지 않고 로그인 필요 라우트·여정을 "건너뜀"으로 기록한다.
- 로그인 상태(쿠키)는 메모리의 `storageState` 로만 들고 있다. 끝날 때 `report.json` 등 산출물에서 비밀값 일치를 검사한다(`scanForSecrets`).
- 스크린샷에는 계정 메뉴의 이메일 등이 찍힐 수 있다. 그래서 산출물은 커밋하지 않는다.
