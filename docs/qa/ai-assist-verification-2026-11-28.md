# 창작 보조의 병렬 작업과 Astra 실호출 검증

상태는 `current`이며 검증 대상은 변경한 소스와 QA 프로젝트다. 운영 배포는 별도 절차다. 2026-11-28에 합성 원고로 확인했다. 제품 변경 전 기준 커밋은 `beccb3597e`다. 기본 설정 310건에는 실제 도구 인자를 설명하는 매크로 지침을 포함했다. 이후 추가한 권리·현지화 지침은 같은 원고를 사용한 비교 시험과 별도 평가 자료로 검증했다.

## 작가가 확인할 수 있는 변경

- 무료 AI 작업대에서 대사와 콘티처럼 서로 다른 모드를 각각 실행할 수 있다. 탭을 바꿔도 작성한 초안과 결과를 해당 모드에 보관한다. 선택한 모드만 취소하며, 작업대를 닫으면 진행 중인 요청을 정리한다.
- 내보내기 코치에서 로컬 PNG·JPEG의 폭·높이·바이트 수를 확인할 수 있다. 작가가 추가 버튼을 누르면 측정값이 편집 중인 원고에 들어간다. 이미지 파일과 파일명은 AI 요청에 포함하지 않는다. JPEG는 파일에 인코딩된 방향을 기준으로 한다.
- 발상 리믹스는 다섯 번째 안과 각 안의 첫 컷을 표시한다. 스크롤 코치는 구간별 간격과 구간 평균을 표시하고 로컬 예시의 고정 점수는 숨긴다. 용어집은 한국어·영어·일본어, 표기 규칙, 문화권별 주의사항을 화면과 복사 결과에 보존한다.
- 제작 매크로는 캔버스 생성, 3D 장면 구성, 레이어 효과, 내보내기 점검 도구의 실제 인자와 반환값을 기준으로 단계를 작성한다. 특정 인물 레이어가 필요하면 실제 ID를 확인하는 단계를 설명한다.
- 무료 작업대에서 마감 점검의 전체 항목과 중요도, 콘티의 구도·컷 간격, 연속성 오류의 위치·수정안, 3D 카메라 좌표·광원, 효과음 3개 언어와 식자 위치, Photoshop 보정 수치, 썸네일 규격과 매크로의 원문 인자를 화면과 복사 결과에서 확인할 수 있다.

## 검증과 해석

| 확인 항목 | 결과 | 판정 범위 |
| --- | --- | --- |
| 병렬 편집과 측정값 첨부 | 실제 Chromium 1280×820과 390×844에서 두 작업의 응답 순서를 뒤집어도 각 원고·결과·클립보드가 일치했다. 320×512 PNG를 선택하고 측정값을 붙이는 단계의 POST는 0건이었다. 실행 후 전송된 JSON에는 원고와 측정값이 포함됐다. | 현재 작업대 컴포넌트를 독립적으로 마운트하고 로컬 서버 응답을 사용했다. |
| 서비스 기본 설정의 Astra | 합성 원고 50편으로 만든 원본 200건, 연속성 정상 대조군 10건, 나머지 기능의 확장 사례 100건이 모두 서비스 출력 검사를 통과했다. 310건의 응답 시간 중앙값은 14.7초, 95백분위는 26.0초였다. | 실제 서비스가 만드는 Chat Completions 본문과 `low` 추론을 사용했다. QA 프로젝트에서 측정한 API 왕복 시간이다. |
| Astra 최고 추론 강도 | Responses API는 `reasoning.effort=max` 입력을 수락했다. 첫 대사 사례는 출력 한도 2,048토큰 중 추론에 1,979토큰을 사용해 미완료로 끝났다. | 사용량이 있는 미완료 요청도 비용 집계에 포함한다. 무료 입력 토큰 계산은 생성 성공이나 한국어 품질 판정에 포함하지 않는다. |
| 실행 가능한 매크로 | 첫 응답은 4단계 모두에서 미지원 인자를 제안했다. 지침 수정 후 같은 원고로 얻은 서비스 기본 설정과 `max` 결과는 각각 3개 자동화 단계를 반환했고, 모든 인자가 실제 도구 스키마와 일치했다. 나머지 작업은 수동 확인 대상으로 안내했다. | 로컬 도구 목록으로 이름·필수 인자·자료형·열거값을 대조했다. 작가 문서에 매크로를 실행하지 않았다. |
| 내보내기 권리 확인 | 서로 다른 합성 원고 2편에서 매크로가 권리 확인 결과를 생략했다. 도구가 미확인 입력을 통과시키던 문제를 수정했다. 필수 검사는 명시적인 완료 확인이 있을 때 통과하며, 검사 생략을 지정한 결과에는 생략 상태를 표시한다. 같은 원고·모델·출력 한도에서 미확인 값을 명시하라는 지침 한 문장을 추가했다. 해당 값을 정확히 명시한 원고는 기존 3/5편에서 수정 후 5/5편으로 늘었다. 이 중 3편은 별도 평가 원고였다. | MCP 서버 테스트에서 누락·거짓·잘못된 자료형·명시적 완료·생략 및 해상도 검사와의 조합을 확인했다. |
| 내보내기 이미지 실험 | 자체 제작한 3개 단편을 세로로 나눈 PNG 36장을 사용했다. 개발 6쌍과 별도 평가 12쌍에서 말풍선 바깥 잘림, 분할선 절단, 인쇄된 순번 중복, 제공된 폭과 800px 일치 여부의 5개 필드가 모두 기대값과 일치했다. | 단편과 도형을 이용한 별도 비전 평가다. 다양한 실제 원고에서의 성능은 측정하지 않았다. |

기대 엔딩 점수는 기존 합성 자료의 0~10점 구간을 0~100점으로 환산해 비교한다. 연속성은 의도적으로 심은 오류를 찾는지와 오류를 고친 뒤 같은 문제를 다시 지적하는지를 별도로 채점한다. 모델을 가리고 원문 인용을 확인한 자동 평가 결과는 사람 편집자의 선호도나 경쟁 제품의 점수를 대신하지 않는다.

12개 기능의 원고 200건 중 모든 편집 조건을 충족한 사례는 167건이다. 기능마다 조건과 원고 수가 달라 이 비율을 제품 전체의 정확도로 사용하지 않는다. 제작 매크로에서는 레이어 ID가 없는 원고 2편에서 수동 확인·불투명도·재개 조건을 요약에 설명했지만, 자동 단계의 인자만 찾는 최초 평가표가 이를 감점했다. 모든 기능의 표본은 작가의 실제 비공개 원고를 사용하지 않은 합성 자료다.

**편집 심사의 재현성.** 최초 심사의 조건 920개에는 통과 878개, 미충족 34개, 판단 유보 8개가 있었다. 미충족·유보 42개를 추론 강도 `low`에서 한 조건씩 재심했다. 원고와 응답 양쪽의 인용을 확인한 32개 중 16개는 조건 충족, 16개는 미충족이었다. 응답에서만 인용을 확인한 매크로 조건 6개도 미충족으로 판정됐다. 나머지 4개는 재심 인용을 확인하지 못했다. 최초 통과 항목 중 대조용으로 고른 100개를 같은 방식으로 재심했을 때 94개에서 충족 근거를 다시 확인했다. 기능별 표에는 최초 평가값을 보존했다.

**배색의 실제 표시.** 합성 원고 10편에서 나온 OKLCH 색상 46개를 Chromium의 sRGB 캔버스에 그린 뒤 픽셀을 읽었다. 영수증 바탕과 인쇄 글씨는 11.84∶1, 비춘 장부 종이와 잉크는 11.79∶1, 좌석표와 글씨는 12.61∶1, 명패·말풍선과 글씨는 16.07∶1이었다. 색상이 읽히더라도 어느 부분에 적용할지 빠질 수 있다. 영수증 장면에서는 잉크와 종이색에 가까운 압흔이 차지하는 면적 차이를 설명하지 못했다. 실제 작화 위 글씨의 가독성은 미측정이다.

**작업대의 제작 정보 보존.** 실제 API 응답 310개를 기존 작업대와 수정한 작업대에 다시 입력했다. 작가에게 전달할 문자열 필드 4,877개에서 원문 또는 해당 한국어 중요도 라벨이 실제 표시 문구에 있는지 검사했다. 기존 요약에서는 230개 응답의 1,844개 필드가 누락됐고, 수정 후 310개 응답에서 누락이 0개였다. 마감 점검 43개 중 마지막에 있던 실물 확인 안내 3개도 보존됐다. 숫자 필드는 이 문자열 분모에서 제외하고 렌즈·좌표·보정 수치, 0과 음수는 별도 단위 테스트로 확인했다. 데스크톱 1280×820과 모바일 390×844 Chromium에서 모드별 실제 응답 하나씩을 표시했다. 28번 모두 줄 목록과 복사 결과가 일치하고 가로 넘침이 없었다. 재생은 로컬에서 수행했다.

**추론 강도에 따른 차이.** 같은 원고 140건의 Responses API 입력과 출력 한도를 고정하고 강도만 바꿨다. low와 medium은 각각 140/140건의 유효한 결과를 반환했다. max는 85건 유효, 48건 출력 한도 도달, 7건 상태 미확인이었다. 생성 콘티를 현지화·연속성·모바일 호흡에 보내는 후속 150건에서는 low 150/150, max 83/150건이 유효했다.

**대사 개선안.** 같은 원고 50편에서 세 안의 문장을 구별할 수 있는 사례가 45편에서 50편으로 늘었다. 편집 조건 전체 통과는 양쪽 모두 48편이었다. 후보에서 한 인물의 경험을 여러 사람의 행동으로 일반화하거나 원고에서 확정하지 않은 행동 주체를 지정한 사례가 나왔다. 별도 생활 단편 16편에서는 기본 지침으로 각 편의 사실·조건·말높임을 보존했고, 16편 모두 인용 근거를 포함한 편집 조건을 통과했다.

작업대는 같은 발화를 여러 말투로 반환한 경우 각 말투의 이유를 유지하고, 어느 안과 대사 문구가 같은지 표시한다. 비교에서만 유니코드와 공백을 정규화한다. 실제 작업대를 띄운 Chromium 데스크톱과 모바일에서 중복 안내와 연출 이유를 화면과 클립보드에서 확인했다. 중복 표시가 추가한 생성 요청은 0건이었다.

**현지화 개선안.** 말장난·행정 용어 등에서 누가 무엇을 가리키는지 장면과 연결하도록 지침을 수정했다. 동일 원고 10쌍에서 편집 조건 전체 통과가 7편에서 9편으로 늘었고, 새로 만든 동음이의어 장면 12쌍에서는 뜻을 원고의 구체적인 행위와 연결한 사례가 10편에서 11편으로 늘었다. 승인한 영·일 표기 일치는 양쪽 모두 12/12였다. 심사 요청을 만들 때 한 개의 평가 항목에 세 항목용 결과 스키마를 연결한 오류를 발견했다. 해당 24개 심사 결과를 제외하고 원래 생성 결과에 바로잡은 평가표를 적용했다.

**제작 매크로 재평가.** 자동 단계만 검사한 최초 점수와 별도로, 대상 레이어가 원고에 없을 때 정확한 수동 작업·수치·재개 조건을 명시하는 방식도 인정했다. 같은 원고 10편에서 제작 의도를 모두 충족한 사례는 7편이었다.
