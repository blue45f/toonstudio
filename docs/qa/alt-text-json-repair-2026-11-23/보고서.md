## 이미지와 복구 메시지

- A는 411바이트 PNG(96×64), SHA-256 `3b68d98847c0a5e7a6134eb0ff10b46928e04568a83fda96bfeecf349f85651b`였다. 각 시험의 첫 요청과 복구 요청에 실린 이미지 바이트를 디코딩해 직접 대조했고, base64 문자열 해시도 일치했다.
- B는 451바이트 PNG(112×64), SHA-256 `a4c590d244f16e7ac27dd664c07ac02f66aa690a86679b971f9ab94c8d3d2882`였다. B 요청에는 B 이미지 한 장이 있었고 A의 잘린 답을 식별하는 표식은 없었다.
- HTTP 200의 정상 메시지 안에 끝이 잘린 JSON 문자열을 넣었다. 복구 요청은 원래 사용자 메시지 전체, 잘린 답, JSON을 고쳐 달라는 지시를 차례로 담았다. 시스템 지시와 출력 스키마는 같았고, 요청을 구분하는 멱등 키는 달랐다. [요청별 해시와 역할 순서](measurements.json)

## 취소, 저장, 재열기

복구 요청을 보류한 동안 화면은 “이미지를 보고 설명을 쓰는 중이에요”와 경과 시간을 표시했다. 두 취소 시험에서는 두 번째 요청에 한해 시험용 전송 계층이 중단 신호를 기록하면서도 응답을 브라우저의 fetch까지 전달했다. 각각 중단 신호 1회, 늦은 응답 수신 1회였다. 이 조건에서 대화상자 본문, 입력값, 미리보기 설명을 화면 갱신과 DOM 변경 시점에 관찰했다. [A 유지 화면](run3/stop/stop-repair-ui/02-A유지-늦은응답후.png) · [B 선택 후 늦은 A 응답을 받은 화면](run3/cancel/cancel-repair-ui/03-B-늦은A반환후.png)

합성 작가 세션마다 포인터로 획 하나를 그린 뒤 기기에 저장된 문서를 읽었다. 응답 전후와 같은 원고를 다시 연 뒤 페이지 해시, 획 ID와 개수, 캔버스에서 가져온 전체 RGBA 픽셀 해시를 비교했다. 세 경우 모두 일치했다. 저장 원문에서 A·B 결과와 잘린 답의 표식도 발견되지 않았다. 정상 결과는 대화상자에 표시되며 복사·붙여넣기 동작은 시험에서 수행하지 않았다.

## 실행 전 안내에서 읽을 수 있는 내용

관리형 상세 안내는 전송 범위를 “이미지 1장(96×64px, 1KB)과 입력한 메모 글”로 표시했다. 공급자가 바쁠 때의 처리 순서는 설명하지만, 형식 복구가 발생하면 같은 이미지 바이트가 한 번 더 전송된다는 설명은 없었다. 복구 중에도 일반 생성 대기 문구가 유지됐다. [펼친 안내와 원문](run3/stop/events.jsonl) · [실행 전 화면](run3/stop/stop-repair-ui/01-실행전-전송안내.png)

## 검증 경계와 실행 기록

- 격리 체크아웃은 `~/.codex/worktrees/4d16/toonstudio`였다. 정리됐던 체크아웃은 이전 수정이 담긴 정확한 로컬 커밋으로 복원했다. 그 부모는 `0d0a0df1a92b66de194441bc3efd31128eb3bda4`다. 확인한 브라우저는 Chromium 159.0.8154.6이고, 매 실행마다 전용 임시 프로필을 사용했다. 모바일은 Chromium 화면·터치 에뮬레이션이다.
- 앱과 테스트 프로세스는 OS 수준에서 전용 루프백 포트 47631만 outbound로 허용했다. 브라우저도 같은 주소의 정적 파일만 통과시키고 로그인 조회·생성 응답은 합성 데이터로 처리했다. 그 밖의 앱 API는 로컬 503으로 종료했다. 전체 WebSocket과 서비스 워커를 차단했다. 서비스 워커는 실행하지 않았고, 개발 서버의 WebSocket 연결 실패는 예상된 기록이다.
- 통과한 세 실행마다 외부 `https://deny-proof.invalid` GET 1건과 허용하지 않은 로컬 포트 47634 GET 1건을 가로채 차단했고, 두 호출이 모두 브라우저에서 TypeError로 끝났음을 기록했다. 해당 실행들의 외부 origin 차단 목록에는 이 외부 점검 주소만 있었다. 실제 백엔드·AI 공급자 요청과 외부 데이터 전송은 0건이다.
- 데스크톱 준비 시도 2회는 각각 로컬 서버 연결 거부와 화면 초기 로딩 150초 초과로 끝났다. 두 시도 모두 생성 요청 0회였다. 같은 SHA·포트에서 서버를 다시 시작하고 초기 로딩 대기만 연장한 뒤 실제 원고까지 검증했다. [연결 거부](run1/cancel/summary.json) · [로딩 시간 초과](run2/cancel/summary.json) · [직렬 실행 명령](logs/serial3.sh)
- 현재 소스의 형식 복구·응답 계약 단위 검사 5건이 통과했다. 복구한 답도 틀리면 추가 요청 없이 형식 오류를 반환하고, 복구 중 공급자 처리 여부가 불명확해져도 재전송하지 않는 경우를 포함한다. 제목으로 선택하지 않은 22건은 이 실행에서 제외됐다. 이 단위 결과는 브라우저 7회 집계에 들어가지 않는다. [검사별 결과](logs/focused-unit.txt)

제품 소스 수정, 새 커밋, PR, 병합 및 배포는 없었다. 실제 공급자의 이미지 수신·처리·보관·비용과 서버 저장은 미검증이다. 실제 공급자 시험은 정확한 조직·프로젝트의 포함 허용량, 초과 과금 강제 차단, 이미지와 메모 전송 범위를 독립 확인한 뒤 별도 지시가 있을 때 진행한다. 후속 로컬 UI에서 남은 경계는 복구 답까지 깨졌을 때 마지막 오류 안내와 사용자가 재시도를 직접 누르기 전 요청 수다.

## 로컬 재현

