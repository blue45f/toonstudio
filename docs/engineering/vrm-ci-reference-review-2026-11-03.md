## 러너 관찰과 한계

PR #2676의 Core production build 작업 126126255645는 GitHub 호스팅 ubuntu-24.04 러너에서 수행됐다. shallow fetch는 19:07:07~19:38:54 UTC, 파일 체크아웃은 19:38:54~19:39:15 UTC였다. 35분 작업 제한 때문에 의존성 설치와 실제 빌드가 실행되지 않았다. 손 시각 검사도 체크아웃 도중 20분 제한에 걸렸다. 이는 빌드·렌더 성공을 뜻하지 않는다.

로그에 fetch 지연의 세부 네트워크 원인까지 드러나지는 않는다. 테스트·전체 빌드 자산·제한 시간을 변경하거나 유료 러너를 추가하지 않았다. 최신 main 반영 후 실행 결과를 다시 확인해야 한다.

## 손 시각 감사 부트스트랩 시험의 기존 버전 불일치

워크플로의 `setup-node@v7` 갱신 후 부트스트랩 시험에는 `v6` 검색 조건이 남아 4개 중 2개가 실패했다. 시험의 버전 참조를 현재 `v7`으로 맞췄다. pnpm 선행 설치 순서와 캐시 설정 검사, 실제 번들 모델 존재 검사는 유지한다. 수정 후 4개 시험이 모두 통과했다.

## 실제 후속 CI 실패 수정

- #2676의 studio-3d 작업 126185704293은 BG3D 계층→컷 버전→장면 문서 순환 경로에서 기본 문서를 먼저 생성해, 레시피가 없는데도 아직 초기화되지 않은 한도 상수를 읽어 6개 suite가 실패했다. 레시피 봉투의 기존 형태 검사로 빈 입력을 먼저 반환하고, 실제 레시피가 있을 때만 한도를 읽도록 했다. 레시피 수·크기·내용 제한은 유지했다. 계층 모듈을 먼저 import하는 회귀 시험을 추가했다. 기존 6개 실패 묶음과 경계 시험 8개 파일 143개, 동일 studio-3d CI 묶음 94개 파일 1,393개 시험이 통과했다.
- focused validation 작업 126185696790은 이벤트 기준 ba7786ed4 커밋이 depth 2 checkout에 없어 exit 128이었다. 이벤트 이후 main이 앞서면 merge ref의 두 부모는 최신 main과 PR head이고, 이전 이벤트 기준 커밋은 두 단계 밖으로 밀릴 수 있다. blob 필터를 유지하고 초기 인증 checkout에서 커밋·트리 전체 이력을 받도록 PR은 depth 0을 사용하고 수동 실행은 depth 1을 유지한다. 인증 종료 후 원격 fetch는 추가하지 않는다. 기준 존재 확인·GIT_NO_LAZY_FETCH·경로 비교 규칙은 유지한다.
- main이 세 커밋 앞선 실제 Git fixture에서 기존 depth 2의 누락을 재현했다. 수정된 이력에서는 원격을 사용할 수 없게 해도 기준 커밋과 경로 차이를 읽고, 기준 원문 blob은 내려받지 않음을 확인했다. 기존 CI 계약 28개와 새 회귀 시험이 통과했다.
- 별도 클라우드 네트워크 probe에서 전체 blobless 이력은 25.91초, Git pack 25.39MiB로 확보됐고 이벤트 기준 커밋도 존재했다. 다른 호스트·시점인 GitHub CI의 시간·전송량 보장은 아니다.
- #2683의 납품 미디어 제외 규칙·워크플로는 복제하거나 수정하지 않았다. 손·Core 검사 입력과 시간 제한은 유지한다. 최종 GitHub CI와 main 병합 결과는 PR에서 별도로 확인한다.

## 통합 UI 러너 디스크 실패 수정

- 신규 #2676 작업 126206940973은 Node 설정 단계에서 러너의 `No space left on device`로 종료됐다. Worker 로그도 기록하지 못해 job log blob이 없었으며 UI 시험은 실행되지 않았다. check annotation에서 원인을 확인했다.
- 통합 작업의 공개 자산·의존성·캐시·시험·24분 한도는 유지하고, 기존 Core build에서 검증한 체크아웃 전 미사용 Android·.NET SDK 정리 단계를 동일하게 재사용한다. GitHub 호스팅 Ubuntu 24.04·비심볼릭 링크·작업공간 비중첩·20GiB 여유 경계도 그대로다. 통합 verifier는 해당 SDK를 사용하지 않는다.
- 새 계약 시험은 단계·환경 가드·삭제 경로를 기존 승인된 Core 단계와 전수 비교하고, 공개 자산·캐시·frozen 설치·시험 호출·시간 제한 보존을 확인한다. 기존 가짜 실행기 기반 안전 경계 시험과 함께 30개가 통과했고 actionlint도 통과했다. 현재 클라우드에서 실제 SDK 삭제는 수행하지 않았다.
- #2683 납품 미디어 제외 규칙은 복제하지 않았다. 이 디스크 수정은 통합 워크플로에만 적용하며, 실제 새 러너에서의 전후 공간과 검증 성공은 CI에서 확인해야 한다.

## #2674와 CTA·공통 검사 설정 정합성

- main 4ce0e45e8 및 #2674의 7f7806dc2를 비교했다. `/collaborate`는 CollaborationBoardPage의 공개 구인·의뢰 게시판이고 `/team/recruiting`은 HiringWorkspacePage의 로그인 후 이력서·초대·제안 관리 화면이다. CommunityPage의 ‘스튜디오·어시스턴트 구인 매칭’ CTA는 공개 게시판 진입이므로 #2674와 같은 `/collaborate`로 통일한다. 최초 관리 화면 선택은 CTA 의도에 맞지 않아 정정했다.
- 같은 라우트가 등록됐는지만 검사하면 이 용도 차이를 놓치므로, 기존 CommunityPage 화면 시험에 CTA의 공개 게시판 목적지 계약을 추가했다. 수정 전 관리 화면 링크에서 실패함을 확인했다.
- 공통 focused checkout 설정도 #2674와 동일한 표현식으로 맞췄다. PR 전체 메타데이터 이력·수동 깊이 1·blob 필터·비영구 인증·lazy-fetch 금지를 유지하며 기존 Git 회귀와 비교 경로 검사는 보존한다.
- 정합성 근거를 #2674 PR 대화에 공유했다. 상대의 CTA는 추가 수정이 필요 없다. 새 커밋의 검증 결과와 SHA는 PR 본문에 기록한다.
