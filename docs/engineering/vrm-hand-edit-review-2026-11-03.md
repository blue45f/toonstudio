## 재현과 수정

`studio-vrm-finger-curl-polarity.test.ts`에 추가한 회귀 검사에서 수정 전
`루미/left/1 첫 단독 편집 방향`이 실패했다. 검지만 `+0.6` rad 적용한 결과와
중지를 함께 굽혀 축을 판별한 결과의 검지 회전 차이가 `1.2` rad였다.

`resolveFingerCurlPolarity`는 손가락을 초기화하고 입력 포즈를 적용한 뒤 중지 끝의
손바닥 방향 이동량을 측정했다. 검지·약지·새끼만 편집하면 중지가 움직이지 않아
이동량이 0이고, 루미처럼 축 반전이 필요한 모델에도 기본 극성 `+1`을 반환했다.
캐시 생성 여부와 편집 순서에 따라 같은 입력이 다르게 보일 수 있는 원인이다.

입력 포즈 대신 부호별 고정 크기 `±0.35` rad 중지 시험 회전을 사용한다.
최종 회전 적용·문서 형식·손목 보정·반대손 보존 경로는 기존 코드를 사용한다.
큰 입력각이나 중지 이외 손가락의 단독 편집도 동일한 시험 회전으로 축을 판별한다.

## 실행한 검증

관련 Vitest 18개 파일, 총 384개 검사 통과:

- 손가락 축: `studio-vrm-finger-curl-polarity.test.ts` 4개 검사.
  루미·시노·시온·후미·카게·지미·아리시아·제니퍼 8개 실제 VRM의 양손,
  입력 양부호, 단독 검지와 전체 손의 일치, 반대손 보존, 반복 적용을 확인했다.
  추가 회귀 검사는 JSON으로 왕복한 편집값을 캐시 초기화 후 5회 재적용한다.
- 손 포즈·손바닥 방향·굽힘·직접 관절 편집·미러·장면 문서·V3 정규화 손가락:
  8개 파일 90개 검사.
- 이력·프로젝트 라이브러리·관절 제한·체형 코어·체형 리그·소품·의상·포즈 적용:
  8개 파일 218개 검사.
- 위 축 검사와 `studio-vrm-export-generate-reload.test.ts`:
  2개 파일 76개 검사. 생성 VRM의 재로딩·리그·메시 구동을 포함한다.

실행 명령은 저장소 루트에서 `node_modules/.bin/vitest run <해당 파일들>`이다.
Node의 GLTFLoader는 텍스처를 읽지 못하므로 이 검사는 본과 변환 검증이며 렌더링 증거로
취급하지 않는다.

Chromium `/usr/bin/chromium`과 SwiftShader로
`/tools/browser-harnesses/hand-compare.html`을 열어 실제 WebGL 컨텍스트 4개,
루미 자연 대기 포즈와 좌우 손 확대 렌더링을 확인했다.
화면 증거: 클라우드 임시 파일 `/tmp/vrm-hand-lumi.png`.
이는 별도 비교 화면이며 전체 편집기 E2E 검증을 대신하지 않는다.

이후 전체 앱 대신 손 비교 화면만 여는 최소 Vite 설정으로 WebGL 단독 편집도 검증했다.
루미 왼손 검지에 `+0.6` rad 입력 후 실제 정규화 본은 `-0.6` rad로 보정됐다.
캐시 초기화와 JSON 저장값 재적용을 10회 반복해도 `-0.6` rad를 유지했다.
확대 렌더링 증거는 `/tmp/vrm-single-finger-webgl.png`다.
