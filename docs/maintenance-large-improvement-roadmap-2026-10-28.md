# 유지보수 중심 대규모 개선 로드맵 — 작업이 커져도, 시간이 걸려도 (PR #2536 기준 문서)

> 사용자 방향: 작업이 커지고 시간이 오래 걸려도, 향후 유지보수를 위해 최대한 크게 개선한다.
> 이 문서는 그 방향을 단계로 바꾼다. 코드·설정 변경은 없다. 속도를 위해 범위를 줄이지 않는다.

## 원칙 — 크게, 그러나 한 번에 다 바꾸지 않는다

- 크게 개선한다는 것은 한 번에 다 바꾼다는 뜻이 아니다.
  크게는 범위를 뜻하고, 단계는 검증 단위를 뜻한다.
- 각 단계는 이전 단계가 검증된 뒤에야 시작한다.
  검증되지 않은 대규모 변경은 유지보수 개선이 아니라 유지보수 부채이다.
- 이 PR은 draft로 유지하고, 머지는 소유자가 직접 한다.
  대규모 변경일수록 머지 권한은 더 엄격하게 지킨다.

## 1단계 — 정리 (지금 진행 중, 삭제·인덱스만)

- 히스토리 문서: 기본값은 제거이다. 지금 필요하거나 향후 필요한 자료만 남긴다.
  판단 기준은 참조, 대체 문서, 주제 종료, 결정 기록, 향후 재사용 가능성이다.
  이미 삭제: 고아 러너 2건 + 히스토리 6건. 전수 판단이 오면 같은 PR에 한 번에 묶는다.
- 문서·설정·테스트 인덱스: 워크플로 101개, Playwright 20개, verify-* 282개, 테스트 3층을
  물리 병합하지 않고 인덱스 문서로 묶는다. 인덱스가 곧 유지보수의 첫 관문이다.
- AI 가독성 기준: `docs/architecture-ai-readability-2026-10-28.md`를 모든 단계의 잣대로 쓴다.

## 2단계 — 피드백 속도 (낮은 위험, 문서·별칭만)

- `test:fast = vitest run` 추가, `test:full` 별칭 명문화. 기존 `test`와 `ci` 체인은 건드리지 않는다.
- Turbo vs 루트 test 경로 주석, 명명 관례 문서화.
- 검증: 로컬 수집 파일 수 비교. CI 전체 확인은 필요하지 않다.

## 3단계 — 테스트 분리 (중간 위험, 진입점 유지)

- 대형 verify-*를 시나리오·태그 단위로 분리하되, 기존 스크립트 이름은 집계 진입점으로 유지한다.
  쪼갠 뒤 실행 스펙 수가 동일한지 로컬 비교가 검증 방법이다.
- a11y: `/about`을 `a11y-smoke`에 추가하고 로컬 Axe로 확인한 뒤에야 `accessibility-smoke`를 삭제한다.
- 3D 시각 검증: 태그 단위 분리만 한다. 다중 진입점을 깨지 않는다.
- v1·v2: 호출자 대조가 끝난 뒤에만 삭제한다.
- 검증: 로컬 선별 실행 + 11/1 이후 해당 게이트 CI.

## 4단계 — 구조 분리 (중간~높은 위험, re-export부터)

- `packages/core` god 패키지: 한 번에 나누지 않는다. 도메인별 하위 패키지 경계를 정하고,
  re-export를 먼저 두고, 소비자를 한 번에 바꾸지 않는다.
- 메가 도메인 `apps/web/src/domains/creator`(1,000개 이상): 하위 폴더별 배럴과 import 규칙을 먼저 정하고,
  그 다음에 나눈다. 폴더만 나누는 것은 분리가 아니다.
- 공유 UI: 웹의 `shared/components`를 공유 패키지로 옮길 때도 re-export부터 둔다.
- 검증: 경계 ratchet 통과 + 로컬 타입체크 + 11/1 이후 CI.

## 5단계 — CI·설정 고위험 (11/1 이후, 시범 1~2개씩)

- 경로 필터 워크플로 reusable 합병, Turbo `^build` 의존 제거, knip config 삭제,
  TEST_ROOTS·커버리지 변경, 메모리 하향·incremental 활성화, 소크 단축·게이트화, ci 체인 단축.
- 각 항목은 시범 1~2개씩, 해당 게이트 CI 그린 확인 뒤에만 다음으로 간다.
- 과금·지출 한도 인상은 이 로드맵에 포함되지 않는다. 분 초기화(11/1)를 기다린다.

## 6단계 — 히스토리 최종 정리

- 남은 히스토리 파일 중 참조되거나 결정 기록인 것은 날짜 폴더로 모은다.
  현재 문서와 히스토리를 같은 폴더에 두지 않는다.
- 히스토리 파일의 내용을 수정하지 않는다. 이동만 하고, 링크 대조를 먼저 한다.
- 이 단계가 끝나면, `docs/`를 처음 보는 사람도 현재 문서와 과거 증거를 구분할 수 있어야 한다.

## 완료 기준 — 95점은 이렇게 확인한다

- 총점 95점 이상 + 어떤 카테고리도 85점 미만이지 않을 것 + 치명적 보안·설정 누수 미해결이 없을 것.
- 숫자는 측정으로만 주장한다: 테스트 수, 번들 ratchet, 경계 ratchet, CI 게이트 그린 여부.
- 11/1 이전에는 어떤 항목도 "CI 그린 확인 완료"로 주장하지 않는다.
