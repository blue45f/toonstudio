## 1. 목표와 비목표

- 목표: 100점 만점에 95점 이상. 단, 95점은 총점만으로 판단하지 않는다.
  총점 95점 이상 + 어떤 카테고리도 85점 미만이지 않을 것
  + 치명적 보안·설정 누수 미해결이 없을 것, 이 세 조건을 모두 충족해야 한다.
- 비목표: 기능을 바꾸는 것, 마이크로서비스로 섣불리 쪼개는 것,
  main에 직접 머지하는 것, 검증 없이 파일·테스트를 삭제·이동하는 것.
- 방향 유지: pnpm 워크스페이스 + Turborepo 모노레포 안의 모듈러 모놀리th.
  유일하게 따로 둔 것은 GPU 추론 서비스(`services/creator-inference`)이며,
  이는 하드웨어·비용·확장 특성이 달라서 올바른 첫 번째 분리이다.
  CRUD 모듈까지 분산하면 1인·소규모 팀의 유지보수 점수가 오히려 떨어진다.

## 3. 확인된 구조 — 이 설계의 전제

- 메인 백엔드: NestJS 모듈러 모놀리th `apps/api`.
  `src/modules/`가 HTTP/WebSocket 경계, `src/platform/`이 http·adapters·database·
  federated-data-plane(기본 비활성)을 담당한다.
- 공유 계약: `packages/contracts`에는 React/DOM/NestJS/DB/HTTP/스토리지 코드를
  넣지 않고, `packages/*`는 `apps/*`를 import하지 않으며,
  크로스 도메인 deep import는 0으로 묶인다.
  경계는 `config/architecture-boundary-ratchet.json`,
  `config/architecture-source-ratchet.json`,
  `scripts/validate-app-boundaries.mjs`로 기계적으로 강제한다. 이 규칙을 유지한다.
- Rust `crates/`는 백엔드 2층이 아니라 Vello 2D 렌더링 엔진 쪽이다.
- 이미 계량된 부채: 레거시 `server/` 파일 28개, `platform/database/` 165개,
  `lint:strict` 경고 예산 2,189개. 경고 예산은 실제로 고친 만큼만 낮춘다.
  숫자로만 낮추면 CI만 깨진다.

## 4. 종류별 폴더링 — 한눈에 인지되는 분류

도구가 루트를 요구하는 파일은 루트에 두고, 나머지는 아래 분류로 수렴한다.
이 PR에서는 분류표와 인덱스만 추가하고, 코드 파일의 물리적 이동은
import·CI 참조 확인이 끝난 뒤 같은 PR에 커밋으로 추가한다.

| 분류 | 현재 위치 | 역할 | 폴더링 원칙 |
|---|---|---|---|
| 배포 단위 | `apps/*` | 배포되는 앱·API | 앱별로 독립, 공유 코드는 packages로 |
| 공유 패키지 | `packages/*` | 도메인·UI·코어·계약 | 단방향 의존, 공개 exports로만 연결 |
| 백엔드 서비스 | `services/creator-inference` | 선택적 GPU 추론 | 유일한 services 항목, 다른 CRUD는 여기에 안 넣음 |
| 네이티브·렌더링 | `crates/*` | Vello 엔진, vendor | vendor는 이유 확인 전 이동·삭제 금지 |
| 설정·정책 | `config/*` | 경계 래칫, 헤더, 정책 JSON | 정본 인덱스는 `config/README.md` 참조 |
| 배포 단위 정의 | `deploy/*` | Cloudflare·워커·데이터 단위 | 단위별 인덱스는 `deploy/README.md` 참조 |
| 자동화 | `scripts/*`, `tools/*` | 검증·빌드·운영 스크립트 | 목적별(build/test/dev/deploy)로 하위 분류, 이름에 목적 명시 |
| 테스트 | `tests/*`, `e2e/*` | 단위·통합·E2E·성능 | 스위트별 설정은 공유 베이스 + 차이만 남김 |
| 문서 정본 | `docs/*` | 아키텍처·제품·운영 문서 | 루트 문서는 목차·입구로만 두고 정본은 docs로 |
| 데이터·에셋 | `data/*` | 릴리스 증거·스튜디오 에셋 | 생성물·백업·dist·coverage는 소스가 아님, 이동 전 용량·LFS 확인 |
| 실험·외부 | `onnx-poc/`, `third_party/`, `patches/` | PoC, 외부 코드, 패치 | PoC는 제품 경로와 분리, 패치는 제거 조건·업스트림 이슈와 함께 관리 |
| 미분류 주의 | `hidden_files/`, `openwiki/` | 목적이 루트에서 불명확 | 용도 확인 전 이동·삭제 금지, 이 문서의 미확인 목록에 둠 |

폴더링 규칙:
1. 이름만으로 종류를 알 수 있게 한다. 도구명·사람명·날짜만으로 된 폴더는 만들지 않는다.
2. 한 폴더는 한 종류·한 책임만 가진다. 설정·코드·문서·테스트를 한 폴더에 섞지 않는다.
3. 이동할 때는 import를 코드모드로 일괄 변경하고, 이동 전후 동일 동작을
   타입체크·선별 테스트로 증명한다. 이동만으로 점수를 올렸다고 주장하지 않는다.

## 5. 코드 최적화·성능·안정성 원칙 — 측정 먼저

이 PR의 첫 커밋은 동작 변경이 없다. 아래는 같은 PR에 누적될 최적화의 순서이다.

1. 테스트 피드백 분리: `turbo.json`의 `test`가 `^build`에 묶여 있다.
   `test:fast`(빌드 비의존 단위)와 `test:full`(빌드 의존 + E2E·성능)로 나누되,
   `package.json` 스크립트 본문이 미검증이므로 본문 확인 뒤에만 적용한다.
2. 설정 수렴: Playwright 약 20개, Vitest 6개, tsconfig 7개를 당장 합치지 않는다.
   공유 베이스 + 스위트별 얇은 설정 + 실행 매트릭스(설정명·목적·실행 조건)부터 만든다.
3. knip 권위 확정: `knip.json`과 `knip.jsonc` 중 하나를 권위로 선언한 뒤에야
   미사용 코드 판정을 신뢰할 수 있다. 권위 확정 전에는 어떤 파일도 미사용으로 단정하지 않는다.
4. 번들·런타임: 스튜디오 무거운 모듈 지연 로딩, 코드 분할, 중복 의존성 정리,
   Turborepo 캐시 경로 정리는 수치(번들 크기·빌드 시간·테스트 시간) 전후 비교표와 함께 적용한다.
5. 보안 핀 수렴: `pnpm-workspace.yaml`의 overrides 중 포크(`patches/braces`)·
   대체본(`extract-zip`)·버전 상한 핀에 재검토일·업스트림 이슈·제거 조건을 고정한다.
   `minimumReleaseAge: 0`은 그래픽 런타임에만 즉시 채택하고 나머지는 숙성 게이트를 두는지
   제품 정책 확인 뒤에 결정한다.
6. 안정성: 벤더 종속을 피한다. AI 리서치 기능은 범용 프로바이더 인터페이스를 유지하고,
   특정 업체 전용으로 되돌리지 않는다. 마이그레이션 파일(`platform/database/`의 일부)은
   최적화 대상에서 제외한다.
