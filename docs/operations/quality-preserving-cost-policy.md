# 품질 보존형 비용 최적화와 사용자 소유 AI — 2026-09-14

## 사용자 결정

비용 최적화는 동일 기능·동일 조건·동일 품질·동일 사용성과 편의성을 전제로 한다.
무료 한도에 맞추기 위한 기능 삭제, 모델·해상도·결과 품질 하향, 인위적 대기·횟수 제한,
사용자에게 불필요한 수동 작업을 떠넘기는 방식은 이 정책에 부합하지 않는다.
이 결정은 앞선 “무료 한도를 넘는 기능은 축소”라는 해석을 대체한다.

## AI 연결 원칙

AI 기능 자체를 제외하지 않는다. 사용자의 제공자·모델·API 키를 하나의 통합 설정에서 관리한다.
각 작업공간은 그 설정을 참조하며 별도의 키 저장소나 반복 입력 창을 만들지 않는다.
키 미설정, 제공자 장애, 한도 소진, 연결 실패를 운영자 키로 우회하지 않는다.
(2026-10-29 결정으로 "키를 등록하지 않은 사용자의 서버 AI 자동 경로"는 예외다 — 아래 절 참고.)
비용을 낮추기 위해 선택한 모델·해상도·입력 내용을 조용히 바꾸지 않는다.
요청 처리 여부가 불명확할 때 자동 재시도하여 중복 과금을 만들지 않는다.
키·인증 헤더는 프로젝트, 내보내기, 협업 메시지, 로그, 분석 데이터에 넣지 않는다.
요청 취소는 제공자가 이미 수락한 작업의 과금 취소를 보장하지 않는다.
외부 제공자의 CORS·보안 제약은 숨기지 않고 검증된 연결 방식으로 처리한다.
운영자 모델 비용을 차단해도 일반 호스팅·트래픽·저장 비용까지 0원이라는 뜻은 아니다.

## 허용되는 최적화

같은 결과를 재사용하는 캐시, 중복 연산 제거, 변경 영역 갱신, Worker 처리, 지연 로딩,
무손실 인코딩 등은 적용 전후 결과와 반응성·메모리·내구성을 함께 검증한다.
화면 미리보기는 축소할 수 있지만 축소본으로 편집 원본을 대체하지 않는다.
안전한 메모리·파일 검증을 제거하여 명목상 지원 범위만 넓히지 않는다.
기능 변경·성능 회귀·결과 차이가 생기는 최적화는 동등한 최적화로 보고하지 않는다.

## 병렬 작업과 배포

다른 세션의 변경을 먼저 확인하고 진행 중인 파일·브랜치·워킹트리를 보존한다.
공유 AI 설정은 `feat/creator-ecosystem-unified-byok-20260914` 작업과 통합한다.
원본 품질·취소·가져오기 검증은 `feat/studio-quality-preserving-upgrade-20260914`가 담당한다.
두 브랜치의 존재는 통합·검증·출시 완료를 의미하지 않는다.
PR, 병합, 로컬 테스트는 배포 승인이 아니다. 자동 배포·Preview를 켜지 않는다.
사용자 별도 배포 승인 및 기존 수동 최소 비용 배포 정책을 유지한다.

## 2026-10-29 사용자 결정 — 키 없는 사용자의 운영 고성능 경로

사용자 결정: 사용자가 키를 등록하면 등록한 키로 실행하고, 없으면 서비스 자체 기능으로 실행한다.
키가 없을 때는 운영자 API 키를 최우선으로, 그다음 성능 좋은 무료 LLM 순으로 둔다.
이 결정은 위 "운영자 키로 우회하지 않는다"를 다음 범위에서 대체한다.

- 키를 등록하지 않은 사용자의 서버 AI 자동 경로(텍스트 작업·AI 보조 기능)는
  운영 고성능 경로(운영자 키) → 성능 순 무료 풀 순서로 처리한다.
- 운영 경로 비용은 운영자가 부담하고 사용자 크레딧을 차감하지 않는다.
  사용자별·서비스 전체 UTC 일일 예산으로 상한을 두고, 예산·원장을 확인하지 못하면 열지 않는다(fail-closed).
- 사용자가 등록한 키가 있으면 그 키를 먼저 쓴다. 추론 전에 확정 거절(한도 소진·인증 거절)될 때만
  ToonStudio AI로 넘기고, 결과 생성 여부가 불확실한 오류는 다른 경로로 다시 보내지 않는다.
- 사용자가 고정한 경로(고정 모드)와 BYOK 경로의 모델·입력은 조용히 바꾸지 않는다.
- 운영 키는 서버 환경변수로만 둔다. 브라우저 번들(`VITE_`)·응답·로그에 싣지 않는다.
- 세부 설정·예산 변수·장애 전환 조건은 [Cloud-only free-first AI runtime](free-ai-runtime.md)에 둔다.
