# 사업계획서 비공개 접근 경계

- 상태: **migration** — 코드와 추가형 migration의 계약이다. Git 병합은 운영 DB 적용·API 배포를 의미하지 않는다.
- 작성일: **2026-11-18**
- 정본: `apps/api/src/modules/business-plan/`, `packages/contracts/src/business-plan/access.ts`

## 접근과 소유권

`/admin/growth/business-plan/`의 원문·문서 이력·멘토 요청·승인 메모는 기존 계정 인증을 사용한다.
플랫폼 관리자라는 이유만으로 자료를 공개하지 않는다. 활성 관리자 소유자와 소유자가 명시적으로
지정한 활성 관리자·운영자 계정만 읽는다. 읽기·수정·내보내기는 별도 권한이고, 다른 계정의 권한을
관리하는 기능은 소유자에게만 제공한다. 소유자가 관리자 역할을 잃으면 소유권에 따른 접근도 중단한다.

최초 GET은 보드나 소유자를 생성하지 않는다. 보드 최신값과 과거 snapshot·저장 감사·영수증이 모두
비어 있을 때만 활성 관리자가 **이 빈 보드의 소유자로 시작**을 선택할 수 있다. 소유권은 DB 잠금으로
한 계정에만 부여하고, 원문 저장과 별개로 감사한다. 소유자 없는 기존 자료에는 소유자를 자동 배정하지
않는다. 이 경우 API는 자료와 버전·제목·건수를 반환하지 않으며, 실제 귀속을 확인한 별도 복구 검토가 필요하다.

| 경로 | 인가와 기록 |
| --- | --- |
| `GET /api/admin/business-plan` | 현재 읽기 권한, 성공 열람 감사, 비공개·캐시 금지 응답 |
| `POST /api/admin/business-plan/claim` | 빈 저장소의 명시적 관리자 소유권 설정, 멱등성·감사 |
| `POST /api/admin/business-plan/save` | 현재 수정 권한, revision CAS, 불변 snapshot·감사·영수증의 원자적 저장 |
| `GET /api/admin/business-plan/export` | 현재 내보내기 권한을 다시 확인하고 성공 감사 |
| `GET /api/admin/business-plan/access` | 소유자에게만 명시적 권한 목록, 목록 조회 감사 |
| `POST /api/admin/business-plan/access` | 소유자만 계정별 읽기·수정·내보내기 부여/철회, 멱등성·감사 |

재전송으로 과거 snapshot을 반환할 때도 현재 권한을 먼저 확인한다. 접근 감사 저장에 실패하면 원문을
반환하지 않고, 수정 감사 실패 시 최신값·snapshot·영수증을 함께 롤백한다. 감사에는 문서 원문이나 제목을
넣지 않는다. 외부 제출·배포·계정 설정 변경은 이 API가 실행하지 않는다.

## 화면과 파일

화면은 열람·수정 권한을 서버에서 받고, 창 복귀·세션 변경 시 다시 확인한다. 확인 중에는 자료를 숨기며,
401/403이면 메모리의 원문·미저장 초안·대기 저장을 제거한다. 읽기만 받은 계정은 검토 화면과 문서 이력을
볼 수 있지만 저장할 수 없다. JSON 원문 표시, JSON 파일, 제출용 텍스트 파일은 각 요청 직전에 내보내기
경로를 통과해야 한다. 이미 읽은 자료의 화면 복사까지 기술적으로 회수할 수 있는 권한은 아니다.

미저장 초안은 브라우저 메모리에만 있다. `localStorage`·`sessionStorage`에 사업 자료를 자동 저장하지 않으며,
가져오기·권한 철회 시 자동 파일 백업도 생성하지 않는다. 필요하면 내보내기 권한이 있는 계정이 명시적으로
파일을 보관한다. 다운로드한 파일의 보관·공유 범위는 사용자가 관리한다.

## 적용·검증·복구

기존 무료 PostgreSQL을 사용하며 새 서비스·유료 플랜·배치 동기화는 추가하지 않는다.
`0123_admin_business_plan_access.sql`은 소유자 열, 명시적 권한 표, 불변 접근 감사 표를 추가한다.
통합 브랜치에서 migration 번호를 조정하면 manifest·통합 테스트의 경로도 함께 조정한다.
런타임 ACL은 현재값과 권한의 지정 열만 UPDATE를 허용하고 snapshot·감사·영수증의 변경·삭제를 차단한다.

운영 적용 전 저장소 정책에 따라 승인 주체·승인 SHA·DB 경계를 확인하고 관리 migration 경로로 적용한다.
성공 기준은 빈 저장소·기존 자료·소유자·미부여 관리자·읽기 전용 계정·철회 계정의 통합 검증과 감사 원자성이다.
이 변경은 운영 DB나 권한의 자동 변경을 요청하지 않는다.

문제가 생기면 사업계획서 경로를 비활성화하고 원문·snapshot·감사 표를 보존한다.
전역 관리자 열람을 허용하던 이전 API로 단순 원복하지 않는다. 소유자 재지정·기존 원문 귀속·자료 삭제는
이 변경의 자동 복구 범위에 포함하지 않는다.
