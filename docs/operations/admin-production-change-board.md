# 제작 변경·충돌·사후 검증 보드

- 상태: **migration — 네이티브 관리자 통합 소스**, 운영 반영 여부는 별도 증빙으로 확인한다.
- 작성일: **2026-11-20**
- 경로: `/admin/production/changes/`

## 기능과 경계

관리자 콘솔의 **제작 변경** 메뉴와 통합 작업실, 웹 관리자 운영 화면에서 진입한다.
기존 ToonStudio 세션으로 확인한 활성 관리자는 기록을 편집하고, 활성 운영자는 조회·내보내기를
사용한다. 비로그인·일반 사용자·정지 계정은 기록과 첨부를 읽을 수 없다. 권한 재확인 중에는
기록을 숨기고, 계정이나 역할이 바뀌면 이전 화면 상태를 분리한다.

초안·제출·영향 분석·검토·승인·반려·예약·적용·검증 완료·종료의 10개 상태를 관리한다.
프로젝트·에피소드·에셋·Revision·담당자·근거 링크·메모·다음 조치를 기록하고, 상태·영향도·
충돌·검증 최신성을 함께 필터링하거나 정렬한다. 실제 프로젝트와 요청을 임의로 생성하지 않으며,
첫 조회는 빈 목록이다. 확인하지 못한 값은 미확인으로 유지한다.

Conflict Center는 로컬·원격 Revision과 캡처를 나란히 보여 주고 시각적·구조적 차이,
영향 범위, 퍼블리싱 영향, 충돌 원인, 해결 방법·근거와 결과 Revision을 기록한다.
Revision ID는 실제 제작 도구에서 생성한 결과를 기록하는 필드이며 보드가 제작 Revision을 생성하지 않는다.

예약·적용·승인은 **보드의 기록 상태**다. 코드 수정, 외부 배포, 운영 데이터 변경, CI 실행,
인프라 제어 또는 예약 실행기를 제공하지 않는다. 요청한 실행 종류는 승인 대기와 승인 범위의
설명으로만 사용한다. 기존 CI·배포·인프라 관리 기능은 해당 전문 보드에서 계속 관리한다.

## 승인과 검증

승인자·승인 시각·감사 이력은 서버 세션과 서버 시계에서 생성한다. 클라이언트가 보낸 승인이나
감사 문서를 정본으로 받지 않는다. 승인 후 핵심 변경 범위가 바뀌면 승인을 무효화하고 검토로
되돌린다. 적용 후에는 핵심 범위와 적용 결과 스냅샷을 고정한다.

적용 기록에는 현재 범위의 승인, 충돌 확인·해결, 결과 Revision과 적용 근거가 필요하다.
검증 완료에는 변경 전후 캡처·Revision·시각, 필수 테스트 통과, 회귀 확인,
검증 담당자·결과·시각, 미확인 항목 검토가 필요하다. 실패·미확인·증빙 누락·Revision 불일치가
남으면 검증 완료로 전환할 수 없다. 검증 근거가 바뀌면 재검증 상태를 표시한다.

최신성은 실제 증빙 시각으로 계산하며 일반 메모 저장 시각을 사용하지 않는다. 기본 유효 시간은
72시간이며 요청마다 1~720시간으로 기록할 수 있다. 이는 보드의 초기값이며 기존 운영 정책을
확인했다고 뜻하지 않는다. 화면 입력·표시는 한국 시각을 사용하고 저장 시각은 시간대가 있는 ISO 형식이다.

## 저장·충돌·캡처

- 공통 계약: `packages/contracts/src/admin-production-change.ts`
- API: `apps/api/src/modules/admin-production-changes/`
- 정본·감사·캡처 메타데이터: PostgreSQL의 `admin_production_change_*` 테이블
- API 접두사: `/api/admin/production-changes`

저장은 요청 버전을 트랜잭션 안에서 비교한다. 다른 관리자가 먼저 수정하면 409를 반환하고,
화면은 미저장 초안을 유지한다. 동일 mutation ID의 동일 요청 재시도는 중복 기록하지 않으며,
다른 내용으로 같은 ID를 재사용하면 충돌로 처리한다. 감사 이력과 캡처 메타데이터는 추가만 허용한다.

캡처는 관리자 권한을 확인한 multipart 업로드의 `file` 필드로 받는다. PNG·JPEG·WebP,
최대 5MiB이며 MIME과 파일 시그니처를 확인한다. 기존 private object storage의 `derived`
저장 목적을 사용한다. 인증된 캡처 읽기는 짧은 수명의 서명 URL로 연결한다. 저장소가 미구성되거나
접근할 수 없으면 명확한 오류를 반환한다. 업로드 실패를 성공으로 표시하지 않는다.

Sites의 이전 보드는 별도 저장소다. 이번 소스 통합은 기존 Sites 데이터·첨부를 자동 이전하지 않는다.
기존 Sites 상대 경로 `/api/captures/...`는 새 관리자 첨부 경로로 인정하지 않는다.

## 운영 반영과 복구

소스 병합은 운영 DB 적용이나 배포 완료를 뜻하지 않는다. 운영 반영 전
`docs/operations/infrastructure-map.md`, `DEPLOY.md`와 현재 승인을 확인한다.
onpod DB와 API 이미지 변경은 해당 운영 규칙에 따라 별도 승인과 실행 증빙이 필요하다.

반영 순서는 추가형 migration `0132_admin_production_changes.sql`, 해당 런타임 ACL과 capability
검사, 검증된 동일 main SHA의 API·관리자 산출물 반영, 권한별 조회·저장·첨부 스모크 확인이다.
ACL 연결은 `scripts/admin-database-feature-contracts.mjs`가 소유한다. 요청 처리 중 DDL이나
자동 migration을 실행하지 않는다. 새 테이블이 없거나 저장소에 접근할 수 없으면 503으로 실패한다.

되돌릴 때는 마지막 검증된 API·웹 이미지/산출물을 복구하고 새 테이블·이력·캡처는 보존한다.
이 migration은 기존 테이블을 변경하지 않는다. 데이터 삭제형 down migration은 제공하지 않으며,
기존 기록의 삭제는 이 기능 통합 승인에 포함되지 않는다.

## 검증 위치

공통 계약 테스트는 승인 우회·재승인·증빙·Revision·최신성을 검사한다. API 테스트는 권한·
입력·저장 실패·업로드를 검사하고, PostgreSQL 통합 테스트는 폐기 가능한 로컬 DB와 제한된
런타임 역할에서 migration 재실행·ACL·감사 불변성·CAS·멱등성을 확인한다. 해당 통합 테스트는
`scripts/run-postgres-integration-tests.mjs`의 필수 목록에 포함한다. 관리자 테스트는 권한 확인,
미저장 보호·서버 충돌과 필터·상세 편집을 검사한다. 운영 반영 완료 여부는 이 문서의 존재로
추정하지 않고 배포 ID·SHA·실행 결과로 확인한다.
