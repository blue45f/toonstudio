## 소품을 장착하고 원고를 출력할 때

원본 17종 양손에 책만, 또는 책과 머그를 함께 들렸다. 이전 동기 구현에서 팔과 손가락을 처음 맞출 때 걸린 시간의 95백분위는 책 단독 90.89ms, 양손 소품 168.31ms였다. 교정본은 그 작업을 나눠 메인 스레드를 브라우저에 돌려준다. 한 번의 계산 구간은 각각 95백분위 8.84ms와 9.11ms, 최댓값 22.08ms와 17.71ms였다. 자세를 유지한 채 다시 검사한 95백분위는 0.082ms와 0.163ms였다. 최종 관절·교선·소품 기울기는 한 번에 계산한 결과와 일치했다.

Chromium과 SwiftShader에서 소품 파일이 준비된 시점부터 캡처 허용까지를 별도로 쟀다. 표의 이전 구현은 분할 계산 중간에도 같은 장면을 다시 그렸다. 교정본은 손과 팔에 실제 변경이 생긴 시점에 다시 그린다. 아리시아의 책·머그를 함께 장착할 때 실제 렌더 콜백은 21→3회였다. 다섯 캡처의 합계 507,500픽셀 중 달라진 픽셀은 머리 영역 경계의 2개였다. 팔·손·소품 픽셀은 모두 같았다. 보정 도중 소품을 해제한 경우에는 캡처 대기가 취소됐고 손목 위치 오차가 0mm였다.

## 헤어와 모자

루미 원고에 가이드 뿌리 두 개를 저장하고 가닥 추가·복제를 반복해 총 11개를 만들었다. 이전에는 서로 다른 뿌리 위치가 8개였고, 수정 후에는 11개가 모두 구별됐다. 먼저 저장한 두 가닥의 좌표 변화는 0이었다. 수정 전에는 얼굴 확대 화면에서 넷째 가닥을 추가해도 359×327 영역의 픽셀이 모두 같았다. 수정 후에는 같은 빌드에서 넷째 가닥 추가 전후의 371×339 얼굴 영역 중 801픽셀에서 한 채널 이상이 12단계 이상 달라졌다. 끝점 X를 키보드로 −0.035m까지 입력하고 저장한 V3에서 같은 값을 읽었다. [얼굴 확대 비교](hair.jpg)

원본 머리카락 위에 베레모와 비니를 각각 씌웠다. 루미의 같은 800×800 후면 구도에서 겉감 위로 드러나는 머리카락은 베레모 2,316→0픽셀, 비니 7,347→160픽셀이었다. 원본 헤어를 남겨 둔 채 실제 정수리와 모자 테두리가 만나는 곳에 맞춰 착용 위치를 정했다. 루미·시온과 두 모자의 네 조합에서 테두리와 머리카락 사이 거리의 중앙값은 0.64~1.97mm였다. [루미의 펠트와 니트 테두리 전후](lumi-hat-fit.jpg)

정면·양옆·후면 총 16구도에서 원래 헤어를 표시한 컷과 진단용으로 숨긴 컷을 대조했다. 시온의 비니는 4방향 합계가 2,063→885픽셀로 줄었고, 정면 한 방향에서는 699→811픽셀로 늘었다. 두 모델 모두 모자를 벗은 화면과 선글라스를 쓴 화면은 각각 기존 원고의 640,000픽셀과 일치했다. 숏·롱·포니테일과 캡·선글라스를 조합한 기존 공식 검수 44컷도 동일한 RGBA로 출력됐다. [루미와 시온의 네 방향 착용 비교](hat-four-views.webp)

## 설정화 구도

원고용 캐릭터 17종과 기존 원고 호환 모델 제니퍼를 같은 포즈와 카메라로 불러와 바운딩 박스를 비교했다. 18종 모두 경계가 일치했다. 인덱스와 표시 재질을 기준으로 정점 변형 호출은 전체 6,652,125→548,114회, 후미 단독 1,687,150→29,352회로 줄었다. 숨긴 재질 그룹과 그리기 범위 밖 정점이 설정화 축척에 영향을 주는 경우도 회귀 테스트에 포함했다. 실제 편집기에서 후미의 4방향(1,600×2,192)과 8방향(3,168×2,192) PNG를 저장했다. 모든 칸에서 머리와 발은 1,024픽셀 높이 중 Y=70~953 안에 들고 시점마다 윤곽이 달랐다. ## 모델링 파일 왕복

UV 이음선이 있는 책 표지의 한 면을 매끈하게, 다른 면을 평평하게 설정해 OBJ로 저장했다. Blender 4.3.2에서 다시 열면 이전 파일은 UV 0개와 평면 삼각형 4개였고, 수정 파일은 원본의 사각면 2개·코너 UV 8개·음영 설정을 복원했다. 같은 카메라의 480×325 Cycles 렌더에서 수정 파일과 원본은 RGBA가 일치했다. 편집기에서 OBJ를 다시 열어 내보낸 GLB의 원본 해시, 위치·법선·UV 속성과 삼각형 인덱스도 일치했다. 내부 편집기가 다각면으로 읽을 수 없는 오목·비평면 5각형과 4,097각형은 삼각형 3개와 4,095개로 저장해 다시 열었다. [표지의 UV와 면 음영 전후](obj.jpg)

표지가 흰색으로 보일 때에는 파일의 UV와 편집기 표시를 각각 조사했다. 같은 원고를 정상적으로 읽은 뒤에도 초기 재질이 텍스처 없이 연결되면 체크무늬의 GPU 업로드가 0회였다. 체크무늬 텍스처가 준비된 뒤 재질을 연결하도록 바꾸고, 첫 연결에 유효한 텍스처가 있는지와 닫을 때 해제되는지를 회귀 테스트로 확인했다.
