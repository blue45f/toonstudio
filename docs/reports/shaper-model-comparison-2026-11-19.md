## 비교한 화면

SHAPER의 공식 안내와 로컬 macOS 앱 1.05(9)의 첫 작업 화면을 확인했다. 공식 안내에서는 파츠를 조합하고 포즈를 바꾼 뒤 몸에 그린 선을 유지하거나 PSD로 꺼내는 과정을 볼 수 있다. 첫 화면의 기본 조형과 완성 캐릭터 예시는 서로 다른 제작 단계다. SHAPER와 ToonStudio에 같은 완성 캐릭터를 넣어 FPS나 품질 순위를 측정한 자료는 없다. [SHAPER 사용 안내](https://shaper.webtoons.com/how-to/)

공개 화면 관찰과 네이티브 분석은 별도로 기록했다. REA의 웹 관찰 기록은 `ev_e620cc046ba1f392fa67a6e9943b5cab47d1a896f064ee39b0efa1ebfa3c7639`이다. REA의 Ghidra 연결은 준비 단계에서 실패했다. 로컬 Ghidra 12.1.4의 독립 실행으로 arm64 런처의 가져오기와 정적 분석은 성공했다. 이 결과에서 캐릭터 토폴로지나 피부 렌더 기법까지 추론할 수는 없다. ToonStudio 쪽 비교에는 자체 GLB와 실제 편집기 출력을 사용했다.

## 근접 촬영용 배경

장면은 미터 단위로 제작했다. 모델을 내려받은 뒤 장면 바닥을 누르면 배치된다. 모델을 고른 다음 **선택한 공간의 추천 구도 적용**을 누르면 원본의 촬영 구도가 모델의 위치·회전·크기를 따라간다. 배치 직후에는 작업 중인 카메라를 유지한다.

| 장면 | 실제 모델에 들어간 세부 | 추천 화각 |
| --- | --- | --- |
| 햇살 드는 유리온실 | 철제 리브, 부채꼴 색유리, 차양, 덩굴, 양치 잎, 모종 트레이와 물뿌리개 | 39° |
| 붉은 등대와 방파제 | 등명기와 난간, 사다리, 계선주, 구조환, 암초와 파면 | 39° |
| 식물 세밀화 작업실 | 직접 만든 1024×512 나뭇결, 5mm 눈금자, 표본 압착기, 시료병, 관절 작업등, 창밖 과수 가지 | 37° |
| 항구 목선 수리소 | 선체 늑골과 널, 체결 부속, 윈치, 로프, 수선 그물 | 40° |

유리온실과 등대는 실제 원고에서 컬러 배경을 넣고 새로고침한 뒤 같은 카메라와 모델이 열렸다. 작업실은 검증 중 3,727,420바이트짜리 PNG를 검사하는 정규식에서 Chrome 호출 스택 초과가 발생했다. 검사를 수정한 뒤 동일 자산 `7271b175…`로 추천 구도 적용·실행 취소·다시 실행·컬러 삽입·저장·재열기를 통과했다. Blender 5.3 재수입 시 네 메시 모두 10µm 용접 기준에서 열린 변·비다양체 변·고립 요소·퇴화 면이 0개다. 작업실은 glbforge 모바일 모델 예산 100/100, 삼각형 26,884개, 드로콜 4개다.

카메라 회귀 검사에서는 등대를 [3.25, 1.5, -2]m로 옮기고 Y축으로 30° 돌린 뒤 축별 크기를 [1.5, 1, 0.75]로 바꿨다. 저장한 카메라 위치·주시점과 원래 카메라를 월드 좌표로 변환한 독립 계산값의 최대 차이는 1.78×10⁻¹⁵m였다. 이 검사는 게스트 원고의 기기 저장·재열기 경로에서 실행했다.

목선 수리소도 실제 원고에서 추천 화각 40°를 취소하고 다시 적용한 다음 컬러 레이어를 저장했다. 새로고침 후 레이어 ID, 장면 해시와 합성 이미지 해시가 일치했다. 근접 컷의 금속·목재·로프 질감을 유지하며 재질을 아틀라스에 합쳐 7개였던 드로콜을 4개로 줄였다. 기존판과 같은 조명의 근접 렌더에서 RGB 평균 오차는 채널당 0.080/255였다. 이 선택으로 추정 텍스처 메모리는 약 4MiB 늘었다. 최종 모델 `4a0e5d73…`의 삼각형은 54,432개다.

호출 스택이 넘치는 현상은 원고 ZIP 생성과 3D 선화 패스 보관에도 있었다. 1320×1320 RGBA PNG로 세 진입점의 실패를 재현한 뒤 같은 유효성 검사를 선형 시간에 처리하도록 고쳤다. ZIP 복원 바이트와 SHA, OPFS의 주선 SHA, 잘못된 입력의 거절을 포함한 인접 테스트 79개가 통과했다.

기본 키트는 최종 얼굴 `b54fdfb2…`를 1판과 구분해 저장한다. WebGL2와 WebGPU에서 같은 윙크 레시피를 다시 열었을 때 얼굴 픽셀 차이가 각각 0이었다. 데스크톱 베이스는 10개, 아틀리에 주인공은 18개 드로콜을 써서 glbforge의 데스크톱 모델 예산 8개를 넘는다. 배경 4종은 각각 드로콜 4개다.

## 검증 범위

2026-11-19에 기본 카탈로그 35종을 각각 추천 구도와 근접 구도로 촬영했다. 아파트·카페·미술실에서는 앞쪽 옆벽이 가구를 가렸다. 기존 추천 거리·높이·화각을 유지하고 방향을 조정했다. 화면에서 모델을 맞힌 광선 중 앞쪽 벽에 먼저 닿은 비율은 아파트 36.6%→18.6%, 카페 29.5%→12.0%, 미술실 33.0%→16.2%였다. 사용자 원고에 저장된 카메라는 기존 값을 읽는다.

새 배경 네 종에는 원본 모델에서 측정한 **세부 구도**를 추가했다. 원고에서 모델을 선택한 뒤 누르면 선체 이음부(38°), 모종 작업대(37°), 표본 작업대(30°), 부두 난간(40°)을 바로 촬영한다. Chrome 157에서 버튼으로 적용한 뒤 실행 취소·다시 실행, PNG 레이어 추가, 새로고침, 3D 재편집을 네 곳 각각 확인했다. 첫 연속 실행에서 수리소 재진입이 시간 초과됐고 같은 검사 단독 재실행이 통과했다. 수리소의 근접 레이어로 저장된 PNG는 2731×1534였다. 구판·대체 자산의 기존 해시 22개도 해당 장면의 추천 구도를 다시 찾는다.

배경 카탈로그의 35개 항목과 샘플 라이브러리, 원본 SHA-256·바이트 수·휴대폰 반입 검사 등을 포함한 8개 파일의 테스트 113개가 통과했다. 캐릭터 툰 셰이더·얼굴 음영 대상은 5개 파일에서 84개가 통과했다. 편집 실측과 별도로 기록한 모바일 예산 점수는 GLB의 용량·드로콜 등 정적 비용을 뜻한다. 모든 기종의 프레임 시간, 전체 동선의 무결함, SHAPER 대비 시각적 동등성은 이 수치로 판정할 수 없다.
