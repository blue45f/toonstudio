# 오프라인 협업 충돌 해결과 검증 기록

- 상태: **migration — 후보 코드의 로컬 검증 완료, PR·병합 및 실제 C8 검증은 별도 단계**
- 기록일: 2026-11-01
- 범위: 선택형 Automerge 오프라인 보관함의 충돌 처리, 동기화 안내, 실제 편집 화면 재투영
- 정본 권위: ADR-0025에 따라 Yjs와 기존 서버 ACK 경로를 유지한다.

## 문제와 구현

오프라인 변경 이후 다른 사용자가 같은 대상을 수정하면 `target-changed` 등이 보관되지만, 원래 구현에는 그 작업을 사용자가 처리하는 명령이 없었다. 재연결만으로는 충돌을 해소하지 못하며, Yjs pending이 0이면 로컬 충돌이 남아도 전체 동기화 완료처럼 표시할 수 있었다.

이번 변경은 operation별로 두 선택을 제공한다.

| 선택 | 로컬 보관함 | 공유 원고와 ACK |
| --- | --- | --- |
| 공유본 유지 | 원래 작업과 payload를 보존하고 별도 해결 기록으로 활성 proposal에서 제외 | Yjs를 수정하지 않으며 서버 receipt를 만들지 않음 |
| 내 변경 다시 적용 | 현재 공유본을 이전 상태로 삼은 새 operation과 원래 작업의 대체 결정을 원자 기록 | 기존 승격·보호 장벽을 사용하며 실제 서버 ACK 전까지 pending 유지 |

이미 `canonical-local` 또는 `server` receipt가 있는 작업은 이 로컬 결정만으로 취소할 수 없다. 이미 출판된 Yjs 변경을 취소했다고 표시하지 않는다. payload가 없거나 손상된 경우와 지원하지 않는 변경, 삭제된 페이지는 재적용을 강행하지 않는다.

선택 시 현재 원고·사용자 scope·operation actor·편집 권한·runtime 세대·공유본 fingerprint를 재검사한다. 두 기기의 선택이 상충하면 피어 문서를 일부만 가져오지 않고 전체 import를 거절하며 현재 기기의 원본과 선택을 유지한다. 동일한 선택은 중복 replacement를 만들지 않는다.

## 저장 및 실패 경계

- 해결 기록은 서버 receipt와 별도인 `resolutions`에 보관한다. 원래 operation은 삭제하거나 덮어쓰지 않는다.
- 활성 pending의 판정은 공통 계약으로 소유하며 projection, reconstruction, promotion, branch 상태가 이를 따른다.
- 해결된 원본과 replacement의 payload도 이력·복구 참조로 유지한다.
- 새 문서를 저장하기 전에 마지막 durable 상태와 후보 상태의 payload 참조 합집합을 보호한다.
- 해결 또는 피어 import의 저장이 실패하면 Worker와 기기 저널을 이전 checkpoint로 복구한다. 복구마저 실패하면 실행 직전의 큐 장벽으로 이미 대기 중인 export·promotion도 차단한다.
- 정상 종료는 새 요청을 막고 이미 수락한 저장 큐를 비운 뒤 Worker를 종료한다.
- 원격 시계가 앞선 문서를 가져와도 새 작업과 선택의 시각은 단조 증가한다.

## 문서 및 피어 호환성

새 저널은 **문서 schema 2**를 사용한다. 기존 operation과 payload codec version 1은 유지한다. 실제 schema 1 문서는 기존 작업·payload 참조·receipt를 검증하고 보존한 뒤 문서 schema 2로 전환한다. 새 문서를 읽는 구 엔진은 지원하지 않는 문서 버전으로 중단하므로 해결 기록을 무시한 채 원래 작업을 다시 활성화하지 않는다.

피어 hello와 bundle은 v3, capability는 `offline-branch-resolutions-v1`을 사용한다. 해결 기록을 이해하지 못하는 구 피어와의 교환은 거절하며, 이를 정상 동기화 완료로 표시하지 않는다. 이미 열린 구버전 탭이 메모리에 가진 v1 저널을 계속 쓰는 상황까지 서버가 강제 종료하는 기능은 이 변경에 포함하지 않는다. 실제 배포 시 별도의 세션·버전 갱신 경계를 확인해야 한다.

## 편집기 연결

기존 단일 동기화 assistant에 로컬 pending과 충돌을 연결했다. 충돌이 남으면 Yjs pending 0만으로 모두 완료라고 표시하지 않는다. 해결 화면에는 페이지·대상 종류·변경 의도·사유·선택의 의미와 진행·실패 상태를 제공한다. 중복 클릭을 막으며 저장 실패 시 카드와 원본을 유지한다.

마지막 pending을 제외해 Yjs 이벤트가 없어도 Host의 현재 원고와 history를 공유본으로 재투영한다. 이전 원고의 비동기 결과는 현재 runtime과 활성 구독의 identity 검사로 배제한다. Provider의 구독·권한·생성·종료는 집중 hook이 같은 live-room 수명주기에서 관리하며 무거운 runtime과 피어 모듈의 지연 로드를 유지한다.

최초 집중 시험에서 수동 hook 드라이버의 기본 Context 누락과 정상 동기화 메뉴바 상세 창의 자동 닫힘 회귀를 확인해 수정했다. 시험의 단언은 유지했다. 구조 검사에서는 새 충돌 UI를 기존 `offline-branch` 소유 폴더로 배치했고, Host는 읽기 전용 CRDT frontier의 정식 공통 타입을 사용한다. 파일 수·크기·진입 그래프 한도를 올리거나 타입 단언으로 실패를 숨기지 않았다.

별도 test 커밋의 기존 fixture 4개도 집중 시험에 포함했다. 제작 보드 인계의 실제 소유자, 저장소에 전달하는 전체 제출 command, 함수별 편집 거부 순서, 정본 migration 119개와 adopted marker 1개의 총 120행을 현재 소스 계약에 맞춘 변경이다. 앱 동작이나 검사 기준을 낮추지 않았다.

번들은 격리 작업트리에서 생성했다. 추적된 `.env.production`은 기준 main과 바이트가 같고 공개 연결 설정 키 4개만 포함함을 확인했으며, 별도 로컬 환경 파일과 운영자 VITE 키 항목은 없었다. 부모 환경의 VITE 키를 승계하지 않고 공개 빌드 입력 2개만 명시했다. 빌드 후 변경 코드 38개의 해시가 모두 유지됐고, 오프라인 runtime·피어·Worker 산출물의 해시를 외부 증거 폴더에 기록했다. 초기 준비본 34개도 최초 해시와 같은 복구 사본으로 별도 보존했다.

실제 C8는 두 계정의 원래 입력, WS 단절 중 새 본인 입력, 기기 보호 상태, 재접속의 동일 입력 ACK, 다른 사용자의 변경 보존, 서버 저장·PNG·양쪽 reload 기준을 유지한다. 기존 전체 실행을 중복하지 않고 총괄이 배정한 단일 구간에서 수행한다. 단위·mock UI 시험은 이 실제 런타임 증거를 대신하지 않는다.

기존 검증의 새 획들은 서로 다른 대상이므로 충돌 선택을 증명하지 않는다. 기존 양쪽 reload 검증이 끝난 뒤 별도의 두 라운드에서 같은 레이어 그룹의 이름을 실제 UI로 변경한다. 공유 기준 이름을 확인한 뒤 editor의 WS를 실제 끊고, editor는 로컬 이름을, owner는 다른 공유 이름을 저장한다. 재연결 뒤 실제 충돌 카드에서 한 라운드는 `공유본 유지`, 다른 라운드는 `내 변경 다시 적용`을 선택한다. 그룹이 없다면 기존 검증 완료 후 실제 `새 레이어 그룹` 버튼으로 만들고 먼저 공유 저장한다. 획 ID·좌표·기존 PNG 기준을 수정하거나 충돌을 runtime에 주입하지 않는다.

두 라운드는 SQLite의 이미 열린 공유 proxy를 통한 `kvGet`으로 복사한 저널을 읽기 전용 검증기에 전달해 원본·payload 참조·선택·replacement·receipt를 대조한다. 새 저장 주체를 만들거나 저널에 직접 쓰지 않는다. `공유본 유지`는 editor의 추가 Yjs 변경과 서버 receipt가 없어야 하며 owner의 공유 이름이 유지돼야 한다. `내 변경 다시 적용`만 새 editor 변경의 실제 서버 ACK와 서버 원고의 로컬 이름 반영을 요구한다. 저널의 `yjsUpdateId`를 wire의 update UUID와 같은 식별자로 간주하지 않는다. 각 선택 뒤 서버 원고·기존 작화·양쪽 재열기를 확인하며 이 추가 라운드가 통과하기 전에는 충돌 UI의 실제 검증 완료로 보고하지 않는다.

최종 검증 결과는 실행한 정확한 소스 SHA와 함께 이 기록과 PR에 갱신한다. 재질 첫 적용 수정은 총괄 담당의 별도 PR·검증 증거와 연결하고, 이 문서를 그 수정의 통과 근거로 사용하지 않는다.
