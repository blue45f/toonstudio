## ToonStudio에서 바뀐 제작 동선

- **대본**에서 회차가 하나일 때도 두 번째 회차를 추가할 수 있다. 장면 제목을 누르면 원문 위치로 이동한다. 기기 안에서 작품 원문을 보존하고 같은 탭을 다시 열 때 보던 회차를 복구한다. Chrome 390px와 1440px에서 두 번째 회차를 저장하고 다시 열어 작가실 JSON의 회차 제목·시놉시스·장면·대사를 대조했다. 첫 회차 보존도 확인했다.
- **3D 배경**에서 작품에 맞는 소재를 내부 소품 이름으로 찾을 수 있다. 작은 화면에서 ‘물뿌리개’로 온실을 찾아 바닥을 터치해 배치하고 구도 선택이 활성화되는 것을 Chrome에서 확인했다. 배치에 쓰는 광선과 화면에 보이는 장면이 같은 카메라를 사용한다.
- **3D 촬영표**에서 고정한 컷 하나 또는 전체의 카메라 이름, 초점 거리나 직교 범위, 위치·주목점, 원본의 출력 크기와 소재 이름을 읽거나 TXT로 받을 수 있다. 장면을 재구성하지 않고 각 컷에 보관한 값을 읽는다. 촬영표와 컷 패널 단위·통합 테스트 26건이 통과했다.
- **캐릭터 랩**에서 왼손 브이와 오른손 주먹을 만든 뒤 한쪽 손목만 움직일 수 있다. 브이에서 손목을 42° 굽히고 되돌린 뒤 편집 파일을 다시 여는 실험에서 42개 손 관련 GLB 본 가운데 왼손목만 달라졌다. 다시 연 장면의 780×638 이미지가 저장 전과 일치했다. 이 검사는 독립 캐릭터 랩에서 진행했다.
- **말풍선**에 선택한 컷으로 대사를 넣는 경로를 추가했다. 컷 전체에 자동 배치하는 명령도 사용할 수 있다. 해당 변경의 단위 테스트에는 기존 말풍선·효과 레이어의 상대 순서 보존이 포함된다.
- **원고와 소재 메뉴**에 캐릭터·온실·펜·콘티·연출 의자·완성 원고를 그린 자체 제작 ImageGen 일러스트를 적용했다. 6종의 투명 WebP 파일은 58,416바이트다. 휴대폰의 전문 도구 전체 목록은 2열로 펼쳐진다. 원고 더보기의 검색은 도구와 필터의 원래 명령을 실행한다. 사용 불가 필터에는 이유가 표시된다.

## 비교 범위

390×844 터치에서 브러시 관리창을 여닫고 같은 작품의 3D 배경으로 이동했다. 820×1180과 1440×960에서 키보드로 배경 다음의 캐릭터 도구로 이동해 작품 경로가 유지되는 것을 확인했다. 별도 원고에 두 컷을 고정하고 선택 컷 TXT와 전체 촬영표 TXT를 내려받았다. 기기에 저장하고 새로고침한 뒤 받은 전체 TXT는 처음 파일과 일치했다. 이 네 브라우저 시나리오는 재시도 없이 통과했다.

390px 휴대폰에서 사선으로 나눈 아래 컷에 두 줄을 넣었다. 수정 전에는 두 번째 말풍선이 윗변을 6.81원고 px 넘었다. 수정 후 최소 여백은 4.52원고 px였고, 저장과 재열기를 거친 두 말풍선에 같은 컷 ID가 남았다. 삼각·오목 컷, 공간 부족과 손상 좌표는 단위 테스트로 확인했다.

일반 투닝의 공개 [매직 작업 화면](https://tooning.io/magic)에서는 글·참조 이미지, 스타일, 비율, 제외 단어와 장수 선택이 보였다. 생성 요청은 로그인이 필요했다. REA 관찰 번호는 `ev_695ed1d42d6953732c32aecfbffc716a9efd4afd9227513d8b8f7722322270a2`다. 같은 제품의 [서비스 메뉴](https://tooning.io/)에는 캐릭터·에디터·보드·챗·글쓰기·타자도 있었다. 메뉴 노출을 관찰한 번호는 `ev_343ab3a2fcd8d25726baeb1b67a87abc00f90edbf38a6d5aa4bf42d5a7592fe9`다.

[디브 홈](https://deev.world/home)에서는 캐릭터 챗과 웹툰·웹소설 탭, 랭킹·카테고리 탐색이 함께 보였다. REA 관찰 번호는 `ev_6dc216bbb7abb8e46465632c1250292545c4c03a1bb46d544dc0c1c51596e6f0`다. 이 관찰에서는 독립 툰비 서비스의 현재 제공 여부나 개인 대화 생성·결제를 검증하지 않았다.

## 3D 배경을 원고에 넣어 확인한 결과

2026-11-19 로컬 정적 빌드 `b8ea0fb0d3dc`에서 기본 배경 35개를 서로 다른 빈 원고에 배치했다. Chrome의 Three.js r187 WebGPU에서 추천 구도를 적용한 뒤 컬러 레이어를 넣고 원고를 다운로드했다. 35개 모두 선택한 모델 한 개, 첨부 GLB의 SHA-256, 저장된 화각이 일치했다. 원고에서 추출한 2731×1534 PNG도 35개가 서로 달랐다.

학교 정문은 전체를 찍으면 돌기둥 문양이 작게 보였다. 세부 구도 버튼에 촬영 대상 이름을 표시하고, 유적의 룬 분수·옥상 급수탱크·교문 돌기둥에 근접 구도를 추가했다. 정적 빌드 `69dbdf976c86`에서 세 장소 모두 추천 구도 → 세부 구도 → 실행 취소·다시 실행 → 원고에 삽입 → 기기 저장 → 새로고침 → 원본 레이어 재편집을 확인했다. 새로 연 PNG 데이터와 모델 해시, 카메라 값이 저장 시점과 일치했다. 픽셀 비율은 각 원고 PNG를 640×359 크기에 맞춘 뒤 연회색 배경(RGB 240, 240, 240)과 한 채널이라도 16을 넘게 차이 나는 픽셀을 센 값이다. 세 장소의 기본·근접은 같은 GLB를 사용했다. 이 비율에는 촬영 대상과 그 주변의 기둥·난간 등 배경 모델 전체가 포함된다.
