2026-11-19 로컬 개발판에서 조사했다. 플로터는 공식 가이드, 공개 홈, 사용자가 로그인한 Chrome의 테스트 원고에서 확인했다. ToonStudio는 프로젝트의 소스, 원고에서 실행한 동작, 내려받은 파일을 구분해 기록했다.

## 로그인 후 직접 확인한 편집 동선

- 테스트용 빈 캔버스에 이름을 붙이고 컷 두 개를 만든 뒤 별도 탭에서 같은 원고를 다시 열었다. 제목과 컷 두 개가 복원됐다. 빈 컷에서 3D 수정을 누르니 인물을 자동 배치할 수 없다는 메시지(`no-figures`)가 떴다. 인물 없는 상태의 결과를 포즈 저장 성공으로 계산하지 않았다.
- 캐릭터 제작에는 얼굴·체형을 양방향으로 조정하는 슬라이더, 전신 포즈와 손 포즈, 카메라 화각, 조명 강도·각도, 참조 이미지와 사용자 포즈 저장이 있었다.
- 그림체 화면에서 선질·인물 비례·채색·질감·배경 효과를 따로 설정하고 프리셋을 저장하는 컨트롤을 확인했다. 대본은 장르와 분위기를 직접 고르는 경로, 아이디어 보드는 글·그림·스케치와 노드 확장·연결·실행 취소를 제공했다. 유료 이미지 생성이나 음성·영상 공급자의 성능은 시험하지 않았다.

## 이번에 실제로 바뀐 컷 출력

원고의 **출력 설정 → 컷으로 내보내기**에서 장면 설명과 대사를 그림 없이 TXT로 저장한다. 숨긴 글은 제외하고, 컷 밖 여백에 쓴 글은 해당 페이지 끝에 따로 둔다. 컷이 없는 페이지는 한 컷으로 담고, 정방형 출력은 긴 변을 맞춰 말풍선과 화면 가장자리가 잘리지 않게 한다. 네 컷을 넘으면 읽기 순서로 시트를 나눠 ZIP에 넣는다.

390px Chrome에서 같은 게스트 원고를 프로젝트 파일로 내려받아 두 개의 크기·색이 다른 컷과 장면 설명을 담아 다시 열었다. 출력 메뉴에서 TXT, ZIP, PNG를 각각 내려받았다. TXT의 두 설명 순서, ZIP의 두 파일 이름과 1080 × 1080 크기, 네 컷 시트의 2160 × 2160 크기를 확인했다. 첫째·둘째 칸 가운데의 픽셀이 각각의 낱장과 같았다. 이 시험은 플로터의 생성 이미지나 소스, 실제 사용자의 작품을 쓰지 않았다.

## 213개 메뉴의 실제 진입점

새 원고의 18개 메뉴에서 213개 명령을 모두 눌렀다. 빠른 시작, 캔버스 크기, 저장 브러시, 패널 접기·펼치기의 대상과 상태 표시를 바로잡았다. 게스트 게시 버튼은 로그인을 안내했고, 권한이 있는 로컬 소유자는 사전 검사까지 진행한 뒤 닫았다. 게시 쓰기 요청은 0건이었다. 작품에 연결한 소유자 원고에서는 비교 검수 버튼이 같은 기기·작품 범위의 수신함에 1362×2043 PNG 1개(62,104바이트)를 추가했다. 두 페이지 원고와 서버 저장본은 작업 전후 해시가 같았다.
