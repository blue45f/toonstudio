# ToonStudio 사용성 벤치마크 검토 (2026-10-13)

> 목적: "기능이 있는가"가 아니라 "실제 업무 흐름에서 사용자가 직관적으로 받아들이는가"를 검증한다.
> 방법: ① 레포 내장 벤치마크 체계 감사 ② 외부 경쟁 제품 IA 벤치마크 ③ 핵심 과업 6개 인지 워크스루 ④ Nielsen 휴리스틱 평가
> 대상 PR: #2297 (ux/intuitive-wayfinding-2026-10-13)

## 1. 레포 내장 벤치마크 감사 — 기능은 재는데, 사용성은 안 잰다

레포에는 이미 상당한 벤치마크 자산이 있다.

| 자산 | 내용 | 성격 |
| --- | --- | --- |
| `docs/benchmarks/studio-competitor-registry.json` | 경쟁·인접 제품 **62개** (Clip Studio Paint, Krita, MediBang, ibisPaint, Procreate, Photoshop, Figma, Canva, Storyboard Pro, Live2D, Blender…) | 기능 패리티 |
| `docs/benchmarks/studio-competitive-intake-2026-09-02.md` | 12개 분야 × 제품별 흡수 주제, P0 스트림 7개 (문서 무결성, Smart Shape, 비파괴 보정, 자연매체, 3D, 애니메이션, AI) | 기능 패리티 |
| `docs/benchmarks/studio-webtoon-ecosystem-registry.json` | 웹툰 특화 제품 (Snaptoon, NAVER WEBTOON SHAPER 등) P0~ | 기능 패리티 |
| `apps/web/src/domains/creator/drawing/DRAWING-BENCHMARK.md`, 각종 `*-parity.test.ts` | 엔진·브러시 패리티 검증 | 성능/충실도 |

완료 기준 8개 중 사용성과 닿은 것은 **1번 "실제 Studio UI에서 발견하고 실행할 수 있다"** 뿐이다. 다음이 없다.

- 과업 성공률·완료 시간·클릭 수 같은 **과업 지표**
- 첫 사용자 기준의 **발견 가능성 테스트** (기능이 몇 뎁스 안에 있는지)
- 용어 이해도 (사용자가 메뉴 이름만 보고 목적을 맞히는가)
- SUS/UMUX 같은 표준 사용성 점수

**결론**: ToonStudio의 벤치마크는 "경쟁 제품이 가진 기능을 가졌는가"는 세계 수준으로 관리하지만, "사용자가 그 기능을 찾는가"는 측정하지 않는다. 기능이 5,569개 파일 규모의 creator 도메인에 쌓일수록, 병목은 기능이 아니라 발견 가능성이다. 이 보고서가 그 빈칸을 채운다.

## 2. 외부 벤치마크 (경쟁 제품 IA)

공식 지원·헬프·튜토리얼 문서를 근거로 확인한 결과다. 확인되지 않은 항목은 추측하지 않았다.

| 제품 | 시작 구조 | 새 작품까지 | 에셋 | 게시 | 저장 고지 |
| --- | --- | --- | --- | --- | --- |
| Clip Studio | 런처가 Paint·작품·ASSETS 허브 | 메뉴 1회 + 용도/템플릿 대화상자 | 다운로드 → **자동 설치** → Material 팔레트 (4.2부터 자동 장착) | 소재 게시는 런처 안에서 완결 | 자동저장은 **설정에서 켜는 옵션** (구식 패턴) |
| 메디방/점프 | 실행해도 캔버스가 안 열리고 클라우드 창이 먼저 뜸 | 클라우드 창에서 용도 선택 → 템플릿 | 클라우드 라이브러리 | 미확인 | 미확인 |
| ibisPaint | My Gallery가 실질적 홈 | + 버튼 → 용도 프리셋 | 내장 소재 + 온라인 갤러리 재사용 | 앱 내 Upload | 미확인 |
| WEBTOON Canvas | 우상단 단일 CTA **Publish** | 시리즈 개설 "6 Easy Steps" 번호 가이드 | 해당 없음 | 임시저장 + PC/모바일 미리보기 | 회차 단위 명시적 저장 |
| Canva | 검색 중심 홈: 최근+템플릿+빠른 시작 공존 | 검색 또는 버튼 1회 → 템플릿 | **에디터 안 패널에 통합** | Share 상시 고정 | **"All changes saved" 상시 표시** |
| Figma | 파일 브라우저 (신규자에겐 예제 파일이 미리 있음) | 브라우저에서 생성 | Community ↔ Assets 패널 연결 | 링크 공유 | 자동 버전 히스토리, 파일명 상시 표시 |

### 축별 업계 표준

- **시작 화면**: 최근 작업 + 새 작품 + 템플릿이 **한 홈에 공존**하는 것이 표준. 어느 하나를 먼저 고르게 강제하지 않는다. 메디방처럼 계정·클라우드 창이 첫 화면을 가로막는 구조는 반면교사.
- **내비 용어**: 1뎁스 5~7개, 전부 사용자 언어 (Home/Projects/Templates/Publish/My Gallery). 도구 이름으로 시작하는 경우는 드물다.
- **현재 위치**: 브레드크럼보다 **작품명을 에디터 상단에 상시 고정**하는 방식이 표준. Figma는 파일명이 위치 표시와 히스토리 진입점을 겸한다.
- **에셋**: 스토어가 별도인 건 문제가 아니다. **적용이 에디터 안에서 끝나야** 표준이다 (Clip Studio 자동 장착).
- **게시**: 번호 매긴 단계 가이드 + 미리보기 + 임시저장을 공식 문서가 보장 (Canvas).
- **자동저장 고지**: 자동저장 자체보다 **상태 문구를 상시 보여주는 것**이 표준 (Canva). Clip Studio식 "설정에서 켜는 자동저장"은 구식.
- **고속 탐색**: 검색은 전 제품 공통. 명령 팔레트는 Figma Cmd+/ 가 모범 — 결과 옆에 단축키를 표시해 학습을 겸한다.

출처: Clip Studio 공식 지원(support.clip-studio.com), Canva 헬프센터, WEBTOON Creators 101 및 Help Center, 메디방 공식 튜토리얼, ibisPaint 공식 강의, Figma 관련 공식/튜토리얼 자료. 네이버웹툰 연재 원고 시스템은 비공개라 제외했다.

## 3. 인지 워크스루 — 실제 업무 흐름 6개

각 과업을 "처음 온 사용자"의 눈으로 따라가며 의사결정 지점(D)과 마찰을 셈한다. 판정은 PR #2297 적용 후 상태 기준이다.

### 과업 1. 신규 창작자 — 첫 작품 만들기 시작
`진입(인트로, 세션 1회·비차단) → 홈 → GNB "제작" → 선택 → /create 시트 → 새 작품 → 에디터`

- D1: GNB 제작 드롭다운 5개 (스튜디오 / 작품 시작하기 / 웹툰 만들기 / 캐릭터 만들기 / 3D 배경). "작품 시작하기"와 "웹툰 만들기"가 둘 다 시작점처럼 읽힌다. 웹툰을 만들 사람은 어디로 가야 하는가? — **마찰 상**
- D2: /create 시트 (새 작품·템플릿·이어가기) — 잘 설계됨. 한 화면에서 고른다.
- D3: 에디터 표면 7종 (canvas/comic/animation/brushes/bg3d/poser/character) 중 기본값이 무엇인지 초보자는 모른다.
- 총평: 시작 시트까지의 길은 좋으나, 그 앞의 드롭다운이 한 번 더 헷갈리게 한다. 벤치마크 표준(Canva·Clip Studio)은 "새로 만들기" 단일 버튼 + 같은 화면 템플릿이다.

### 과업 2. 독자 — 장르별 인기 작품 찾기
`홈 → 탐색(장르/랭킹/캘린더) 또는 전체 메뉴 "작품 찾기"`

- 경로는 짧고(2~3단계) 그룹 라벨이 사용자 언어다. — 양호
- 단, "탐색" 아래 목적지가 둘이다: 헤더 "장르"는 `/explore`, 전체 메뉴 "탐색"은 `/discover`. 이름이 같은데 페이지가 다르다. — **마찰 중** (별칭 정리 대상)

### 과업 3. 작업 중단 후 이어서 그리기
`재방문 → /studio 최근 작업 | /create 이어가기 | 내 홈 최근 작업 | 연속성 안내`

- 복구 자체(로컬 저장·복구 상태 문구)는 강하다. RouteFallback이 "마지막으로 작업한 위치를 확인하고 있습니다"로 상태를 설명한다.
- 그러나 "이어가기" 입구가 3곳 이상으로 분산돼, 사용자는 매번 같은 곳으로 돌아오지 못한다. — **마찰 중** (대표 입구 1곳 지정 필요)

### 과업 4. 완성 후 게시·연재
`에디터 → 검수·내보내기(/studio/publish) | 연재 센터(/publish)`

- 두 표면의 차이를 이름만으로 알 수 없다. 코드 주석 스스로 "본문이 다른 분화 표면"이라 적시. — **마찰 상** (각 화면 상단에 관계 설명 1줄 + 상호 링크로 완화 가능)

### 과업 5. 소재(브러시·에셋) 사서 작품에 적용
`마켓(둘러보기→상세→구매) → 내 보관함 → 스튜디오 작품 재료(/studio/assets) → 에디터 적용`

- 마켓과 에디터가 별도 표면이라 "샀다 → 쓴다"가 끊긴다. 업계 표준(Clip Studio ASSETS)은 스토어가 도구 안에 있고 적용이 1~2단계다. — **마찰 중상** (에디터 내 마켓 검색/적용 진입점이 완화책)

### 과업 6. 팀원 초대해 검수받기
`협업 진입 → 제작 관리(/production) 프로젝트 → 검수 표면`

- "협업"이 가리키는 곳이 4곳 (제작 관리·팀/권한·구인/의뢰·커뮤니티)이라 첫 선택부터 추측이 필요하다. — **마찰 상** (P1 분류체계 단일화와 함께 해소)

### 워크스루 요약

| 과업 | 단계 | 마찰 | 주 원인 |
| --- | --- | --- | --- |
| 1. 첫 작품 시작 | 4~5 | 상 | 시작점이 2개로 읽힘 |
| 2. 작품 찾기 | 2~3 | 중 | /discover·/explore 이름 충돌 |
| 3. 이어 그리기 | 2~3 | 중 | 입구 분산 |
| 4. 게시·연재 | 3~4 | 상 | publish 3표면 |
| 5. 소재 적용 | 4~5 | 중상 | 마켓↔에디터 단절 |
| 6. 팀 검수 | 3~4 | 상 | "협업" 4갈래 |

PR #2297로 좋아진 부분: 모든 과업에서 "지금 어디인가"(브레드크럼 121개, 제목 분리)가 개선됐고, 전체 메뉴에서 운세 같은 비업무 항목이 업무 그룹에 섞이지 않게 됐다. 남은 마찰은 대부분 **시작점·중복 이름** 문제로, 보고서 §5 로드맵 P1·P2가 직접 겨냥한다.

## 5. 직관성 검증 — 실사용자 테스트 프로토콜 (실행 대기)

코드 분석만으로 "직관적이다"를 확정할 수 없다. 다음 프로토콜을 제안한다 (PR 머지 후 1주 내 실행 권장).

- **대상**: 웹툰 창작 경험자 3명 + 입문자 2명 (원격 비조정, 화면 공유)
- **과업**: 위 6개 과업을 지시문만으로 수행. 성공 기준: 도움 없이 3분 내 완료
- **지표**: 과업 성공률, 첫 클릭 정답률 (first-click test), 완료 시간, 사후 SEQ(과업별 난이도 7점)
- **카드 소팅 검증**: 전체 메뉴 29개 목적지의 그룹 이름만 보고 분류 — 특히 "쉬어가기" 신설이 다수 의견과 일치하는지
- **합격선**: 성공률 80%, 첫 클릭 정답률 70%, SEQ 평균 5.5 이상. 미달 과업은 로드맵 P1·P2 착수 근거로 사용

## 6. 재채점 (벤치마크 반영)

외부 벤치마크와 워크스루를 반영해도 기존 채점(66 → PR 후 79)의 뼈대는 유지된다. 달라진 것은 근거의 성격이다: 이제 점수는 "내부 코드 품질"이 아니라 **경쟁 표준 대비 과업 마찰**로 설명된다. 90점대까지는 §5의 실사용 테스트 통과 + 로드맵 P1(분류체계 단일화)·P2(동음이의 정리)가 필요조건이다.

## 7. 벤치마크에서 새로 나온 고도화 과제 (PR #2297 이후)

| 우선 | 과제 | 근거 | 예상 효과 |
| --- | --- | --- | --- |
| 신규 P0 | **에디터 상단에 저장 상태를 상시 문구로 표시** ("저장됨 · 오후 3:12" / 저장 중 / 복구 가능). ToonStudio의 저장·복구 기술은 경쟁 제품보다 강한데 사용자가 볼 수 없어 체감되지 않는다 | Canva "All changes saved" | 상태 커뮤니케이션 +2 |
