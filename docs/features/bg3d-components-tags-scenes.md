# 3D 장면의 컴포넌트·태그·장면 정보와 SKP 이름 연결

- 상태: **current** — 소스와 테스트로 확인되는 현재 동작이다. 사람이 실제 브라우저에서 조작해 본 결과는 아니다(→ "검증 범위").
- 확인일: 2026-10-22 (`apps/web/src/domains/creator/bg3d/`, `apps/web/src/domains/creator/scene3d/`)
- 범위: 배경 3D 장면 문서(`toonstudio.bg3d-scene`)에 더한 노드 태그·컴포넌트 참조·장면 이름과 메모·숨긴 태그 목록, 3D 장면 아웃라이너의 태그 칩·태그별 숨기기·컴포넌트 묶음 보기, SketchUp(.skp) 가져오기의 이름 연결(SKP 사이드카), 3D 모델 라이브러리의 원본 이름 검색, 컷(샷)·고정 컷과의 연동.

- 문서 버전: 장면 문서 `version`은 **3 그대로**다. 새 필드는 모두 선택 필드이다. 처음 계획(버전을 올리고 이전 버전에서 옮기기)과 다른 선택이라 **소유자 판정을 기다린다**(2026-10-22 기준 미결). 이유·대가·판정 선택지는 "버전을 올리지 않은 이유와 대가"에 적었다.

## 원칙

1. **이름만 잇는다.** SKP에서 온 컴포넌트·태그·장면은 이름 글자만 장면 문서와 라이브러리 검색에 쓰인다. 계층, 태그(레이어) 표시 상태, 장면(카메라)은 되살리지 않으며 화면과 이 문서가 같은 말로 알린다.
2. **파일 안의 이름은 믿을 수 없는 글자다.** 화면에는 글자(text)로만 그리고, 문서에 옮길 때는 태그·메모 규칙(주소·자격 증명 모양·제어 문자·`__proto__` 거절)을 다시 통과해야 한다.
3. **태그 숨김은 오브젝트 숨김과 별개다.** 태그를 숨겨도 오브젝트의 `visible`은 바뀌지 않는다. 그래서 태그를 다시 보여도 따로 숨겨 둔 오브젝트는 숨겨진 채로 남는다.
4. **사용자가 누를 때만 문서가 바뀐다.** 태그와 메모는 자동으로 붙지 않는다(SKP 이름은 "태그로 붙일 이름" 제안과 "메모 후보"로만 보인다). 예외 하나: .skp를 **가져와 배치하는 순간**에는 그 배치에 한해 컴포넌트 묶음 참조(`skp-<해시 앞 16자리>`)가 붙는다.
5. **규칙에 어긋나면 일부만 적용하지 않고 통째로 거절한다.** 한도를 넘거나 규칙에 맞지 않는 편집은 이유(`invalid-input`·`limit-exceeded`·`unchanged`·`entity-not-found`·`busy`)와 함께 거절하고, 화면은 다음 행동이 있는 문장으로 알린다.
6. **편집은 기존 실행 취소 경로로 커밋한다.** 새 기록 장치를 만들지 않았다. 캡처·일괄 렌더·복원·물리 조작 중에는 구성 편집을 막는다(`busy`).

## 문서 형식과 버전

모든 필드는 선택이며, 값이 없으면 **키 자체를 만들지 않는다**(빈 배열·빈 객체를 쓰지 않는다). 그래서 태그·컴포넌트·장면 정보를 쓰지 않은 문서는 이전과 바이트가 같다.

| 필드 | 위치 | 규칙 |
| --- | --- | --- |
| `tags` | 노드 | 노드당 최대 **8개**, 태그 하나 최대 **32** 코드 포인트. NFKC 정규화·앞뒤 공백 제거·연속 공백 접기, 중복 제거, 코드 유닛 순서 정렬(`localeCompare`를 쓰지 않아 로케일이 바뀌어도 바이트가 같다). 규칙에 맞지 않는 항목(제어 문자·주소·자격 증명 모양·`constructor`/`prototype`/`__proto__`)은 버린다 |
| `componentRef` | 노드 | `{ id, name }`. `id`는 `^[A-Za-z0-9][A-Za-z0-9._~-]{0,79}$`, `name`은 최대 **48** 코드 포인트. 하나라도 규칙에 맞지 않으면 참조 전체를 버린다. 알 수 없는 키가 있으면 엄격 경계가 거절한다 |
| `meta.name` | 장면 | 최대 **80** 코드 포인트 |
| `meta.memo` | 장면 | 최대 **600** 코드 포인트. 줄바꿈을 살리되 줄마다 같은 텍스트 규칙을 적용하고, 앞뒤 빈 줄을 없애며 연속 빈 줄은 하나로 접는다. 한 줄이라도 주소·자격 증명 모양이면 메모 전체를 버린다 |
| `meta.hiddenTags` | 장면 | 숨긴 태그 목록. 최대 **64개**. 객체(사전)가 아니라 목록이라 임의 키로 프로토타입을 건드릴 길이 없다 |
| `hiddenTags` | 컷(샷) | 컷을 만들 때의 숨긴 태그. 태그를 쓰는 장면의 컷만 이 필드를 갖는다 |

편집이 쓰는 한도는 문서 한도보다 조금 더 보수적이다: 장면 전체에서 서로 다른 태그는 **64개**(숨긴 태그 목록 한도와 같아 모든 태그를 숨길 수 있다), 태그·컴포넌트 참조가 차지하는 바이트 어림값은 **96KiB**(문서 예산 320KiB를 이것만으로 채우지 못하게 한다).

### 엄격 경계와 편집 경계

- **엄격 경계**(`parseStudioBg3dSceneDocument`·`serializeStudioBg3dSceneDocument`): 정본이 아닌 표기(정렬되지 않은 태그, 중복 태그, 빈 태그 목록, 빈 `meta`, 알 수 없는 키, 한도 초과)를 거절한다.
- **관대한 정규화**(`normalizeStudioBg3dSceneDocument`): 규칙에 맞지 않는 개별 값은 버리고, 한도를 넘으면 예산 오류를 던진다.
- **이전 버전 읽기**(`migrateStudioBg3dSceneDocument`): v1·v2 표시가 붙은 문서가 `meta`·`tags`·`componentRef`를 주장하면 거절한다(이 필드는 v3에서 생겼다).
- **편집 경계**: 편집 계획은 한도를 넘는 변경을 `limit-exceeded`로 먼저 거절한다. 편집기 상태를 문서로 옮기는 경계(런타임 ↔ 문서 변환)는 예산 오류를 던지는 대신 앞쪽만 남기는 방식(`truncate`)을 쓴다.

### 버전을 올리지 않은 이유와 대가

장면 문서 `version`은 3으로 두었다. 처음 계획은 "버전을 올리고 이전 버전에서 옮기기"였으나 선택 필드 추가로 바꿨고, 이 선택은 **소유자 판정을 기다린다**(미결). 선례는 코드로 일부만 확인된다: `pinnedVersionedCut`은 v1·v2 거절 가드에 없어 나중에 더한 선택 필드로 보이고(`migrateDecodedSchemaV2Document` 등), `shots`·`activeShotId`·`camera.nearClip`은 v1·v2 거절 가드에 있어 v3 도입과 함께인지 이후 추가인지 저장소 이력(스쿼시 병합)으로 가릴 수 없다.

**올리면 무엇이 함께 바뀌어야 하나(코드 읽기로 확인).** 요소(`element.bg3dScene`)가 문서를 그대로 품고, 문서 모듈을 가져오는 소스 파일(타입 가져오기 포함)이 118개(시험 제외, 2026-10-22), 엄격 파싱·직렬화·이전 버전 읽기를 부르는 파일이 29개(문서 모듈 자신과 도구 3개 포함)다. 그중 저장된 v3 데이터를 직접 만지는 곳이 막힌다.

| 소비자 | 버전을 올리면 | 근거 |
| --- | --- | --- |
| 고정 컷(`pinnedVersionedCut`) | `parseStudioScene3dCutSource`가 `legacyBg3d`를 엄격 파서로 다시 읽으므로 저장된 v3 원본이 거절된다. 이행해서 읽으면 `version`이 달라져 `parseCut`의 `sourceHash` 검사("고정한 원본 해시가 저장 내용과 다릅니다")에 걸린다. 해시를 원본 바이트 기준으로 바꾸거나 이행 때 다시 계산하고 승인을 다시 받아야 한다 | `studio-scene3d-shot-versions.ts` |
| 3D 템플릿 보관 | 기록의 `sceneJson`이 정본 직렬화와 글자 그대로 같아야 읽는다. 저장된 v3 템플릿이 모두 거절된다. 읽을 때 이행하고 다시 저장하는 단계가 필요하다 | `bg3d-template-library.ts` |
| 프로젝트 가져오기·아카이브 | 가져오기는 `migrateStudioBg3dSceneDocument`를 거치므로 v3→v4 이행이 있으면 읽힌다. 아카이브 지문(`collectBg3dSceneFingerprints`)은 `serialize`로 만들어 이행 전 v3 장면은 지문을 못 만든다. 이행 뒤에 비교하도록 순서를 맞춰야 한다 | `studio-project-file.ts`, `studio-project-archive.ts`, `studio-bg3d-project-library.ts` |
| 관대한 정규화(`normalizeStudioBg3dSceneDocument`) | 모르는 `version`은 기본 장면으로 되돌린다. 이행 없이 부르는 곳은 장면이 통째로 비워진다. 시험을 뺀 7개 파일의 16개 호출 지점을 하나씩 점검해야 한다 | `studio-bg3d-scene-document.ts`, `studio-bg3d-grade-plates.ts`, `useStudioBg3dCanonicalDocumentState.ts` 등 |

이 표에 없는 소비자(자동 저장·협업 게시 등 요소 안에 문서를 품는 경로)는 점검하지 않았다.

**대가(앞으로만 나아가는 변경).** 이 기능을 모르는 이전 빌드가 새 문서를 만나면 경로에 따라 결과가 갈린다. 이 기능 직전의 문서 모듈 소스를 임시 시험 코드로 그대로 실행해 확인했다(시험 코드는 저장소에 넣지 않았다). **실제 이전 빌드를 띄워 본 것은 아니다.**

1. **엄격 경계는 거절한다(소리 나는 실패).** `parse`·`migrate`·`serialize`가 모두 `null`을 돌려준다. 프로젝트 가져오기는 이를 "3D 배경 장면 데이터가 손상되었거나 지원하지 않는 버전입니다."로 알리며 가져오기를 멈춘다.
2. **관대한 정규화는 조용히 버린다(소리 없는 유실).** 알려진 필드만 다시 조립하므로 `tags`·`componentRef`·`meta`를 오류 없이 버린다. 그 결과를 이전 빌드가 엄격 직렬화하면 정상 문서로 통과하고 새 빌드도 그대로 읽는다. 이 문서가 이전 빌드의 편집기 경로(`useStudioBg3dCanonicalDocumentState`, `normalizedRuntimeRoundTrip` 등 — 이 기능이 바꾸지 않은 호출 구조)로 들어가 다시 저장되면 태그·컴포넌트 묶음·장면 이름과 메모가 사라진다. 이전 빌드에서 어떤 실제 진입 경로가 엄격 경계를 건너뛰고 이 경로로만 들어오는지는 나열하지 않았다.
3. **버전을 올려도 이 위험은 없어지지 않는다.** 올린 문서를 이전 빌드가 만나면 엄격 경계는 같은 식으로 거절하고, 관대한 정규화는 모르는 버전을 기본 장면으로 되돌려 태그 몇 개가 아니라 **장면 전체**가 비워진다. 그래서 득실이 비슷하다고 보고 올리지 않았다.

롤백이 필요하면 이 기능으로 쓴 태그·컴포넌트·장면 정보가 든 문서를 먼저 내보내 보관하고, 옛 빌드에서 그 문서를 열어 다시 저장하지 않는다. 이미 열려 있던 옛 빌드 탭이 새 빌드가 쓴 문서를 읽는 경우도 같은 위험이다.

**소유자 판정 선택지.**

- **(a) 지금 상태를 승인한다.** 위 위험을 받아들이고 v3 선택 필드로 둔다. 추가 작업은 없다.
- **(b) 4로 올린다.** `STUDIO_BG3D_SCENE_DOCUMENT_VERSION`을 4로 바꾸고 v3→v4 이행(v3 표시 문서가 `meta`·`tags`·`componentRef`·컷 `hiddenTags`를 주장하면 거절)과 가드 시험을 더한다. 여기에 위 표의 고정 컷 해시 방침, 템플릿 보관 이행, 관대한 정규화 호출부 점검, 템플릿 `sceneJson`·시험 고정값 갱신이 함께 필요하다. 저장 형식을 바꾸는 일이므로 실제 저장 데이터로 이행 시험을 먼저 한 뒤 병합한다.

## 태그 숨기기가 닿는 곳

태그 숨김은 **저장하는 문서의 `visible`을 바꾸지 않고**, 그리는 쪽에서만 `visible: false` 사본으로 투영한다(`projectStudioBg3dTagVisibility`). 숨길 것이 없으면 입력 배열을 그대로 돌려줘 참조가 바뀌지 않는다. 부모가 숨겨지면 자식이 함께 숨겨지는 기존 규칙은 그대로다.

| 경로 | 태그 숨김 반영 | 비고 |
| --- | --- | --- |
| 편집기 뷰포트 렌더(프리미티브·모델 사본, 인스턴싱 후보, 그림자 범위) | 반영 | `studio-bg3d-editor-layout-view-model.ts` |
| 아웃라이너의 "보이는 오브젝트" 계산(숨김 눈 아이콘, "태그로 숨김" 표시) | 반영 | `collectStudioBg3dEffectivelyVisibleEntityIds` |
| 특화 런타임 스냅샷(Babylon 특화 엔진이 받는 렌더 전용 사본: 선·톤·Magic 출력 등) | 반영 — 숨긴 태그를 사본의 `visible`에 굽는다 | `bakeStudioBg3dTagVisibilityIntoDocument`. 저장 문서에는 쓰지 않는다 |
| 물리 미리보기에 쓸 오브젝트 선택 | 반영 — 태그로 숨긴 오브젝트는 고를 수 없다 | 기존 문구 "숨긴 오브젝트는 물리 미리보기에 사용할 수 없습니다." |
| Magic Layer 대상 선택 | 반영 — 태그로 숨긴 오브젝트는 "숨겨진 3D 객체에는 Magic Layer를 만들 수 없어요."로 거절한다 | `studio-bg3d-editor-insert-host.ts`가 구운 사본으로 판정한다. 저장하는 `adapted.document`는 구우지 않는다 |
| 연결 레이어(컷에 붙인 3D 패스)의 재검토 판정 | 반영 — 숨긴 태그가 가리는 결과가 바뀌면 재검토 대상 | 이름·메모·태그 붙이기·컴포넌트 묶기만 바뀌면 재검토 대상이 아니다 |
| 물리 충돌 세계 | **미반영** | 숨긴 태그의 오브젝트도 충돌 후보에 남는다(물리 호스트가 편집기 엔티티를 그대로 쓴다) |
| Scene3D 문서 투영(`projectStudioBg3dDocumentToScene3d`) | **미반영** | 투영을 되돌릴 때 `entity.visible`을 노드에 다시 쓰므로 거기에 굽으면 저장된 `visible`이 오염된다. 태그·컴포넌트·`meta`는 투영을 왕복해도 보존된다(시험) |

## 아웃라이너 사용 흐름

1. 3D 장면 아웃라이너의 "목록 보기 방식"에서 **계층** 또는 **컴포넌트**를 고른다(`aria-pressed` 토글 두 개). 컴포넌트 보기는 같은 컴포넌트에 속한 오브젝트를 한 묶음으로 보이고, 묶음에 속하지 않은 오브젝트는 "컴포넌트 없음"에 둔다. 묶음이 아직 없으면 만드는 방법을 안내한다.
2. 오브젝트에는 태그가 둘째 줄에 보이고(스크린리더는 "태그:"로 읽는다), 태그로 숨겨진 오브젝트에는 눈 아이콘과 "태그로 숨김"이 붙는다.
3. 아웃라이너 아래 접힌 영역 **"태그와 장면 정보"**(기본은 접힘)를 펼치면 다음이 있다.
   - **태그**: 고른 오브젝트에 태그 붙이기, 태그 떼기, 태그 칩(장면 전체 태그 목록), 태그의 오브젝트 모두 선택, 태그 숨기기·보이기. "숨긴 태그는 보기와 출력에서만 빠져요. 오브젝트 자체의 숨김 상태는 바뀌지 않아요."
   - **컴포넌트**: 고른 오브젝트 묶기(묶음 이름 입력), 선택한 오브젝트 묶음 풀기. 묶음 줄에서 접기·펼치기, 이름 바꾸기(제자리 입력, Enter 저장·Esc 취소), 인스턴스 모두 선택, 묶음 풀기. 묶어도 모양이나 위치는 서로 따라가지 않는다.
   - **장면 정보**: 장면 이름과 메모. "장면 정보 저장"을 눌러야 문서에 들어가며 저장 전에는 "저장하지 않은 변경이 있어요."가 보인다.
   - **원본 SKP 이름**: 고른 오브젝트 중 .skp에서 온 모델이 있으면 그 원본의 이름 기록(→ 다음 절).
4. 태그·컴포넌트·장면 정보 영역의 편집은 영역마다 상태 줄(`role="status"`)로 결과를 알리고, 실패는 원인과 다음 행동을 함께 적는다(예: 한도 초과 → "안 쓰는 태그를 뗀 뒤 다시 시도해 주세요."). 묶음 줄의 이름 바꾸기 실패는 줄 아래에 알린다. 묶음 줄의 "묶음 풀기" 단추는 별도 안내 없이 목록만 바뀐다(실행 취소로 되돌릴 수 있다).
5. 실행 취소·다시 실행은 기존 단축키와 버튼을 그대로 쓴다. 장면 이름·메모를 포함한 `meta` 전체가 기록에 들어 있어 되돌리면 함께 돌아온다.

### 접근성

- 트리는 `role="tree"`·`treeitem`, `aria-level`·`aria-selected`·`aria-expanded`를 갖고, 화살표 위/아래·Home·End로 이동한다. 오른쪽 화살표는 접힌 줄을 펼치고(이미 펼쳐 있으면 첫 자식으로), 왼쪽 화살표는 펼친 줄을 접거나 부모 줄로 이동한다. Enter·Space는 선택한다. 묶음 줄도 같은 규칙을 따른다.
- 아이콘 단추도 대상이 든 이름을 갖는다(예: "교실 책상 세트 이름 바꾸기", "교실 태그 숨기기", "교실 태그 오브젝트 3개 선택"). 터치 대상은 `min-h-11 sm:min-h-9`(44px 이상)이고, 아웃라이너 줄의 아이콘 단추는 `panel` 변형에서 `size-11 sm:size-7`이다(`dock` 변형은 데스크톱용 28px). 안내 문구는 12px 이상이며 `NOTICE_TEXT` 토큰을 쓴다.
- 이름 바꾸기는 `autoFocus` 대신 ref로 초점을 입력칸에 옮기고, 저장하거나 취소하면 이름 바꾸기 단추로 초점이 돌아온다. 실패는 입력칸 아래 `role="alert"`로 알리고 입력칸에 `aria-invalid`를 건다.
- 태그 숨김 여부는 색에만 의존하지 않는다(아이콘 + "태그로 숨김" 글자). 태그 칩의 눈 단추는 지금 할 동작을 이름으로 말한다("교실 태그 숨기기" ↔ "교실 태그 보이기").
- 새로 더한 움직임은 묶음 줄 화살표의 회전 하나이며 `motion-reduce:transition-none`을 따른다.

## SKP 사이드카

"사이드카"는 새 파일이 아니라 기존에 있는 **자산 메타데이터의 `skpImport` 이름 기록**(.skp 변환 보고서 v1의 이름, 목록당 최대 16개)이다. 이 기능은 그 기록을 읽어 배치된 노드와 **이름으로** 잇는다.

| 이어 주는 것 | 방법 |
| --- | --- |
| 배치된 노드 ↔ 이름 기록 | 노드가 가리키는 첨부 자료(`generic3dWorkflow.sourceFormat === "skp"`)의 정규화 GLB 해시로 기록을 찾는다. 읽기 전용이다 |
| 같은 .skp를 여러 번 놓은 인스턴스 | 가져와 배치하는 순간 `componentRef`를 붙인다: `id = skp-<해시 앞 16자리>`, `name = 모델 표시 이름`(규칙에 맞지 않으면 "SketchUp 모델"). 같은 해시면 같은 묶음으로 보인다 |
| 컴포넌트·태그(레이어) 이름 | 고른 오브젝트의 "원본 SKP 이름"에 글자로 보인다. 태그 규칙을 통과하는 이름만 "태그로 붙일 이름"으로 제안하고(나머지는 "N개는 태그 규칙에 맞지 않아 제안하지 않아요"), 누르면 **그때** 태그가 붙는다 |
| 장면 이름 | **메모 후보**로만 보인다. "메모에 붙이기"는 메모 초안에 한 줄(`SKP 장면: 이름`)을 더할 뿐이며 "장면 정보 저장"을 눌러야 문서에 들어간다 |
| 라이브러리 검색 | 저장된 이름을 "원본 이름 검색"에 쓴다(→ 다음 절) |

**이어 주지 않는 것(화면의 가져오기 안내와 변환 보고서 자세히 보기에도 같은 문장으로 적었다):** SketchUp의 컴포넌트 계층, 태그(레이어) 표시 상태, 장면(카메라). OpenSKP 변환 보고서가 이름만 내보내기 때문이다. 이름 기록의 상태는 불러오는 중·없음·읽기 실패(다시 시도 단추)로 나뉘어 보인다. 기록이 없으면 "이름 기록은 .skp를 가져온 기기에만 남아요. 다른 기기에서 가져온 소재라면 .skp 파일을 다시 가져와 주세요."라고 알린다. 목록당 16개를 넘는 이름은 저장돼 있지 않으며, 그때는 "전체 N개 중 앞의 M개만 저장돼 있어요."로 밝힌다.

## 원본 이름 검색

3D 모델 라이브러리 패널의 기존 검색 입력이 소재 이름·형식에 더해 **저장된 컴포넌트·태그·장면 이름**도 찾는다(별도 검색 화면이나 추가 불러오기는 없다). 입력 자리 표시는 "모델 이름·형식·컴포넌트·태그·장면 이름 검색…"이다. 소재 이름이 아니라 원본 이름으로만 걸린 카드에는 이유를 카드 아래에 글자로 보인다("원본 이름 일치: 이름 외 N개"). 소재 이름이 이미 맞은 카드에는 붙이지 않는다.

- 대상: 이 기기에 이름 기록이 저장된 .skp 소재. 기록이 없는 소재는 이름으로 걸리지 않는다.
- 이름은 권리 판정에 끼지 않는다(이름이 있어도 권리를 모르면 미확인이다).
- 이름은 최대 48개(목록당 16개 × 3)까지 모으고, 보이지 않는 글자는 걸러 낸다.

## 컷(샷)·고정 컷과의 연동

- **컷(샷)**: 태그를 쓰는 장면에서 컷을 만들면 그 시점의 숨긴 태그 목록(`hiddenTags`)을 함께 기억하고, 컷을 적용하면 그 목록으로 되돌린다. 이 필드가 없는 이전 컷은 적용해도 태그 가시성을 건드리지 않는다. 태그가 없는 장면의 컷은 이전과 바이트가 같다.
- **고정 컷(`pinnedVersionedCut`)**: 원본 문서(`legacyBg3d`)에 태그·컴포넌트·`meta`가 들어 있어도 `sourceHash`는 저장 모음을 왕복한 뒤에도 같고, 구성 정보가 없는 예전 원본으로 만든 컷도 그대로 검증된다. 고정 컷을 되살리는 투영이 노드 태그·컴포넌트 참조·숨긴 태그를 잃지 않는다.
- **연결 레이어 재검토**: 보이는 결과를 바꾸지 않는 편집(태그 붙이기·컴포넌트 묶기·장면 이름·메모)은 재검토 대상이 아니고, 숨긴 태그가 가리는 오브젝트가 있는 상태에서 태그를 숨기거나 다시 보이면 재검토 대상이다. 오브젝트를 직접 숨긴 것과 태그로 숨긴 것은 같은 보이는 결과로 본다.
- **컷의 `savePerformance`는 바꾸지 않았다.** 이미 만든 컷 레이어의 태그 가시성은 컷에서 "원본 갱신"을 해야 다시 반영된다.

## 알려진 한계와 후속 작업

- **문서 `version`을 올리지 않았다**(→ "버전을 올리지 않은 이유와 대가"). 처음 계획과 다른 선택이라 소유자 판정을 기다린다. 이 필드를 모르는 이전 빌드는 엄격 경계에서 거절하거나 관대한 정규화에서 태그·컴포넌트·장면 정보를 오류 없이 버릴 수 있다(이전 문서 모듈 소스로 확인, 실제 이전 빌드로는 미확인). 앞으로만 나아가는 변경으로 다룬다.
- **태그 숨김이 닿지 않는 곳**: 물리 충돌 세계, Scene3D 문서 투영(→ "태그 숨기기가 닿는 곳"). 컷의 `savePerformance`도 갱신하지 않아 "원본 갱신"이 필요하다.
- **SKP 사이드카는 이름만 잇는다.** 컴포넌트 계층·태그 표시 상태·장면 카메라는 되살리지 않는다. 이름은 변환 보고서가 목록당 16개까지만 저장하므로 큰 모델의 이름은 일부만 남는다.
- **컴포넌트 참조 자동 연결은 .skp를 가져와 배치하는 순간에만 한다.** 라이브러리에 저장해 둔 SKP 소재를 나중에 놓은 경우에는 자동으로 묶이지 않고, 아웃라이너의 "원본 SKP 이름"(읽기)과 손으로 묶기만 가능하다.
- **이름 기록은 .skp를 가져온 기기에만 있다.** 다른 기기에서 열면 "이름 기록이 없어요"가 보이고 라이브러리 이름 검색에도 걸리지 않는다.
- **오브젝트 이름 바꾸기**는 기존 `window.prompt` 방식 그대로다(컴포넌트 묶음 이름은 제자리 입력).
- **"태그와 장면 정보" 영역은 기본으로 접혀 있다.** 처음 쓰는 사람이 찾기 어려울 수 있는지는 사람이 써 보고 정해야 한다.
- 아웃라이너 줄 수가 매우 많을 때(수천 개)의 성능과 태그 칩 목록의 스크롤은 측정하지 않았다.
- 나머지 로케일의 번역과 실제 브라우저 확인은 후속 작업이다.
