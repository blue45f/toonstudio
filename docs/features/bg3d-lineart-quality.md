## 2. 설정과 데이터 흐름

`output.line` 에는 기존 16개 필드에 **선택 필드 2개**가 더해졌다. 컷별 덮어쓰기(`shots[].output.line`)에서는 입력에 있는 키를 그대로 남긴다(`false` 도 문서 전체 설정을 덮는 값이라 의미가 있다).

| 필드 | 범위 | 비고 |
| --- | --- | --- |
| `interiorSuppressionEnabled` | `true` | 켰을 때만 저장한다. 없으면 꺼짐 |
| `interiorSuppressionStrength` | 0..1 | 켜져 있고 기본(0.6)이 아닐 때만 저장한다. 없으면 0.6 |

- **정규화의 단일 기준**은 `studio-bg3d-scene-document.ts` 의 `LINE_FIELD_SPECS` 표다. 전체 설정(`output.line`)과 컷별 덮어쓰기(`shots[].output.line`)가 같은 표를 쓰고, 순서는 저장 문서의 키 순서와 같다. 파생 규칙(`resolveStudioBg3dInteriorSuppression`, `studioBg3dLineNeedsDepth`)과 기본 강도 상수는 `studio-bg3d-scene-document-types.ts` 에 있다.
- **편집기**: 패널 → `updateLtLineSettings(patch)` → `{ ...output.line, ...patch }` 를 문서 정규화에 통과 → 삽입 시 `Object.freeze({ ...document.output.line })` 스냅샷 → `renderStudioBg3dLtLayersInWorker`. 깊이 캡처는 `studioBg3dLineNeedsDepth(line)` 일 때 요청한다.
- **멀티패스 내보내기**: `applyStudioBg3dShot`(문서 `output.line` + 컷 덮어쓰기 병합) → `buildStudioBg3dShotArtifacts` → 같은 렌더러. `main-line`/`texture-line` 패스는 렌더 결과의 역할(`role`)별 레이어다. 깊이 캡처 판정은 `studioBg3dShotBatchNeedsDepth(line, passes)`(= 선 설정이 요구하거나 깊이·법선 패스를 내보낼 때)를 배치 계획과 내보내기 실행이 함께 쓴다.
- 두 경로가 같은 설정 객체와 같은 레이어 바이트를 내는 것은 `studio-bg3d-lt-line-settings-flow.test.ts` 가 확인한다.
- **라이브 뷰포트의 "선화 미리보기"는 이 설정을 읽지 않는다.** 흰 재질과 메시 가장자리를 보여 주는 별도 표시다(`StudioBg3dSceneNodes.tsx`). 설정을 실제로 소비하는 편집기 쪽 경로는 "삽입"이다. LT 패널의 "출력 의도 미리보기" 막대는 렌더러가 아니라 CSS 근사이며, 이번에 막대 높이를 `widthPx` 와 같게, 농도를 `strength × min(1, widthPx)` 로 바꿔 3장의 두께·농도 규칙과 맞췄다.
- LT 프리셋은 장면 문서의 엄격 경계(`parseStudioBg3dSceneDocument`)로 검증되므로 새 필드도 같은 규칙을 거친다.

## 3. 연속 선 폭

### 변경 전 (기준 커밋 `37b51837`, 2026-10-16 측정)

슬라이더 값 0.25~8px 전체가 **5단계의 정수 반경** `ceil((w - 1) / 2)` 로 끊겼고, 한 픽셀 선이 아니라 Sobel 반응(경계 양쪽 두 픽셀)을 그대로 팽창해 설정값의 약 2배로 그려졌다. 아래는 같은 합성 계단(41×21)에서 가운데 행의 잉크 합(px)이다.

| 설정 폭 | 변경 전: 휘도 / 깊이 / 알파 윤곽 | 변경 후 (세 경우 모두) |
| --- | --- | --- |
| 0.5 | 2 / 1 / 1 | 0.50 |
| 1 | 2 / 1 / 1 | 1.00 |
| 1.1 | 4 / 3 / 2 | 1.10 |
| 1.5 | 4 / 3 / 2 | 1.50 |
| 2 | 4 / 3 / 2 | 2.00 |
| 3 | 4 / 3 / 2 | 3.00 |
| 3.1 | 6 / 5 / 3 | 3.10 |
| 5 | 6 / 5 / 3 | 5.00 |
| 8 | 10 / 9 / 5 | 8.00 |

(깊이 윤곽은 `depthStrength = 1`, `exteriorOutlineStrength = 0` 로 잰 값이다. 0.25px 는 변경 전 2 / 1 / 1, 변경 후 0.25 다. 변경 후 값의 재현: 시험 `선 폭: 슬라이더 값이 곧 픽셀 두께다`.)

### 방법과 이유

1. **한 픽셀 중심선.** 흐린 휘도의 Sobel 크기에서 기울기 방향(4방향 양자화) 비최대 억제(Canny 의 얇게 만들기)로 중심선 한 픽셀만 남긴다. 규칙은 `크기 ≥ 이전 이웃(왼쪽·위 쪽) 이고 크기 > 다음 이웃(오른쪽·아래 쪽)` 이며, 계단형 경계처럼 동점이면 다음 쪽 픽셀이 가진다. 투명(알파 0) 픽셀은 크기 0 으로 만들어 물체 가장자리 선을 빼앗지 못하게 한다.
2. **거리 기반 서브픽셀 덮임.** 중심선 픽셀에서 거리 `d` 만큼 떨어진 픽셀의 덮임을 `clamp(max(w, 1) / 2 + 0.5 - d, 0, 1)` 로 칠한다. 축 정렬 선에서는 정수 오프셋의 덮임 합이 정확히 `w` 가 된다(예: `w = 1.5` → `1 + 2 × 0.25`). 겹치는 기여는 합이 아니라 **최대값**이라 농도가 넘치지 않는다. 가중치는 0..256 정수 표라 플랫폼과 무관하게 같은 바이트가 나온다.
3. **1px 미만**은 폭 1 모양에 농도를 `w` 배로 줄인다(머리카락 선 표현). `w = 1` 에서 두 식이 이어진다.
4. **8-연결 대각선**은 격자 점까지의 거리만 쓰면 축 정렬보다 얇아 보이므로 대각 이웃 두 픽셀 사이 중점을 가상 표본으로 더한다.
5. **알파 윤곽**은 투명 쪽을 그릴 수 없어 중심으로 칠하면 보이는 두께가 절반이 된다. 그래서 윤곽만 따로 모아 물체 **안쪽으로만**, 칠하기 폭 `max(w, 2w - 1)` 로 칠해 보이는 두께를 `w` 로 맞춘다. 알파 경사의 반응은 **포화시키지 않고 경사에 비례**하게 쓴다(아래 "안티앨리어싱된 알파 윤곽").
6. **재질선** 자체는 `w ≤ 3` 이면 칠하지 않고(예전 규칙과 같다), 그보다 굵은 주선에서는 `w - 2` 로 연속 증가한다. 주선 곁을 비우는 구역은 `min(8, max(3, w + 2))` 폭으로 새 주선 폭에 맞춰 다시 계산하므로, 주선 바로 옆의 재질선 모양은 예전과 다를 수 있다.

**왜 이 방법인가.** (a) 슈퍼샘플링은 `n²` 배의 메모리·시간이 들고 타일 헤일로도 `n` 배가 되어 큰 이미지에 맞지 않는다. (b) 전역 유클리드 거리 변환은 한 픽셀이 읽는 거리에 상한이 없어 타일로 나눈 결과가 전체 프레임과 같다는 약속을 지킬 수 없다. (c) 중심선 + 국소 거리 덮임은 폭이 정해지면 도달 거리가 유한(최대 폭에서 몇 픽셀)하고, 정수 연산이라 결정적이며, 변경 전 파이프라인과 같은 입력·출력 계약(0..255 반응 → 레이어)을 그대로 쓴다.

| 1 | 1.00 | 1.15 | 1.29 | 1.78 | 2.61 / 2.80 (w = 1) |
| 1.5 | 1.50 | 1.61 | 1.72 | 2.12 | — |
| 2 | 2.00 | 2.14 | 2.24 | 2.60 | 5.23 / 5.54 |

160×160 반평면 계단(안티앨리어싱 없음)의 중앙 창에서 잉크 합 ÷ 경계선 길이(px)다. 측정 도구는 이 저장소에 두지 않았고, 같은 입력을 만드는 시험(`비스듬한 경계(축 정렬이 아닌 선)`)이 초과량의 상한을 고정한다: 22.5° 에서 +0.3px, 30° 에서 +0.5px, 45° 에서 +0.9px 이내이며 설정 이상이고 폭에 단조 증가한다.

- 축 정렬(0°/90°)의 이진 알파·휘도·깊이 경계 두께는 설정과 ±0.02px 로 같다. 안티앨리어싱된 알파 윤곽은 아래 소절을 본다.
- 비스듬한 경계의 초과량은 칠하기 단계보다 **중심선 단계**가 크다. 칠하기만 따로(8-연결 Bresenham 선에 적용) 재면 설정 폭 대비 폭 1 이하에서 +16%, 1.5~2.5 에서 +10%, 3 이상에서 +8% 이내이고 −3% 보다 얇아지지 않는다. 반면 4방향 비최대 억제는 30~60° 에서 계단 모양 또는 이중 대각선을 남긴다(능선 픽셀 수 ÷ 경계 길이: 45° 에서 1.37~1.41, 이상값 0.71). 4×4 슈퍼샘플로 안티앨리어싱한 경계는 30°/60° 부근에서 더 굵게 나온다(폭 1 에서 1.66, 폭 2 에서 2.62).
- 이 편차는 변경 전(같은 입력에서 폭 1 은 2.6~2.8px, 폭 2 는 5.2~5.5px)보다 작지만 0 이 아니다.
- 기울기 방향을 보간하는 비최대 억제를 시험해 보았으나(안티앨리어싱 경계의 능선 밀도 기준) 30° 는 나아지고 10°~22.5° 는 나빠져 채택하지 않았다. 후속 과제는 9장.

### 안티앨리어싱된 알파 윤곽

실제 캡처는 `render.antialias` 기본값이 `true` 라서 물체 가장자리의 알파가 계단이 아니라 1~2픽셀 경사다. 알파 경사의 반응을 포화시키면 경사가 넓을수록 선이 굵어지므로(알파 경사 1px, 경계 알파 0.5 에서 폭 1 이 1.50px) 반응을 경사에 **비례**하게 쓴다. 경사 반응은 알파의 중앙 차분이고, (반응 × 불투명도)를 가장자리 픽셀에 걸쳐 더하면 경사 모양과 무관하게 정확히 1px 이 된다(차분의 합이 상쇄된다). 합성 알파 경사에서 잰 가운데 행의 잉크 합(px)이다.

| 가장자리 알파 | 폭 1: 변경 전 → 지금 | 폭 3: 변경 전 → 지금 | 폭 5: 변경 전 → 지금 |
| --- | --- | --- | --- |
| 계단(1.0) | 1.00 → 1.00 | 2.00 → 3.00 | 3.00 → 5.00 |
| 1px 경사, 경계 알파 0.8 | 1.79 → 1.00 | 2.79 → 3.00 | 3.79 → 5.00 |
| 1px 경사, 경계 알파 0.5 | 1.50 → 1.00 | 2.50 → 3.00 | 3.50 → 5.00 |
| 1px 경사, 경계 알파 0.2 | 1.20 → 1.00 | 2.20 → 3.00 | 3.20 → 5.00 |
| 2px 경사(0.3 / 0.7) | 2.00 → 1.00 | 3.00 → 2.40 | 4.00 → 3.81 |
| 3px 경사(0.25 / 0.5 / 0.75) | 2.50 → 1.00 | 3.50 → 2.00 | 4.50 → 3.00 |

- 1픽셀 경사에서는 정수 폭(1·2·3·5)이 정확하고, 분수 폭(1.5·2.5)은 설정보다 최대 0.25px 얇다.
- 4×4 슈퍼샘플로 안티앨리어싱한 **사선 실루엣**(0~90° 8방향)은 폭 1 이 1.00~1.05px, 폭 2 가 1.90~2.00px, 폭 3 이 2.90~3.03px 였다(변경 전은 폭 1 이 1.41~1.64px, 폭 2·3 이 2.50~3.01px). 휘도 경계와 달리 알파 윤곽은 사선에서 부풀지 않는다.
- **한계**: 경사가 2~3픽셀로 넓으면(흐린 알파) 폭 1 은 정확하지만 폭이 클수록 설정보다 얇아진다(3px 경사에서 폭 3 이 2.00px, 폭 5 가 3.00px). 겹치는 칠하기를 최대값으로 합쳐 부분 반응들의 합이 줄기 때문이다. 알파 경사에 맞춰 폭을 보정하는 방식은 채택하지 않았다: 칠하기가 픽셀마다 다른 폭을 쓰게 되어 도달 거리 예산(아래)이 흔들리고, 1~2픽셀 경사인 일반 캡처에서는 이미 ±0.1px 안이기 때문이다.
- 시험: 품질 시험의 `안티앨리어싱된 알파 윤곽` 과 `비스듬한 경계` 구역.

### 타일 경계 예산

큰 이미지는 타일로 나눠 처리하며 타일은 전체 프레임과 ±1 바이트 안에서 같아야 한다(헤일로 12px). 새 단계가 한 출력 픽셀에 영향을 주는 입력 거리를 항목별로 계산해 `STUDIO_BG3D_LT_LINE_RECEPTIVE_FIELD_PX` 에 두었다.

| 항목 | 구성 | 도달 거리(px) |
| --- | --- | --- |
| 주선 | 흐림 2 + Sobel 1 + 비최대 억제 1 + 가려진 선 이동 1 + 폭 8 칠하기 4 | 9 |
| 알파 윤곽 | 알파 Sobel 1 + 안쪽 칠하기(폭 15) 7 | 8 |
| 재질선 | 주선 분리 구역 9 + 재질선 칠하기(폭 6) 3 | 12 |
| 내부선 억제 근접도 | 윤곽 근거 1 + 밴드 3 (주선 계산과 병렬) | 4 |
| **최악** | | **12 (= 헤일로 12, 여유 0)** |

시험 `타일 경계 예산` 이 `12 ≤ 헤일로` 를 고정하고, `studio-bg3d-tiled-artifacts.test.ts` 의 "모든 기능을 켠" 두 경우가 타일/전체 프레임 동일성을 확인한다. 이 12 는 항목별 최악 합이라 실제 장면에서 필요한 거리는 대개 더 짧다: 일회성 비교 실험(저장소에 두지 않음, 139×107 합성 장면에 모든 기능을 켜고 47×31 타일로 나눔)에서 헤일로 7 까지는 전체 프레임과 차이가 0 이었고 6 에서 최대 22, 4 에서 최대 61 바이트 어긋났다. 즉 예산을 줄이면 타일 이음매가 실제로 드러난다. **계산상 여유가 0 이므로 선 단계를 하나 더하려면 먼저 이 값을 다시 계산하고 헤일로를 늘려야 한다.**

## 4. 가려진 선 제거 (`hiddenLineRemoval`)

**변경 전**: 값 검증(`assertBoolean`)만 있고 렌더에서 읽는 곳이 없어 켜도 꺼도 같았다.

**정의**: 캡처된 이미지에는 보이는 표면만 있어 "가려진 형상"을 그릴 수 없다. 그래서 의미를 이미지 기준으로 좁혔다. **깊이 캡처가 있을 때**, 앞 물체가 뒤 면을 가리는 경계(깊이 불연속)에서 *먼 쪽(가려지는 면)*에 앉은 휘도 선을 앞 물체 쪽 가장 가까운 이웃으로 옮겨 깊이 윤곽과 **한 줄**로 합친다. 옮기는 양은 가려진 비율(깊이 에지 추출기의 `occluded` 채널)만큼이고 먼 쪽 픽셀에는 보이는 비율만 남는다. 재질선(`texture-line`)도 먼 쪽 반점을 같은 비율로 줄인다. 옮기는 시점은 비최대 억제가 **끝난 뒤**다(그 전에 먼 쪽을 0 으로 만들면 옆 픽셀이 새 최대가 되어 두 칸 떨어진 가짜 선이 생긴다).

**고정한 픽셀 수치** (12×7, 5|6 열 경계에서 휘도와 깊이가 함께 갈리고 왼쪽이 앞 물체, `depthEnabled`):

| 행 가운데 4~7 열의 알파 | 값 |
| --- | --- |
| 가려진 선 제거 끔 | `[0, 128, 255, 0]` — 앞쪽 깊이 윤곽(128)과 먼 쪽 능선(255)이 이웃한 두 줄 |
| 가려진 선 제거 켬 | `[0, 255, 0, 0]` — 한 줄 |
| 앞 물체가 반대쪽(오른쪽)일 때 켬/끔 | 같음 `[0, 0, 255, 0]` — 이미 앞 물체 쪽에 선이 있다 |

**효과가 없는 경우**(시험으로 고정): 깊이 입력이 없을 때, 선 설정이 깊이를 요구하지 않을 때. 후자는 깊이선 검출도 내부선 억제도 꺼져 있는 경우로, 깊이 패스를 함께 내보내려고 깊이가 들어와도 **주선은 바뀌지 않는다**(깊이 패스 선택 여부에 따라 주선이 달라지면 안 되기 때문이다). UI 는 이 조건을 숨기지 않는다: 깊이를 캡처하지 않는 상태의 "가려진 선 제거" 아래에 "지금은 깊이를 캡처하지 않아 효과가 없어요" 안내가 나온다.

## 5. 내부선 억제

### 정의

- **윤곽선** = (1) *알파 윤곽*: 불투명 픽셀이 투명(알파 0) 픽셀과 맞닿는 경계, (2) *깊이 윤곽*: 앞 물체가 뒤 면·배경을 가리는 깊이 불연속(깊이 캡처가 있을 때).
- **내부선** = 그 밖의 모든 선: 명암·재질 휘도 경계, 법선(모서리) 선, 깊이 굴곡, 그리고 재질선 레이어 전체.
- 강도 `s`(0..1, 기본 0.6). 내부선의 농도에 `1 - s × (1 - p)` 를 곱한다. `p` 는 그 픽셀의 **윤곽 근접도**(0..1)다. 윤곽선 자체에는 곱하지 않는다.
- **근접도 `p`**: 윤곽 근거를 3픽셀 밴드로 번지게 한 값이다. 가로·세로 각각 거리 `k = 0, 1, 2, 3` 의 가중치가 `256 / 192 / 128 / 64`(=`256 × (1 - k / 4)`)이고 두 방향의 곱을 쓰며(정수 연산) 겹치면 최대값이다. 윤곽 위는 `p = 1`, 밴드 밖은 `p = 0`.
- 결과: 윤곽선은 그대로, 윤곽에서 3px 안에 붙은 내부선(접촉선 후보)은 거리에 따라 덜 줄고, 3px 넘게 떨어진 내부선은 `(1 - s)` 배가 된다. 재질선 레이어는 정의상 내부선이라 근접도 예외 없이 `(1 - s)` 배다.
- 꺼짐, 필드 없음, `s = 0` 은 모두 예전과 **바이트 단위로 같은** 출력이다(시험).

| 선 종류 | 분류 | 억제 |
| --- | --- | --- |
| 알파 윤곽 | 윤곽 | 줄이지 않음 |
| 깊이 윤곽 | 윤곽 | 줄이지 않음 |
| 윤곽에서 3px 안의 휘도·법선·깊이 굴곡 선 | 내부 | `1 - s × (1 - p)` (가까울수록 덜) |
| 윤곽에서 3px 넘는 휘도·법선·깊이 굴곡 선 | 내부 | `× (1 - s)` |
| 재질선 레이어 | 내부 | `× (1 - s)` 전부 |

### 깊이 캡처

억제가 켜져 있고 `s > 0` 이면 깊이도 함께 캡처한다(깊이 윤곽이 윤곽 근거라서). 편집기 삽입은 `studioBg3dLineNeedsDepth(line)`, 배치 계획·내보내기 실행은 `studioBg3dShotBatchNeedsDepth(line, passes)` 로 같은 판정을 쓴다. 켜면 가려진 선 제거도 함께 작동한다.

### 고정한 픽셀 수치 (30×14 합성, 투명 배경 위 불투명 사각형, 휘도 경계는 안쪽)

| 상황 | 억제 끔 | `s = 0.6` | `s = 1` |
| --- | --- | --- | --- |
| 알파 윤곽(왼쪽·오른쪽) | 255 | 255 | 255 |
| 윤곽에서 먼 안쪽 휘도 선 | 255 | 102 (= 255 × 0.4) | 0 |
| 윤곽에서 1px 떨어진 안쪽 선 | 255 | 217 | 191 |
| 2px | 255 | 179 | 128 |
| 3px | 255 | 140 | 64 |
| 4px 이상(밴드 밖) | 255 | 102 | 0 |

기타: 불투명 장면에서 깊이 윤곽이 윤곽 근거가 된다(깊이 변화 없는 안쪽 휘도선은 사라지고 깊이 경계의 선은 남는다). 재질선 레이어는 `(1 - s)` 배(±1 반올림)이며 `s = 1` 이면 레이어가 만들어지지 않는다.

### 한계 (정직하게)

- **선 렌더러의 입력에 객체 ID 가 없다.** (매직 선택용 객체 ID 캡처 `captureStudioBg3dMagicObjectIds` 는 있지만 LT 렌더러에 연결돼 있지 않다.) 그래서 접촉선(물체가 바닥·다른 물체에 닿는 선)은 알파·깊이 불연속으로만 알아볼 수 있고, 두 물체가 맞닿아 깊이가 이어지는 접촉선(상자가 바닥에 닿는 선 등)은 윤곽 근거가 되지 못해 내부선으로 취급되어 **억제된다.** 독립 검토가 상자-바닥 접촉선을 재현했다: 억제 강도 0.6 에서 알파 241 → 104, 1.0 에서 12 로 줄고 실루엣은 255 로 남는다. "윤곽에 붙은 선을 남긴다"는 윤곽에서 3px 안(알파·깊이 윤곽 기준)의 선에만 해당하며, 편집기 안내 문구도 그렇게 적었다. "외곽·접촉선 위주로 남기기"는 이 한계 안에서만 충족한다.
- **윤곽 근거가 전혀 없으면**(불투명하고 깊이가 없거나 깊이 윤곽이 없음) 구분할 방법이 없어 모든 내부선이 균일하게 `(1 - s)` 배가 된다. `s = 1` 이면 주선 레이어도 만들어지지 않는다.
- 이미지 맨 위·아래·좌우 가장자리 행/열은 깊이 이웃이 없어 가려진 면을 알 수 없다(그 행에서 선이 한 칸 어긋날 수 있다).
- **프리셋을 적용하면 내부선 억제가 초기화된다.** 프리셋 적용은 `output.line` 전체를 프리셋의 선 설정으로 바꾸는데 내장 프리셋에는 억제 필드가 없어서, 억제를 켜 둔 문서에 내장 프리셋을 적용하면 억제가 꺼진다(시험이 고정한다). 억제를 함께 담은 사용자 프리셋은 저장·적용할 수 있다.
- 억제를 끄면 강도도 저장하지 않으므로 다시 켜면 강도는 기본 60%에서 시작한다.

## 6. 편집기 UI

LT 패널 "선화" 탭의 "정밀 선 검출" 접이식 구역은 `StudioBg3dLtLineDetailControls.tsx` 로 옮겼다(`StudioBg3dLtPanel.tsx` 는 886줄에서 782줄로 줄었고 기존 컨트롤의 id·라벨·동작은 그대로다). 추가된 것:

- "내부선 억제" 스위치 — 설명은 한계를 숨기지 않는다: 안쪽 명암·재질·모서리 선을 줄이고 물체와 배경의 경계(윤곽)는 남기지만, 바닥에 닿는 선처럼 깊이가 이어지는 곳은 안쪽 선으로 보고 줄이며, 켜면 깊이도 함께 캡처한다. 켜면 "억제 강도"(0~100%) 슬라이더가 나온다.
- 접힌 "정밀 선 검출" 요약에 "내부선 억제"를 적어 접힌 상태에서도 찾을 수 있고, 켜 두었으면 "내부선 억제 켬" 으로 상태가 보인다.
- "가려진 선 제거" 아래의 안내 문구가 깊이 캡처 여부에 따라 바뀐다(효과 없음 / 이중선을 한 줄로 합침).
- 화면 문구는 이 패널의 이웃 컨트롤처럼 한국어 고정 문구이며 번역 사전을 거치지 않는다. 사용자 입력은 문구에 끼워 넣지 않는다.

## 7. 하위 호환, 롤백, 기본·프리셋 폭 재보정

### 선택 필드 규약

- 새 필드는 **억제가 켜져 있고 기본이 아닐 때만** 저장한다. 꺼짐·없음은 쓰지 않고, 켜 둔 채 강도가 기본(0.6)이면 스위치만 쓴다. 억제를 켠 적 없는 문서와 켰다가 끈 문서는 직렬화 결과가 키가 없던 문서와 **바이트 단위로 같다**(시험: `rollback compatibility`). 컷별 덮어쓰기(`shots[].output.line`)에서는 `false` 도 문서 전체의 `true` 를 덮는 값이라 입력에 있는 키를 그대로 남긴다.
- 엄격 저장 경계(`parseStudioBg3dSceneDocument`)는 다른 작성기가 쓴 "꺼짐·기본" 표기(`interiorSuppressionEnabled: false`, 의미 없는 강도, 기본 강도)를 없는 것과 같게 받아들이고 정규화해서 키를 없앤다. 형식이 틀린 값(문자열, 범위 밖 숫자, `null`)은 그대로 거부한다.
- Worker 프로토콜(v2, 정확 키 검사)은 선택 키 2개를 허용하도록 넓혔고 버전은 올리지 않았다. 키가 없는 요청은 그대로 유효하다.
- 정규화는 기준 커밋의 구현과 대조했다: 무작위 입력 200,000건(범위 밖 숫자·잘못된 형식·누락 키 포함, 기존 16개 필드만)을 기준 커밋의 `normalizeStudioBg3dSceneDocument` 와 커밋한 최종 트리의 구현에 넣어 전체 설정과 컷 덮어쓰기를 키 순서까지 포함한 JSON 으로 비교했고 불일치는 0건이었다(2026-10-16). 폭이 없거나 틀린 입력의 대체값만 1 에서 1.75 로 의도적으로 달라져, 기준 쪽 결과의 그 값을 바꿔 비교했다. 이 비교는 일회성 점검이며 저장소에 도구로 두지 않았다. 키 순서는 시험의 **골든 JSON** 이 고정한다(`jsonStructuresEqual` 은 키 순서를 무시하므로 왕복 비교만으로는 순서를 지킬 수 없다).

### 롤백 주의

이 기능을 되돌려 **이전 코드**로 돌아가면, 억제를 한 번도 켠 적 없는(또는 끈) 문서는 그대로 읽힌다. 반대로 **억제를 켠 문서·프리셋은 이전 코드가 읽지 못한다.** 이전 코드는 모르는 키를 "손상"으로 본다.

1. 엄격 저장 왕복: `parseStudioBg3dSceneDocument` / `serializeStudioBg3dSceneDocument` 가 정규화로 달라지는(모르는 키가 있는) 문서를 거부한다.
2. 프로젝트 가져오기: `studio-project-file.ts` 의 `canonicalizeBg3dSceneElement` 가 "3D 배경 장면 데이터가 손상되었거나 지원하지 않는 버전입니다." 예외를 던져 그 장면이 든 프로젝트를 불러오지 못한다.
3. 장면 재편집: `studio-bg3d-editor-derivations.ts` 의 `canonicalSceneDocument` 가 null 을 돌려줘 편집 내용이 반영되지 않는다.
4. 사용자 LT 프리셋: `studio-mannequin-bg3d-preset-sqlite-repository.ts` 의 `parseCanonicalStudioBg3dLtPresetSqlitePayload` 가 알 수 없는 필드가 있는 행을 오류로 거부한다.

따라서 롤백 전에 억제를 켠 문서와 사용자 프리셋을 먼저 끈 뒤 다시 저장해야 한다. 억제를 쓰는 사용자가 있는 동안에는 롤백이 아니라 앞으로 고치는 쪽을 권한다.

### 기본·프리셋 폭 재보정

선 폭이 픽셀 두께가 되면서 같은 폭 값이 더 얇은 선을 낸다(변경 전 기본 폭 1px 는 휘도 경계를 2px 로 그렸다). 이전 출력의 인상을 유지하려고 **새 문서의 기본 폭과 내장 프리셋 폭**을 새 렌더러 기준으로 다시 맞췄다. 방법:

1. 장면: 상자·구·원기둥·바닥·벽을 광선 추적한 절차 장면(2×2 슈퍼샘플로 알파 경사를 만든다). 크기 3종(480×270, 960×540, 1138×640) × {불투명, 투명} × {질감 있음, 평면} = 12장. 도구는 저장소에 두지 않았다(기준 커밋의 렌더러 사본이 필요하다).
2. 구 렌더러: 기준 커밋의 `studio-bg3d-lt-render.ts` 사본. 구성(문서 기본 + 내장 프리셋 5종)의 전체 선·톤 설정과, 설정이 요구하면 깊이·법선을 같은 입력으로 넣는다.
3. 지표: 주선 레이어의 알파 합 ÷ 255(= 잉크 px).
4. 장면마다 새 렌더러의 폭을 이분 탐색해 신 잉크 = 구 잉크가 되는 폭 `w*` 를 구하고, 12개 `w*` 의 **기하평균을 0.05 단위(슬라이더 단계)로 반올림**해 새 폭으로 정했다.

| 구성 | 구 폭 → 신 폭 | 구 두께 휘도 / 깊이 / 알파(px) | 구 잉크(px, 480×270 불투명 / 투명) | 신/구 잉크비: 불투명(질감) | 불투명(평면) | 투명 |
| --- | --- | --- | --- | --- | --- | --- |
| 문서 기본 | 1 → **1.75** | 2 / 1 / 1 | 782 / 1381 | 0.94~1.08 | 0.78~0.88 | 1.08~1.17 |
| 배경 콘티 | 2.4 → **3.1** | 4 / 3 / 2 | 1336 / 1960 | 0.83~0.89 | 0.81~0.83 | 1.22~1.27 |
| 깔끔한 건축 선화 | 0.8 → **2.1** | 2 / 1 / 1 | 1432 / 2218 | 0.86~1.00 | 0.72~0.87 | 1.08~1.17 |
| 흑백 만화 | 1.1 → **3.25** | 4 / 3 / 2 | 6458 / 3379 | 0.84~0.88 | 0.80~0.85 | 1.16~1.21 |
| 거친 펜 | 1.8 → **3.05** | 4 / 3 / 2 | 5663 / 3023 | 0.85~0.89 | 0.81~0.83 | 1.21~1.25 |
| 컬러 웹툰 배경 | 0.75 → **1.75** | 2 / 1 / 1 | 732 / 877 | 0.98~1.04 | 0.78~0.86 | 1.04~1.15 |

(구 두께는 41×21 합성 계단에서 잰 값이다. 신/구 잉크비의 범위는 각 군의 장면 3~6장에서 최솟값~최댓값이다. 폭을 바꾸지 않고(문서 기본 1, 프리셋 원래 폭) 비교한 480×270·960×540 질감 장면 4장에서는 신/구 잉크비가 0.31~0.97 로 모든 구성에서 선이 얇아졌다.)

**목표(불투명·투명 모두 0.9~1.1)는 일부만 달성했다.** 주선 잉크비는 전체 0.72~1.27, 불투명(질감) 0.83~1.08, 불투명(평면) 0.72~0.88, 투명 1.04~1.27 이다. 이유는 폭 하나로 맞출 수 없는 구조 차이다: 옛 렌더러의 두께는 선 종류마다 달라서(폭 1 이하는 휘도 2px·깊이 1px·실루엣 1px, 폭 1.1~3 은 4px·3px·2px) 휘도 선이 많은 불투명 장면과 실루엣이 많은 투명 장면의 등잉크 폭이 다르다. 문서 기본의 `w*` 는 불투명(질감) 1.64~1.88, 불투명(평면) 2.00~2.23, 투명 1.51~1.63 이었다. 12장의 기하평균을 쓴 것은 어느 한 군에 치우치지 않기 위한 선택이다. 문서 기본(1.75) 기준으로 불투명(평면) 장면을 맞추려면 폭을 약 15~28% 키워야 하고, 투명 장면을 맞추려면 약 7~14% 줄여야 한다. 이 측정은 절차 장면 한 계열이라 실제 모델 장면에서는 달라질 수 있다. 표의 구 잉크와 신/구 잉크비, 위의 `w*` 와 반올림 결과는 커밋한 최종 트리에서 다시 쟀고(2026-10-16) 같은 값이 나왔다.

질감선 잉크비는 질감선이 켜진 구성에서 0.69~1.10 이다. 주선이 굵어지면 주선 곁에서 질감선을 비우는 구역(폭 + 2px, 최대 8px)도 넓어져 질감선이 조금 줄어든다.

**한계(이미 저장된 옛 문서).** 폭 모델을 구분하는 표지(문서 버전 등)를 만들지 않았다. 저장된 폭 값은 그대로 두므로, 옛 코드에서 저장한 문서는 같은 폭 값으로 **새 렌더러에서 더 얇게** 그려진다(예: 폭 1 로 저장된 문서의 주선 잉크는 위 표 기준 변경 전의 0.6~0.7배). 내장 프리셋을 다시 적용하면 새 폭이 들어오고, 옛 폭으로 프리셋을 적용했던 문서는 더 이상 그 프리셋과 일치하지 않아(일치 판정은 선·톤 설정 전체의 직렬화 비교다) "변환 프리셋" 선택 상자가 "사용자 설정"으로 표시된다. 폭이 없는 입력의 대체값(`normalizeStudioBg3dLineOutputSettings`)도 새 기본 폭 1.75 를 쓴다. 이 숫자들은 시험(`calibrated default and preset stroke widths`)이 고정하며, 바꾸려면 위 측정부터 다시 해야 한다.

### 그 밖의 시각 변화

`hiddenLineRemoval` 은 기본값이 `true` 이고 프리셋 5개 중 4개가 깊이선 검출을 켜 두었으므로, 깊이선을 쓰는 문서는 이제 먼 쪽 이중선이 한 줄로 합쳐진다. 깊이선 검출을 끈 문서(기본값)는 영향이 없다.

## 8. 성능

`renderStudioBg3dLtLayers` 를 직접 호출해 잰 시간이다(시험에서 시간은 단언하지 않는다). Node 24, 단일 스레드, 4코어 공유 VM이라 ±10% 안팎의 흔들림을 감안한다. "기존"은 기준 커밋의 렌더러를 그대로 복사해 같은 입력으로 잰 값이다. 2026-10-16 에 두 번 쟀다. 처음은 부하가 낮을 때(load average 0.3~0.5), 두 번째는 커밋한 최종 트리에서 다른 작업이 함께 돌 때(load average 3~5)다. 아래 표는 두 번째 값이고, 처음 잰 비율을 옆에 적었다.

### 고밀도 잡음(최악에 가까운 입력, 3840×2160, 모든 픽셀이 무작위 휘도)

선 후보 픽셀이 화면 곳곳에 있어 칠하기 비용이 가장 커지는 입력이다. 이 입력에서는 **신규가 기존보다 느리다**. 칠하기 안쪽 반복문을 선형 오프셋과 `Uint8Array` 로 바꾼 뒤(결과 바이트 동일: 무작위 6,000건 비교) 네 번 잰 범위다(처음 두 번과 최종 트리에서 다시 잰 두 번).

| 폭 | 기존(ms) | 신규(ms) | 신규/기존 | 최적화 전 신규/기존(한 번 잼) |
| --- | --- | --- | --- | --- |
| 1 | 1637~1722 | 1858~1892 | 1.08~1.14 | 1.20 |
| 2 | 1746~1840 | 2085~2156 | 1.17~1.22 | 1.31 |
| 8 | 2019~2194 | 3138~3464 | 1.50~1.68 | 2.07 |

폭이 클수록 칠하기 커널이 커져(폭 8 에서 약 70개 오프셋 × 선 픽셀 수 × 칠하기 호출 3~4회) 격차가 벌어진다. 더 줄이려면 칠하기를 최대값 필터 분해 같은 다른 알고리즘으로 바꿔야 하는데 도달 거리 예산과 시험이 모두 흔들려 이번에는 하지 않았다. 실제 장면의 선 후보 비율은 잡음보다 훨씬 낮으므로 "0.68~0.99배" 는 **일반 장면에 한한 수치**다.

### 메모리와 깊이 캡처 비용

- 렌더 한 번의 최대 상주 메모리(maxRSS): 투명 배경 타원 장면(폭 2, 재질선 켬)에서 기존 +116MB, 신규 +129MB(기본), 신규 +161~163MB(억제 + 깊이). 고밀도 잡음 4K 에서는 절대 최대가 기존 291~306MB, 신규 307MB, 신규(억제 + 깊이) 323~326MB 였다(각각 두 번 잼). 능선 장(Float32)과 억제용 바이트 배열 같은 새 작업 배열 때문으로 보이나 항목별로 나눠 재지는 않았다.
- **내부선 억제를 켜면 삽입이 깊이를 함께 캡처한다.** 깊이는 픽셀당 4바이트(Float32)라 3840×2160 에서 약 33MB(31.6MiB)를 Worker 로 전송하고, 깊이 캡처를 위한 렌더 패스가 한 번 더 든다. 깊이선 검출을 이미 쓰는 문서에는 추가 비용이 없다. 이 캡처 비용(시간)은 측정하지 않았다.

## 9. 한계와 후속 과제

- **비스듬한 휘도·깊이 경계의 두께 편차**(3장 표): 중심선을 8-연결로 얇게 만드는 후처리(세선화)로 줄일 수 있으나, 현재 타일 헤일로(12px)에 여유가 없어 헤일로를 함께 늘려야 한다. target.
- **객체 ID** 를 선 렌더러 입력으로 받아야 접촉선을 가려낼 수 있다(5장). 객체 ID 캡처 자체는 매직 선택에 있다. target.
- **넓은 알파 경사**(2~3px, 흐린 알파)에서는 폭이 클수록 선이 설정보다 얇아진다(3장).
- **기본·프리셋 폭**은 장면 종류별 편차가 남는다(주선 잉크비 0.72~1.27, 7장). 이미 저장된 옛 문서는 새 렌더러에서 더 얇게 그려진다(폭 모델 표지 없음).
- **고밀도 잡음**에서는 신규가 기존보다 느리다(최대 1.7배, 8장). 칠하기 알고리즘을 바꿔야 줄일 수 있다.
- 깊이가 없으면 가려진 선 제거는 아무 일도 하지 않는다(설계상 정직한 동작). 깊이를 선 설정과 무관하게 항상 캡처하게 할지는 캡처 비용 문제라 정하지 않았다.
- 억제 강도 100% 는 질감선 레이어를 만들지 않는다. 제작 패스 사전 점검(`studio-bg3d-production-pass-readiness.ts`)은 이를 알고 질감선 패스에 미리 경고한다. 주선은 윤곽 근거가 없을 때만 비므로 사전 점검이 알 수 없다.
- 실제 브라우저·WebGL 장면의 눈 비교, 모바일 기기 확인은 하지 않았다.
- 라이브 뷰포트에 이 설정을 반영하는 선화 미리보기는 하지 않았다. 등급 판(`studio-bg3d-grade-plates.ts`, 48×27 대용 판)은 `widthPx` 를 자체 정수 규칙으로 반올림해 읽는다. 렌더러와 이어져 있지 않아 바꾸지 않았고, 기본 폭이 1.75 가 되면서 그 판의 선은 반경이 0 에서 1 로 늘어 1px 에서 3px 로 굵어진다.

## 10. 연결하지 않은 모듈: `scene-3d/studio-3d-line-art-extractor.ts`

연결하지 않았다. 이 모듈(787줄)은 `studio-3d-dcc-suite.ts` 배럴, 자기 시험, `studio-3d-ui-metadata.test.ts`, 벤치마크 보고서에서만 참조된다(배럴 자체가 `check-unconnected-code` 의 orphan-module 로 기준 커밋부터 지적돼 있다). 이유:

1. 출력 계약이 다르다. 이진 에지 마스크와 선택적 SVG 스트로크를 한 번에 돌려주고 정수 두께(1~8)와 자체 색을 갖는 반면, LT 파이프라인은 `main-line`/`texture-line` 래스터 레이어를 Worker 프로토콜 v2, 타일 헤일로(±1 바이트 동일성), 장면 문서 설정과 함께 쓴다. 끼워 넣으려면 설정 모델·저장·UI·프리셋·프로토콜을 새로 만들어야 하고, 이번 과제(S7)의 범위를 넘는다.
2. 이 모듈의 선 두께는 연속 폭 요구를 충족하지 않는다(정수 1~8).
3. 모듈의 스크린톤 합성은 LT 톤 단계와 겹치고, 787줄을 정적 import 그래프에 올리면 번들 래칫을 건드린다.
4. 필요한 기능(Canny 식 얇게 만들기, 깊이·법선 불연속)은 LT 파이프라인에 시험으로 고정해 이미 구현했다. 이 모듈의 코드는 재사용하지 않았고 품질 평가도 하지 않았다.

`node scripts/check-unconnected-code.mjs --json` 결과는 변경 전과 변경 후 모두 859건이며 새 지적은 0건이다(기준선 파일이 비어 있어 `--check` 는 변경 전부터 실패한다). 새 모듈은 모두 연결된 코드가 import 한다.
