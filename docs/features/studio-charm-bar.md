# 원클릭 참(Charm) 스탬프 바

작성 기준일: 2026-10-16 · 대상 화면: Studio 편집기 작업공간(`/studio`)

이 문서는 자주 쓰는 반복 요소(집중선·땀방울·소품 등)를 한 번 누르거나 끌어다 놓아 캔버스에 붙이는 **참 바**의 **현재 구현(current)** 과 **아직 없는 것(target)** 을 나눠 적는다. 구현되지 않은 것을 현재 기능처럼 쓰지 않는다.

## 1. 상태 요약

| 영역 | 상태 | 근거 |
| --- | --- | --- |
| 참 바 본체(아이콘 칩·누르기·키보드·끌어다 놓기) | current | `apps/web/src/domains/creator/charm/StudioCharmBar.tsx`, `StudioCharmChip.tsx` |
| 도킹(붙임·자유 배치·가장자리 도킹) | current, 1024px 이상 | `StudioCharmBarSlot.tsx` 가 기존 `StudioWorkspaceRegion` 을 그대로 쓴다 |
| 켜기·끄기 | current | 템플릿·에셋 메뉴의 "요소"·"효과·스티커" 구역 머리 `StudioCharmBarToggleButton` |
| 고정·해제, 순서 편집 | current | 참 고르기(`StudioCharmPicker.tsx`), 순서 편집 모드, 요소 상세의 "참 바에 고정"(`StudioCharmPinAction`) |
| 로컬 영속 | current | 기존 UI 환경설정 저장소(SQLite/OPFS)의 `charm-bar` 키 |
| 기본 스타터 팩 | current, 12개 | `studio-charm-starter-pack.ts` |

| 실제 브라우저·모바일 기기 화면 검증 | 아직 안 함 | 별도 UI/UX 단계에서 수행한다 → 9장 |
| 메뉴바·명령 팔레트·전역 단축키로 켜기 | target | 지금은 위의 메뉴 토글뿐이다 |
| 효과음·내장 일러스트 칩 끌어다 놓기 | target | 캔버스 드롭에 해당 계약이 없다 → 3장 |

새 서버 API, 새 DB 마이그레이션, 새 런타임 의존성, 새 소재 포맷, 새 에셋은 없다. 참은 기존 카탈로그 항목을 가리키는 참조(ID)일 뿐이고, 붙이기는 편집기가 이미 가진 삽입 명령을 그대로 부른다.

## 2. 사용자 흐름 (current)

1. **켜기**: 템플릿·에셋 메뉴에서 "요소" 또는 "효과·스티커" 구역을 열고 맨 위의 `참 바` 스위치를 켠다(스위치에 포인터를 올리거나 포커스·터치하면 지연 로드하는 본체와 카탈로그 데이터를 미리 불러온다). 바는 도구 레일 옆에 붙어 나타난다. 처음 켜는 빈 바에는 기본 참 12개가 한 번 담기고 "기본 참 12개를 담았어요" 안내가 뜬다. 필요 없는 참은 편집에서 뺄 수 있고, 한 번이라도 목록을 고치면 다시 자동으로 담지 않는다.
2. **붙이기**: 칩을 누르거나(Enter·Space) 캔버스로 끌어다 놓는다. 위치 규칙은 3장이다.
3. **고르기**: 바의 `+`(참 고르기)에서 검색하고 분류(효과·선, 스티커, 소품, 이모지, 효과음, 도형·장식, 일러스트, 내 소재, 말풍선, 3D)로 좁혀 고정·해제한다. "즐겨찾기" 분류는 기존 즐겨찾기(내장 일러스트·내 소재의 별, 요소 카탈로그의 별)를 읽기만 하고 바꾸지 않는다.
4. **요소 상세에서 고정**: 요소 패널의 상세 미리보기에 "참 바에 고정" 토글이 있다. 고정하면 바가 함께 켜진다.
5. **순서·삭제 편집**: `⋯` 메뉴의 "순서·삭제 편집"에서 칩을 고르고 앞으로·뒤로·빼기를 누른다. 키보드로는 Alt+방향키(순서), Delete(빼기)이다.
6. **옮기기·닫기**: 작업 배치 편집에서 자유 배치로 떼거나 왼쪽·오른쪽·위·아래 가장자리에 붙일 수 있다(1024px 이상). `⋯` 메뉴의 "참 바 닫기"나 같은 스위치로 끈다. 켜 둔 상태·목록·순서는 저장된다.

화면이 가려지는 상태(캔버스 전용 모드, 모바일 몰입 모드, 프레젠테이션으로 패널을 숨긴 상태)에서는 바를 그리지 않고, 풀리면 켜 둔 상태 그대로 돌아온다.

## 3. 붙이기 규칙 (current)

### 위치

| 상황 | 놓이는 곳 |
| --- | --- |
| 컷(프레임)을 선택 | 그 컷의 중앙, 컷 안에 맞춘다 |
| 프레임이 아닌 요소를 선택 | 그 요소의 중앙(문서 안으로 맞춘다) |
| 선택 없음 | 지금 보이는 화면의 중앙 |
| 보이는 화면도 알 수 없음 | 문서 중앙 |

같은 대상에 5초 안에 이어 붙이면 계단식으로 조금씩 비껴 놓여 완전히 겹치지 않는다(호스트의 `nextAssetInsertionPlacement` 와 같은 규칙, `studio-charm-cascade.ts`).

격자 스냅이 켜져 있으면 객체를 끌 때와 같은 자석 규칙(`snapStudioObjectDragPosition`, 허용 거리는 화면 px 기준)으로 놓이는 요소의 왼쪽 위 모서리를 격자에 맞춘다. 말풍선은 변종마다 호스트가 놓는 실제 크기(`studioCharmBubbleFootprint`)로 맞추며, 이 크기표가 호스트와 어긋나면 `studio-charm-bar-host-contract.test.ts` 가 실패한다.

### 종류별 동작

| 종류(`kind`) | 원본 | 부르는 호스트 명령 | 위치·스냅 | 끌어다 놓기 |
| --- | --- | --- | --- | --- |
| `element` | 요소 카탈로그 | `addRenderedImage` | 계획된 위치·스냅 | `application/json-asset` |
| `fx` | 효과 오버레이, 만화·동물·소품 스티커 | `addRenderedImage` | 계획된 위치·스냅 | `application/json-asset` |
| `library` | 내 소재 라이브러리 | `addRenderedImage` | 계획된 위치·스냅 | `application/json-asset` |
| `emoji` | 효과 이모지 | `addSticker` | 계획된 중심점·스냅 | `application/json-insert` |
| `bubble` | 말풍선 변종 | `addBubble` | 계획된 중심점·스냅(변종 크기) | `application/json-insert` |
| `raster` | 내장 일러스트 | `addBuiltinRasterAsset` | 호스트의 기본 규칙(스냅 없음) | 없음, 누르기만 |
| `sfx` | 효과음 프리셋 | `addSfxPreset` | 호스트의 기본 규칙(스냅 없음) | 없음, 누르기만 |
| `object` | 삽입 카탈로그의 3D 오브젝트 | `openStudioObjectInsert` | 3D 도구가 열린다(문서는 바뀌지 않음) | `application/x-studio-object-insert+json` |

끌어다 놓기는 새 MIME 이나 소재 포맷을 만들지 않고 기존 캔버스 드롭(`onWrapDrop`)이 읽는 세 계약을 그대로 쓴다. 드롭 쪽 파서가 거절할 페이로드는 끌기를 시작하지 않고 "눌러서 붙이세요"로 안내한다.

### 되돌리기 한 단계 (current)

칩 하나는 호스트 삽입 명령을 정확히 한 번 부른다. 그 명령들은 각각 히스토리 커밋(`addEl` → `commit`)을 정확히 한 번만 일으키므로 삽입 한 번은 되돌리기 한 단계다. `openStudioObjectInsert` 는 문서를 바꾸지 않고 3D 도구만 연다.

호스트(`StudioCuttoonEditorHost.tsx`)는 거대한 클로저라 마운트하지 않고, `studio-charm-bar-host-contract.test.ts` 가 같은 소스를 AST 로 읽어 다음을 고정한다. 이 계약이 깨지면 시험이 먼저 실패한다.

- 위 명령의 선언은 호스트에 하나뿐이고 커밋 호출은 각각 정해진 횟수(1 또는 0)이며, 반복문이나 콜백 안에서 부르지 않는다.
- 명령들이 도구 벨트 안정 핸들러 묶음에 들어 있고, 안정 핸들러는 인자를 모두 그대로 전달한다(7번째 인자인 계획된 위치가 잘리지 않는다).
- 캔버스 드롭은 세 가지 끌기 계약을 모두 읽고 놓은 요소를 `addEl` 한 번으로 넣는다.
- 작업공간은 참 바 슬롯을 캔버스 열 앞에 한 번만 둔다.

호스트가 잠금·저장 중 등으로 거절하면(`addRenderedImage` 가 `false`) 참은 "붙이지 못했어요. 편집 잠금이나 저장 중인지 확인해 주세요."라고 알리고 다른 명령으로 우회하지 않는다. 이모지·말풍선·효과음 명령은 호스트가 결과를 돌려주지 않아 거절 여부를 알 수 없다. 대신 잠금(검수·공동 편집·페이지 잠금)은 칩이 미리 감지해 `aria-disabled` 로 표시하고 누르면 이유만 알린다.

## 4. 저장 (current)

- 권위: 기존 UI 환경설정 저장소(`studio-ui-preferences-v1` 네임스페이스, SQLite over OPFS)의 `charm-bar` 키. `StudioUiPreferencesRepository` 에 `loadCharmBar`·`saveCharmBar` 가 더해졌고 `localStorage` 로 내려가지 않는다. 기존 즐겨찾기 키(자산·효과·요소)는 건드리지 않으며 시험이 확인한다.
- 형태: `{ version: 1, charms: StudioCharmId[], open: boolean, starterSettled: boolean }`. 참 ID 는 `<종류>:<원본 ID>` 이고 소재 본문·권리 정보는 저장하지 않는다. 최대 24개이며 중복·알 수 없는 종류·형식이 틀린 항목은 읽을 때 조용히 버린다. 깨진 JSON·다른 버전은 빈 상태로 닫는다.
- 쓰기: 직렬화한다. 저장소를 한 번도 읽지 못한 동안의 명령은 화면에는 바로 반영하되 저장하지 않고 "저널"에 남겨 두었다가, 읽기에 성공하면 읽은 상태 위에 순서대로 다시 적용한다. 토글은 사용자가 화면에서 본 의도(고정·해제, 켬·끔)로 바꿔 기록해, 읽은 상태가 달라도 반대로 뒤집히지 않는다.
- 저장소를 읽거나 쓰지 못하면 이번 탭의 메모리 상태는 유지하고 "저장소에 연결하지 못해 이번 탭에서만 유지돼요"와 `저장 다시 시도`를 보인다.
- 상태 공유: 바 본체, 요소 패널의 고정 버튼, 메뉴의 스위치가 같은 모듈 스토어(`useSyncExternalStore`)를 본다. 거대한 호스트에 상태를 올리지 않는다.

### 내 소재 목록

편집기 호스트는 "내 에셋" 메뉴를 열어야 보관함 목록을 읽는다. 그 전에는 호스트의 `assets` 가 비어 있다. 그래서 참 바는 목록이 필요한 때(내 소재 참이 고정돼 있거나 참 고르기가 열렸을 때)에만, 호스트가 읽었으면 그 목록을, 읽는 중이면 끝나기를, 아니면 보관함의 **읽기 전용** 경로(`listAssetsReadOnly`, 정리·삭제를 하지 않음)로 직접 한 번 읽는다(`useStudioCharmLibrary.ts`). 읽는 동안 내 소재 칩은 자리표시이고, 실패하면 안내와 `내 소재 다시 불러오기`를 보인다. 사라진 소재는 읽은 뒤에야 "사용할 수 없는 참"이 된다.

## 5. 기본 스타터 팩 (current)

전부 저장소에 이미 있는 항목을 가리키는 참조 12개다. 새 소재를 만들거나 외부 소재를 들이지 않았다.

| 참 | 원본 |
| --- | --- |
| 집중선, 속도선 | 효과 오버레이 `radial-focus`, `speed-lines` |
| 큰 땀방울, 당황 식은땀 | 효과 오버레이 `sweat-drop`, `nervous-sweat` |
| 눈물·물방울 | 효과 이모지 💧 |
| 분노 마크, 느낌표, 반짝임, 우울 세로줄 | 효과 오버레이 `anger-mark`, `exclaim-mark`, `sparkle-cluster`, `gloom-lines` |
| 주먹 | 효과 이모지 👊 |
| 기본 소품 | 소품 스티커 `prop-smartphone`, `prop-coffee-cup` |

- **손 모양**: 저장소의 손 모양은 3D 포저의 포즈 프리셋(`vrm/studio-vrm-hand-poses.ts`)으로만 있고 캔버스에 바로 붙는 소재가 아니다(삽입 카탈로그의 "손 소품"은 손에 쥐는 3D 소품이다). 캔버스에 붙일 수 있는 가장 가까운 기존 소재가 주먹 이모지뿐이라 그것만 담았다. 손 모양 소재를 새로 만들지 않았다.
- **눈물**: 눈물 전용 소재는 없어 물방울 이모지를 담았다.
- `studio-charm-starter-pack.test.ts` 가 모든 참조가 실제 카탈로그에서 해석되는지, 끌어다 놓기가 가능한지를 지킨다. `기본 참 다시 담기`는 이미 있는 참을 건너뛴다.

## 6. 키보드·접근성 (current)

참 칩들은 하나의 도구 모음(`role="toolbar"`)이고 한 번에 칩 하나만 Tab 정지점을 가진다(roving tabindex). 세로 레일·가로 띠·떠 있는 창 어느 모양이어도 같은 키가 통하도록 네 방향 화살표를 모두 이동으로 쓴다(`studio-charm-keyboard.ts`).

| 키 | 동작 |
| --- | --- |
| ← → ↑ ↓ | 이전·다음 칩으로 이동(끝에서 반대편으로 순환) |
| Home / End | 첫·마지막 칩 |
| Enter / Space | 선택한 참을 붙인다(키를 누르고 있어도 한 번만) |
| Alt + ← ↑ / → ↓ | 순서를 한 칸 앞·뒤로 |
| Delete | 참 바에서 뺀다 |
| Esc | 순서 편집 끝내기 |

- 칩은 네이티브 `button` 이고 접근 가능한 이름은 참 이름(AI 생성이면 ", AI 생성" 덧붙임)이다. 사용법은 `aria-describedby` 의 숨김 안내문에 있다. `⋯` 메뉴의 "단축키 안내"가 같은 키를 보여 준다.
- 붙이기·고정·순서 변경 결과는 `role="status"` 안내 영역으로 알린다. 같은 문구를 연달아 알려도 다시 읽히도록 매번 새 노드로 갈아 끼운다.
- 삭제·순서 변경 뒤 포커스는 옮겨진 칩이나 이웃 칩으로 간다. 참 고르기를 Esc 로 닫으면 `+` 버튼으로 돌아온다. 아직 불러오는 중인 자리표시 칩은 버튼이 아니므로 화살표 이동, Alt+방향키 순서 변경, 삭제 뒤 포커스 모두 건너뛰어, 내 소재 읽기가 실패해 자리표시가 오래 남아도 키보드가 그 뒤 칩에 닿는다.
- 불러오는 중은 스켈레톤(`role="status"`, `aria-busy`), 빈 바는 스타터 팩 제안, 원본이 사라진 참은 "사용할 수 없는 참", 잠금은 `aria-disabled` 와 이유 문구, 저장소·내 소재·본체 불러오기 실패는 안내와 다시 시도 버튼을 갖는다. 본체 불러오기가 실패해도 편집기와 도구 구성은 그대로다.
- `prefers-reduced-motion` 이면 전환·눌림 효과를 끈다. 터치·좁은 화면(`pointer-coarse`, `max-lg`)에서 칩과 버튼은 44px 이상이다.
- 사용자 문구는 이웃 컴포넌트와 같은 `bi(ko, en)` 이중언어 관례(`studio-charm-copy.ts`, 범위 이름 `StudioCharmBar`)를 쓴다.

## 7. 구조 (current)

`apps/web/src/domains/creator/charm/` 에 있다. 도메인 안에서만 가져오며 다른 도메인의 내부 파일을 새로 가져오지 않는다.

| `studio-charm-insert.ts`, `studio-charm-cascade.ts` | 놓일 위치 계획·스냅, 호스트 명령 호출, 연속 삽입 카운터 |

## 8. 권리 (current)

참은 권리 정보를 만들거나 바꾸지 않고, 원본 항목이 가진 것을 요약해 선택기의 마우스 올림 설명에 보여 준다. AI 생성 소재는 칩에 "AI" 표시와 ", AI 생성" 이름을 붙인다.

| 종류 | 요약 |
| --- | --- |
| 요소·효과·스티커·소품·말풍선 | ToonStudio 가 코드로 직접 만든 내장 벡터(외부 소재 없음) |
| 효과음 | ToonStudio 가 만든 글자 스타일 프리셋. 글꼴 조건은 단정하지 않는다(`attributionRequired: null`) |
| 이모지 | 기기 이모지 글꼴로 그려지는 글리프. 별도 파일·라이선스 항목 없음 |
| 내장 일러스트 | 원본의 라이선스 참조·AI 생성 여부·표기 의무를 그대로 가져온다 |
| 내 소재 | 기록된 권리를 그대로 요약하고, 없거나 확인 전이면 그렇게 말한다. 출처가 AI 생성으로 기록돼도 AI 로 표시한다 |
| 3D 오브젝트 | 내장 3D 도형·소품·씬. 3D 도구에서 열어 편집한다 |

내 소재의 삽입은 기존 "내 에셋" 사용 경로(`addRenderedImage`)와 같고 이름만 더해진다. 내장 일러스트는 호스트의 `addBuiltinRasterAsset` 을 그대로 불러 내장 소재 ID 와 AI 생성 이력(`aiProvenance`)이 요소에 붙고, 말풍선 장식이면 대사 칸까지 한 번의 문서 변경으로 들어간다. 커뮤니티 에셋 즐겨찾기(`community:`)는 원본을 내려받아 검증해야 해서 참 대상이 아니다. 이 요약은 권리 허가서나 법률 검토를 대신하지 않는다.

## 9. 검증과 알려진 한계

### 실행한 검증

```bash
pnpm exec vitest run apps/web/src/domains/creator/charm \
  apps/web/src/domains/creator/catalog/StudioElementsBrowser.test.tsx \
  apps/web/src/domains/creator/studio-ui-preferences-sqlite.test.ts
node scripts/check-studio-eager-graph.mjs
node scripts/check-source-file-size.mjs
```

- 단위·컴포넌트 시험이 상태 모델, 저장소(저널·직렬화·실패 복구), 카탈로그와 권리, 위치 계획·스냅, 끌기 페이로드, 키보드, 칩·선택기·안내의 loading/empty/error/retry, 슬롯의 지연 로드와 도킹, 요소·효과 메뉴 연결을 확인한다.
- 브라우저가 없는 단계라 화면(밝은·어두운·고대비 테마, 모바일·데스크톱, 도킹 상태)은 컴포넌트 시험으로만 증명했다.

### 한계 (target)

- 실제 브라우저에서의 레이아웃·테마·터치 끌기 확인은 별도 UI/UX 단계의 일이다. 터치 기기에서 HTML 끌어다 놓기는 브라우저 지원에 달려 있어, 터치에서는 누르기가 기본 경로다.
- 효과음·내장 일러스트 칩은 호스트 명령이 위치 인자를 받지 않아 호스트의 기본 삽입 위치를 따르고 스냅을 적용하지 않는다.
- 이모지·말풍선·효과음 명령은 호스트가 성공 여부를 돌려주지 않아, 잠금이 아닌 다른 이유로 거절되면 "붙였어요"로 알릴 수 있다.
- 메뉴바·명령 팔레트·전역 단축키로 참 바를 켜는 길은 아직 없다. 룩·필터·보정 즐겨찾기를 참으로 붙이는 기능, 기기 간 동기화도 없다.
- 호스트의 내 소재 목록을 아직 읽지 않았다면 참 바가 같은 보관함을 따로 한 번 읽어, 두 곳이 목록을 각각 메모리에 들고 있을 수 있다(참 바를 닫으면 해제된다).

### 롤백

기능은 기본으로 꺼져 있고(`open: false`) 사용자가 스위치를 켜야 나타난다. 되돌릴 때는 이 기능의 커밋을 되돌리면 되며, 이미 저장된 `charm-bar` 키는 읽는 코드가 없어져 무시될 뿐 다른 저장 데이터에 영향이 없다.
