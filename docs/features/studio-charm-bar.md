# 원클릭 참(Charm) 스탬프 바

작성 기준일: 2026-10-16 · 대상 화면: Studio 편집기 작업공간(`/studio`)

이 문서는 자주 쓰는 반복 요소(집중선·땀방울·소품 등)를 한 번 누르거나 끌어다 놓아 캔버스에 붙이는 **참 바**의 **현재 구현(current)** 과 **아직 없는 것(target)** 을 나눠 적는다. 구현되지 않은 것을 현재 기능처럼 쓰지 않는다.

## 2. 사용자 흐름 (current)

1. **켜기**: 템플릿·에셋 메뉴에서 "요소" 또는 "효과·스티커" 구역을 열고 맨 위의 `참 바` 스위치를 켠다(스위치에 포인터를 올리거나 포커스·터치하면 지연 로드하는 본체와 카탈로그 데이터를 미리 불러온다). 바는 도구 레일 옆에 붙어 나타난다. 처음 켜는 빈 바에는 기본 참 12개가 한 번 담기고 "기본 참 12개를 담았어요" 안내가 뜬다. 필요 없는 참은 편집에서 뺄 수 있고, 한 번이라도 목록을 고치면 다시 자동으로 담지 않는다.
2. **붙이기**: 칩을 누르거나(Enter·Space) 캔버스로 끌어다 놓는다. 위치 규칙은 3장이다. 같은 칩을 연달아 눌러도 같은 컷 안에서 계단식으로 이어진다. 결과는 호스트가 알려 준 만큼만 말한다 — 확인된 것만 "붙였어요", 결과를 주지 않는 이모지·말풍선·효과음은 "요청했어요"이고, 요청·거절·실패는 눈에 보이는 안내로도 잠시 띄운다(3장).
3. **고르기**: 바의 `+`(참 고르기)에서 검색하고 분류(효과·선, 스티커, 소품, 이모지, 효과음, 도형·장식, 일러스트, 내 소재, 말풍선, 3D)로 좁혀 고정·해제한다. "즐겨찾기" 분류는 기존 즐겨찾기(내장 일러스트·내 소재의 별, 요소 카탈로그의 별)를 읽기만 하고 바꾸지 않는다.
4. **요소 상세에서 고정**: 요소 패널의 상세 미리보기에 "참 바에 고정" 토글이 있다. 고정하면 바가 함께 켜진다.
5. **순서·삭제 편집**: `⋯` 메뉴의 "순서·삭제 편집"에서 칩을 고르고 앞으로·뒤로·빼기를 누른다. 키보드로는 편집 중에 Alt+방향키(순서), Delete·Backspace(빼기), Esc(끝내기)이다. 편집 중이 아닐 때의 Delete 는 참을 빼지 않고 빼는 방법만 알린다 — 붙인 직후에는 방금 붙인 요소가 선택돼 있어 그 요소를 지우려는 키가 되돌릴 수 없게 참을 지우면 안 되기 때문이다. `⋯` 메뉴는 키보드만으로 열고(첫 항목으로 포커스), ↑ ↓ Home End 로 오가고, Esc 나 가장자리를 벗어나는 Tab 으로 닫으면 `⋯` 버튼으로 돌아온다.
6. **옮기기·닫기**: 작업 배치 편집에서 자유 배치로 떼거나 왼쪽·오른쪽·위·아래 가장자리에 붙일 수 있다(1024px 이상). `⋯` 메뉴의 "참 바 닫기"나 같은 스위치로 끈다. 켜 둔 상태·목록·순서는 저장된다.

화면이 가려지는 상태(캔버스 전용 모드, 모바일 몰입 모드, 프레젠테이션으로 패널을 숨긴 상태)에서는 바를 그리지 않고, 풀리면 켜 둔 상태 그대로 돌아온다.

## 3. 붙이기 규칙 (current)

### 위치

| 상황 | 놓이는 곳 |
| --- | --- |
| 컷(프레임)을 선택 | 그 컷의 중앙, 컷 안에 맞춘다 |
| 프레임이 아닌 요소를 선택 | 그 요소의 중앙(문서 안으로 맞춘다) |
| 텍스트·이모지 스티커처럼 크기(폭·높이)가 없는 요소를 선택 | 선택이 없는 것으로 보고 지금 보이는 화면의 중앙. 호스트가 스티커에는 폭·높이를 두지 않고 텍스트에는 폭만 두기 때문이다 |
| 선택 없음 | 지금 보이는 화면의 중앙 |
| 보이는 화면도 알 수 없음 | 문서 중앙 |

같은 대상에 5초 안에 이어 붙이면 계단식으로 조금씩 비껴 놓여 완전히 겹치지 않는다(호스트의 `nextAssetInsertionPlacement` 와 같은 규칙, `studio-charm-cascade.ts`).

#### 연속 붙이기 (current)

호스트의 삽입 명령(`addEl`)은 새 요소를 문서에 넣고 곧바로 그 요소를 선택한다. 그대로 두면 같은 칩을 다시 눌렀을 때 세션의 선택이 "방금 붙인 요소"가 되어, 컷을 고른 채 시작했어도 대상이 그 요소(프레임이 아닌 요소의 중앙)로 바뀌고 계단 카운터가 0 으로 돌아간다. 컷 400×300 에 효과(480px)를 네 번 붙이면 첫 번째만 컷 안(276×276)에 맞고 나머지는 같은 자리에 480×480 으로 겹쳐 컷 밖으로 나갔다. 스티커처럼 폭·높이가 없는 요소가 선택되면 선택이 없는 것으로 읽혀 화면 중앙으로 새기도 했다.

그래서 `createStudioCharmBurst` 가 **직전에 읽은 뒤 같은 문서에 새로 생긴 요소**가 선택돼 있으면 그것을 사용자의 선택이 아니라 직전 붙이기의 결과로 보고, 직전 붙이기가 쓴 선택(컷·요소·없음)을 그대로 이어 받는다. 그러면 같은 컷 안에서 매번 계단식으로 비껴 놓이고 컷 밖으로 커지지 않는다. 이어 받지 않는 경우: 사용자가 문서에 원래 있던 요소를 직접 고르거나 선택을 풀었을 때(그 선택을 따른다), 5초가 지났을 때, 다른 페이지·문서 마스터로 옮겨 요소 목록이 통째로 바뀌었을 때, 그 사이 요소를 지웠을 때, 선택한 요소가 요소 목록에 없을 때(저장 전 펜 획), 세션이 요소 목록을 주지 않을 때. 한계: 5초 안에 같은 문서에서 다른 도구로 새 요소를 만들어 선택하면 그것도 "새로 생긴 요소"라 직전 대상을 이어 받는다.

호스트가 이를 위해 세션으로 넘기는 값(`selected`, `elements`)과 `addEl` 이 새 요소를 선택하는 동작은 호스트 계약 시험이 소스에서 고정한다.

격자 스냅이 켜져 있으면 객체를 끌 때와 같은 자석 규칙(`snapStudioObjectDragPosition`, 허용 거리는 화면 px 기준)으로 놓이는 요소의 왼쪽 위 모서리를 격자에 맞춘다. 말풍선은 변종마다 호스트가 놓는 실제 크기(`studioCharmBubbleFootprint`)로 맞추며, 이 크기표가 호스트와 어긋나면 `studio-charm-bar-host-contract.test.ts` 가 실패한다.

### 종류별 동작

| 종류(`kind`) | 원본 | 부르는 호스트 명령 | 위치·스냅 | 끌어다 놓기 |
| --- | --- | --- | --- | --- |
| `element` | 요소 카탈로그 | `addRenderedImage` | 계획된 위치·스냅 | `application/json-asset` |
| `fx` | 효과 오버레이, 만화·동물·소품 스티커 | `addRenderedImage` | 계획된 위치·스냅 | `application/json-asset` |
| `library` | 내 소재 라이브러리 | `addRenderedImage` | 계획된 위치·스냅 | `application/json-asset` |
| `emoji` | 효과 이모지 | `addSticker` | 계획된 중심점·스냅 | `application/json-insert` |
| `bubble` | 말풍선 변종 | `addBubble` | 계획된 중심점·스냅(변종 크기) | `application/json-insert` |
| `raster` | 내장 일러스트 | `addBuiltinRasterAsset` | 호스트의 기본 규칙(스냅 없음) | 없음, 누르기만 |
| `sfx` | 효과음 프리셋 | `addSfxPreset` | 호스트의 기본 규칙(스냅 없음) | 없음, 누르기만 |
| `object` | 삽입 카탈로그의 3D 오브젝트 | `openStudioObjectInsert` | 3D 도구가 열린다(문서는 바뀌지 않음) | `application/x-studio-object-insert+json` |

끌어다 놓기는 새 MIME 이나 소재 포맷을 만들지 않고 기존 캔버스 드롭(`onWrapDrop`)이 읽는 세 계약을 그대로 쓴다. 드롭 쪽 파서가 거절할 페이로드는 끌기를 시작하지 않고 "눌러서 붙이세요"로 안내한다.

### 되돌리기 한 단계 (current)

칩 하나는 호스트 삽입 명령을 정확히 한 번 부른다. 그 명령들은 각각 히스토리 커밋(`addEl` → `commit`)을 정확히 한 번만 일으키므로 삽입 한 번은 되돌리기 한 단계다. `openStudioObjectInsert` 는 문서를 바꾸지 않고 3D 도구만 연다.

호스트(`StudioCuttoonEditorHost.tsx`)는 거대한 클로저라 마운트하지 않고, `studio-charm-bar-host-contract.test.ts` 가 같은 소스를 AST 로 읽어 다음을 고정한다. 이 계약이 깨지면 시험이 먼저 실패한다.

- 위 명령의 선언은 호스트에 하나뿐이고, **간접 호출까지 따라가도** 호출당 히스토리 쓰기가 정해진 횟수(1 또는 0)이며, 반복문·콜백·재귀 안에서 쓰지 않는다. 호스트 파일 안의 함수(선언, `const` 화살표, `useCallback`)를 이름으로 모아 기본 쓰기(`commit`·`commitCoalesced`·`commitPages`)에 닿는 호출 그래프를 따라 쓰기 수를 합산한다(`studio-charm-host-writes.test-support.ts`). 예전에는 직접 부르는 커밋 호출 이름 네 개만 세어서, 호스트 사본의 `addSticker` 에 `patchEl`, `addBubble` 에 `addText()`, `addRenderedImage` 에 `updateActivePage` 를 더해도 통과했다. 지금은 이 세 변형과 허용된 도우미가 내부에서 커밋하게 바뀐 경우, 새 도우미를 거친 쓰기를 모두 잡는 것을 시험이 변형 사본으로 확인한다.
- 각 명령이 본문에서 이름으로 부를 수 있는 함수는 사람이 검토해 올린 **허용 호출 목록**뿐이다. 새 호출이 생기면 시험이 실패해, 그 호출이 문서를 바꾸는지 보게 한다.
- 명령들이 도구 벨트 안정 핸들러 묶음에 들어 있고, 안정 핸들러는 인자를 모두 그대로 전달한다(7번째 인자인 계획된 위치가 잘리지 않는다).
- 캔버스 드롭은 세 가지 끌기 계약을 모두 읽고 놓은 요소를 `addEl` 한 번으로 넣는다.
- 작업공간은 참 바 슬롯을 캔버스 열 앞에 한 번만 둔다.
- 슬롯이 읽는 세션 필드는 모두 호스트가 뷰에 넘기는 속성이고, 편집 잠금 값은 호스트가 파생하는 식 그대로(`activeSurfaceReviewLocked = collaborationDocumentLocked || (pageEditLocked && !masterEditMode)`, 안내는 `() => string` 함수) 읽는다.
- 전역 디스패처가 `defaultPrevented` 이거나 단축키 경계 안인 키를 편집 명령으로 실행하지 않는다는 전제(참 바의 키 입력 시험이 같은 함수·선택자로 흉내 낸다).

**이 계약 시험의 한계**: 호스트 파일 밖에서 온 함수(import, 훅이 돌려준 함수)의 내부, `ref.current.fn()` 같은 멤버 호출, 동적 호출은 따라가지 못한다. 그런 호출은 허용 목록에 이름이 없으면 실패하지만, 이미 허용된 외부 함수(`createCanvasImageElement` 등) 내부가 바뀌는 것은 이 시험이 보지 못한다. 한 함수 안의 분기는 호출 위치를 모두 더하므로 보수적으로 센다.

### 붙이기 결과 안내 (current)

결과는 호스트가 알려 준 만큼만 말한다.

| 결과 | 언제 | 안내 |
| --- | --- | --- |
| 붙였어요(`inserted`) | `addRenderedImage`·`addBuiltinRasterAsset` 이 `true` | "붙였어요: 이름" |
| 요청했어요(`requested`) | 결과를 주지 않는 이모지·말풍선·효과음, `void` 로 끝난 일러스트 | "이름 붙이기를 요청했어요. 캔버스에 안 보이면 잠금이나 저장 중인지 확인해 주세요." |
| 붙이지 못했어요(`rejected`) | 호스트가 `false` | 이유가 잠금·저장 중·다른 삽입 진행 중(`builtinRasterBusyId`)·네트워크 실패 중 무엇인지 참은 모르므로 그렇게 말하고, 편집기에 표시된 안내를 보라고 한다. 다른 명령으로 우회하지 않는다 |
| 실패(`failed`) | 명령이 예외 | 예외 메시지 |

요청·거절·실패는 스크린리더용 상태 영역에 더해 눈에 보이는 안내(`data-studio-charm-note="result"`)로도 8초 동안 띄운다. 같은 문장을 스크린리더가 상태 영역으로 이미 읽으므로 보이는 쪽은 `aria-hidden` 이다. 다음 붙이기가 성공하면 먼저 사라진다. 이전에는 이모지·말풍선·효과음을 호스트가 거절해도 "붙였어요"로 알렸다.

잠금(공동 편집·페이지 검토·검수)은 칩이 미리 감지해 `aria-disabled` 로 표시하고 누르면 이유만 알린다. 사유는 호스트가 파생한 값으로 정한다: 공동 편집 잠금(문장은 호스트의 `collaborationLockMessage()` 를 불러 얻는다)을 먼저 보고, 그 밖의 쓰기 불가는 `activeSurfaceReviewLocked` 로 판정한다. 문서 마스터를 편집하는 동안의 페이지 검토 잠금은 호스트가 쓰기를 허용하므로 칩도 막지 않는다.

### 끌어다 놓기와 누르기의 레이어 이름 차이 (current, 호스트 쪽 차이)

누르기는 호스트 삽입 명령에 `{ name: 참 이름 }` 을 넘겨 레이어 이름이 참 이름이 된다. 끌어다 놓기는 호스트의 캔버스 드롭(`onWrapDrop`)이 로컬 에셋 페이로드를 `elementPatch` 없이 놓아서 레이어 이름이 없다. 호스트 쪽 동작이라 참 바에서는 고치지 않았다.

## 4. 저장 (current)

- 권위: 기존 UI 환경설정 저장소(`studio-ui-preferences-v1` 네임스페이스, SQLite over OPFS)의 `charm-bar` 키. `StudioUiPreferencesRepository` 에 `loadCharmBar`·`saveCharmBar` 가 더해졌고 `localStorage` 로 내려가지 않는다. 기존 즐겨찾기 키(자산·효과·요소)는 건드리지 않으며 시험이 확인한다.
- 형태: `{ version: 1, charms: StudioCharmId[], open: boolean, starterSettled: boolean }`. 참 ID 는 `<종류>:<원본 ID>` 이고 소재 본문·권리 정보는 저장하지 않는다. 최대 24개이며 중복·알 수 없는 종류·형식이 틀린 항목은 읽을 때 조용히 버린다. 깨진 JSON·다른 버전은 빈 상태로 닫는다.
- 쓰기: 직렬화한다. 저장소를 한 번도 읽지 못한 동안의 명령은 화면에는 바로 반영하되 저장하지 않고 "저널"에 남겨 두었다가, 읽기에 성공하면 읽은 상태 위에 순서대로 다시 적용한다. 토글은 사용자가 화면에서 본 의도(고정·해제, 켬·끔)로 바꿔 기록해, 읽은 상태가 달라도 반대로 뒤집히지 않는다.
- 저장소를 읽거나 쓰지 못하면 이번 탭의 메모리 상태는 유지하고 "저장소에 연결하지 못해 이번 탭에서만 유지돼요"와 `저장 다시 시도`를 보인다.
- 상태 공유: 바 본체, 요소 패널의 고정 버튼, 메뉴의 스위치가 같은 모듈 스토어(`useSyncExternalStore`)를 본다. 거대한 호스트에 상태를 올리지 않는다.

### 내 소재 목록

편집기 호스트는 "내 에셋" 메뉴를 열어야 보관함 목록을 읽는다. 그 전에는 호스트의 `assets` 가 비어 있다. 그래서 참 바는 목록이 필요한 때(내 소재 참이 고정돼 있거나 참 고르기가 열렸을 때)에만, 호스트가 읽었으면 그 목록을, 읽는 중이면 끝나기를, 아니면 보관함의 **읽기 전용** 경로(`listAssetsReadOnly`, 정리·삭제를 하지 않음)로 직접 한 번 읽는다(`useStudioCharmLibrary.ts`). 읽는 동안 내 소재 칩은 자리표시이고, 실패하면 안내와 `내 소재 다시 불러오기`를 보인다. 사라진 소재는 읽은 뒤에야 "사용할 수 없는 참"이 된다.

## 6. 키보드·접근성 (current)

참 칩들은 하나의 도구 모음(`role="toolbar"`)이고 한 번에 칩 하나만 Tab 정지점을 가진다(roving tabindex). 세로 레일·가로 띠·떠 있는 창 어느 모양이어도 같은 키가 통하도록 네 방향 화살표를 모두 이동으로 쓴다(`studio-charm-keyboard.ts`).

| 키 | 동작 |
| --- | --- |
| ← → ↑ ↓ | 이전·다음 칩으로 이동(끝에서 반대편으로 순환) |
| Home / End | 첫·마지막 칩 |
| Enter / Space | 선택한 참을 붙인다(키를 누르고 있어도 한 번만) |
| Alt + ← ↑ / → ↓ | 순서를 한 칸 앞·뒤로 |
| Delete · Backspace | **순서 편집 중에만** 참 바에서 뺀다(맥의 ⌫ 는 Backspace). 편집 중이 아니면 빼지 않고 방법만 알린다 |
| Esc | 순서 편집 끝내기(칩이나 편집 도구 버튼에서) |

- 칩은 네이티브 `button` 이고 접근 가능한 이름은 참 이름(AI 생성이면 ", AI 생성" 덧붙임)이다. 사용법은 칩마다가 아니라 도구 모음(`role="toolbar"`)에 한 번만 `aria-describedby` 로 연결한 숨김 안내문에 있다. `⋯` 메뉴의 "단축키 안내"가 같은 키를 보여 준다. 도구 모음에 `aria-orientation` 은 두지 않았다: 세로 레일·가로 띠·떠 있는 창에서 모두 네 방향 화살표가 통하고 배치는 CSS 가 정하므로 고정 값이 한 배치에서는 틀리기 때문이다.
- **단축키 경계**: 바 본체(`<section>`), 포털로 body 끝에 뜨는 팝오버(`⋯` 메뉴·참 고르기), 슬롯의 불러오는 중·실패 자리표시는 `data-studio-shortcut-boundary="true"` 다. 전역 디스패처는 이미 처리된 키(`defaultPrevented`)와 경계 안의 키를 캔버스 편집 명령으로 실행하지 않으므로, 칩이 처리하지 않는 키(Backspace·Shift+방향키·글자)가 선택한 캔버스 요소를 지우거나 옮기지 않는다. 경계 안에서도 되돌리기·다시 하기는 편집기로 통과한다. 이웃 `StudioSelectionContextBar` 등과 같은 관례다.
- **`⋯` 메뉴·참 고르기 키보드**: 팝오버는 body 끝 포털이라 포커스를 옮기지 않으면 Tab 으로는 닿지 못했다. 이제 `⋯` 메뉴는 열리면 첫 활성 항목(참이 없어 첫 항목이 꺼져 있으면 다음 항목)으로 포커스를 옮기고, ↑ ↓ Home End 로 항목을 오가며 끝에서 순환한다. 메뉴·선택기 모두 가장자리를 벗어나는 Tab(맨 끝에서 Tab, 맨 앞에서 Shift+Tab)과 Esc 로 닫으면 `⋯`·`+` 버튼으로 포커스가 돌아온다(비모달이라 포커스를 가두지는 않는다). 항목을 실행해 닫을 때도 같다. 순서·삭제 편집은 `⋯` 버튼이 사라지므로 포커스가 칩으로 가고, 편집을 끝낼 때도 칩으로 돌아간다.
- 붙이기·고정·순서 변경 결과는 `role="status"` 안내 영역으로 알린다. 같은 문구를 연달아 알려도 다시 읽히도록 매번 새 노드로 갈아 끼운다. 요청·거절·실패는 눈에 보이는 안내로도 잠시 띄운다(3장).
- 참 고르기 타일은 고정 상태를 `aria-pressed` 한 곳으로만 전한다(라벨은 "이름 — 참 바에 고정" 그대로). 권리·출처 요약은 마우스 올림(`title`)에만 두지 않고 각 타일의 `aria-describedby` 와 목록 아래의 눈에 보이는 영역(포커스·올림·누름을 받은 항목)에 둔다.
- 삭제·순서 변경 뒤 포커스는 옮겨진 칩이나 이웃 칩으로 간다. 참 고르기를 Esc 로 닫으면 `+` 버튼으로 돌아온다. 메뉴의 "참 바 닫기"로 바 자체를 끄면 바가 사라지므로 포커스는 문서로 넘어간다(다시 켜는 스위치는 에셋 메뉴에 있다). 아직 불러오는 중인 자리표시 칩은 버튼이 아니므로 화살표 이동, Alt+방향키 순서 변경, 삭제 뒤 포커스 모두 건너뛰어, 내 소재 읽기가 실패해 자리표시가 오래 남아도 키보드가 그 뒤 칩에 닿는다.
- 불러오는 중은 스켈레톤(`role="status"`, `aria-busy`), 빈 바는 스타터 팩 제안, 원본이 사라진 참은 "사용할 수 없는 참", 잠금은 `aria-disabled` 와 이유 문구, 저장소·내 소재·본체 불러오기 실패는 안내와 다시 시도 버튼을 갖는다. 본체 불러오기가 실패해도 편집기와 도구 구성은 그대로다.
- `prefers-reduced-motion` 이면 전환·눌림 효과를 끈다. 터치·좁은 화면(`pointer-coarse`, `max-lg`)에서 칩과 버튼은 44px 이상이다.
- 사용자 문구는 이웃 컴포넌트와 같은 `bi(ko, en)` 이중언어 관례(`studio-charm-copy.ts`, 범위 이름 `StudioCharmBar`)를 쓴다. **`bi()` 에는 정적 문구만 넣는다**: `bi` 는 쌍마다 전역 번역 사전에 키를 등록하고 영문을 기계 번역 소스로 올리므로, 내 소재 이름 같은 동적 값을 끼워 넣으면 ja 등에서 사용자가 만든 텍스트가 외부 번역 API 로 나갈 수 있고 새 문구마다 전역 번역 갱신이 일어난다. 동적 값은 `biFill("붙였어요: {label}", "Stamped: {label}", { label })` 처럼 번역된 틀에 자리표시로 채운다(저장소의 `formatI18nTemplate(bi("{value0}…", …), values)` 관례). `studio-charm-copy.test.ts`(소스 검사)와 `StudioCharmBar.i18n.test.tsx`(번역 대기 목록·사전에 이름이 없음)가 지킨다.
- 선택기가 보여 주는 참 이름·권리 요약은 카탈로그가 가진 한글 그대로다(요소·효과 라벨과 같다). 이 데이터의 영문화는 하지 않았다.

- **번들**: 슬롯과 순수 모듈 8개(약 44 KiB 원본)를 작업공간이 정적으로 가져오면 Studio 첫 청크 그래프에 그대로 묶여, PR #2325 의 `core` 가 번들 래칫(`Studio route after app shell` 원시 +20 KiB·gzip +8.8 KiB·청크 +5)에서 적색이 됐다. 그래서 슬롯째 지연 로드한다 — 작업공간은 `StudioCharmBarSlotLazy` 만 가져오고, 슬롯은 작업공간이 마운트된 뒤에 받는다. 참 바는 템플릿·에셋 메뉴에서 켜야 쓰는 선택 기능이고 저장된 상태는 어차피 비동기로 읽으므로 사용자가 보는 차이는 슬롯 청크 한 번(약 16 KiB 원시)만큼의 지연이다. 칩·선택기·카탈로그 데이터(SVG)는 바를 펼칠 때 한 번 더 지연 로드한다. 작업공간 계약 시험(`studio-charm-bar-host-contract.test.ts`)이 정적 import 가 되살아나지 않는지 지킨다(`pnpm run check:studio-eager-graph`·`check:studio-bundle`).
- 편집기 호스트(`StudioCuttoonEditorHost.tsx`)는 고치지 않았다. 기존 파일에는 작은 연결만 더해졌다: 작업공간에 슬롯 렌더 1곳(`StudioCuttoonEditorWorkspace.tsx`), 에셋 메뉴에 스위치 1곳(`StudioAssetToolPopoverBody.tsx`), 요소 상세에 고정 버튼 1곳(`StudioElementsPanel.tsx`), 저장소에 `charm-bar` 읽기·쓰기(`studio-ui-preferences-sqlite.ts`). 작업공간 파일은 `@ts-nocheck` 라서 컴파일러가 슬롯에 넘기는 세션 필드를 검사하지 못한다. 슬롯이 읽는 세션 필드 23개(`StudioCharmHostSession` 15개 + 슬롯 8개)는 호스트 계약 시험이 선언을 읽어 호스트가 뷰에 넘기는 속성과 직접 대조한다(이 문서의 개수도 같은 시험이 지킨다).

## 8. 권리 (current)

참은 권리 정보를 만들거나 바꾸지 않고, 원본 항목이 가진 것을 요약해 선택기에 보여 준다(마우스 올림 설명, 타일의 `aria-describedby`, 포커스·올림·누름을 받은 항목의 눈에 보이는 영역). AI 생성 소재는 칩에 "AI" 표시와 ", AI 생성" 이름을 붙인다.

| 종류 | 요약 |
| --- | --- |
| 요소·효과·스티커·소품·말풍선 | ToonStudio 가 코드로 직접 만든 내장 벡터(외부 소재 없음) |
| 효과음 | ToonStudio 가 만든 글자 스타일 프리셋. 글꼴 조건은 단정하지 않는다(`attributionRequired: null`) |
| 이모지 | 기기 이모지 글꼴로 그려지는 글리프. 별도 파일·라이선스 항목 없음 |
| 내장 일러스트 | 원본의 라이선스 참조·AI 생성 여부·표기 의무를 그대로 가져온다 |
| 내 소재 | 기록된 권리를 그대로 요약하고, 없거나 확인 전이면 그렇게 말한다. 출처가 AI 생성으로 기록돼도 AI 로 표시한다 |
| 3D 오브젝트 | 내장 3D 도형·소품·씬. 3D 도구에서 열어 편집한다 |

내 소재의 삽입은 기존 "내 에셋" 사용 경로(`addRenderedImage`)와 같고 이름만 더해진다. 내장 일러스트는 호스트의 `addBuiltinRasterAsset` 을 그대로 불러 내장 소재 ID 와 AI 생성 이력(`aiProvenance`)이 요소에 붙고, 말풍선 장식이면 대사 칸까지 한 번의 문서 변경으로 들어간다. 커뮤니티 에셋 즐겨찾기(`community:`)는 원본을 내려받아 검증해야 해서 참 대상이 아니다. 이 요약은 권리 허가서나 법률 검토를 대신하지 않는다.

### 한계 (target)

- 실제 브라우저에서의 레이아웃·테마·터치 끌기 확인은 별도 UI/UX 단계의 일이다. 터치 기기에서 HTML 끌어다 놓기는 브라우저 지원에 달려 있어, 터치에서는 누르기가 기본 경로다.
- 효과음·내장 일러스트 칩은 호스트 명령이 위치 인자를 받지 않아 호스트의 기본 삽입 위치를 따르고 스냅을 적용하지 않는다.
- 이모지·말풍선·효과음 명령은 호스트가 성공 여부를 돌려주지 않아 참이 붙었는지 확인할 수 없다. 그래서 "붙였어요" 대신 "요청했어요"로 알리고 눈에 보이는 안내를 띄우지만, 실제로 붙었는지는 사용자가 캔버스에서 확인해야 한다. 성공을 확인해 주는 신호는 호스트 변경이 있어야 한다.
- 거절(`false`)의 이유는 참이 알 수 없다(잠금·저장 중·다른 삽입 진행 중·네트워크). 호스트가 띄운 안내를 보라고만 말한다.
- 단축키 경계의 대가: 칩을 마우스로 누르면 포커스가 칩에 남을 수 있고, 그 동안에는 Delete·글자 단축키·Shift+방향키가 캔버스에 닿지 않는다(되돌리기·다시 하기만 통과). 방금 붙인 요소를 키보드로 지우거나 옮기려면 캔버스를 눌러 포커스를 옮겨야 한다. 빼기를 순서 편집 중으로 한정한 것도 같은 이유다.
- 연속 붙이기의 선택 이어 받기는 "새로 생긴 요소"를 요소 ID 목록 비교로 알아본다. 5초 안에 같은 문서에서 다른 도구로 새 요소를 만들어 선택하면 그것도 직전 붙이기의 결과로 보고 직전 대상을 이어 받는다(3장).
- 호스트 계약 시험은 호스트 파일 밖의 함수 내부와 멤버 호출을 따라가지 못한다(3장의 한계).
- 선택기의 참 이름·권리 요약, 카탈로그의 고정 한글 문구(`studio-charm-catalog.ts`)는 영문화하지 않았다. 도구 모음에 `aria-orientation` 도 두지 않았다(6장).
- 끌어다 놓아 만든 레이어는 이름이 없고 눌러서 붙인 레이어는 참 이름을 가진다(호스트 드롭 경로의 동작이라 고치지 않음).
- 메뉴바·명령 팔레트·전역 단축키로 참 바를 켜는 길은 아직 없다. 룩·필터·보정 즐겨찾기를 참으로 붙이는 기능, 기기 간 동기화도 없다.
- 여러 브라우저 탭이 같은 저장소를 동시에 고치면 마지막 저장이 이긴다. 탭 사이 실시간 동기화는 없다.
- 호스트의 내 소재 목록을 아직 읽지 않았다면 참 바가 같은 보관함을 따로 한 번 읽어, 두 곳이 목록을 각각 메모리에 들고 있을 수 있다(참 바를 닫으면 해제된다).

### 롤백

기능은 기본으로 꺼져 있고(`open: false`) 사용자가 스위치를 켜야 나타난다. 되돌릴 때는 이 기능의 커밋을 되돌리면 되며, 이미 저장된 `charm-bar` 키는 읽는 코드가 없어져 무시될 뿐 다른 저장 데이터에 영향이 없다.
