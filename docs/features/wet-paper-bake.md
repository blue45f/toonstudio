## 3. 실행 경로

- **입력**: 제품 수채 플래너가 만든 dab 계획(같은 레인의 베이스 워시와 같다)과 획 고정 시드(요소 id에서 계산).
- **Canvas(커밋 획)**
  - 렌더 본문이 `requestStudioWetPaperBake`를 부른다. 결과가 없으면 이번 프레임은 베이스 워시를 그린다.
  - 호스트는 setTimeout 0 조각마다 8 ms 예산 안에서 솔버 스텝을 하나씩, 합성은 약 16k 픽셀씩 전진한다. 끝나면 `onReady`가 한 번 불리고 다음 렌더에서 굽힌 래스터를 `drawImage`로 그린다.
  - 솔버·합성 코드와 프로그램 표(물·안료·종이 계수)는 `studio-wet-paper-runtime.ts` 동적 import 뒤에 있어 Studio 진입 청크에 실리지 않는다. 진입 그래프에는 호스트, 프로그램 id·요청 키(`studio-wet-paper-program-ids.ts`), 정착 표면 해석만 실린다.
  - 캐시는 두 층이다. 굽기 결과(색과 무관한 광학 밀도)는 dab 서명으로, 합성 래스터는 색별로(항목당 2개) LRU로 보관한다. 색만 바뀐 획은 다시 풀지 않고 합성만 한다. 소프트 상한(결과 48개·400만 셀, 래스터 600만 픽셀)을 넘으면 핀이 아닌 오래된 것부터 버린다.
  - 핀: 최근 2초 안에 요청됐거나 막 보관한 결과·래스터와 합성 중인 결과는 버리지 않는다. 예전에는 대칭 획처럼 한 화면이 소프트 상한보다 많이 쓰면 하나를 넣을 때마다 다른 것을 버려, 서로 밀어내며 합성을 끝없이 되풀이했다. 핀 때문에 하드 상한(소프트의 2배)을 넘겨야 하면 새 것을 보관하지도 알리지도 않고(베이스 워시 유지), 그 키는 5초 동안 다시 걸지 않는다.
  - 요청자(획 노드 렌더 인스턴스 + 대칭 변형 번호): 같은 요청자가 다른 입력(두께 슬라이더·노드 끌기·색 미리보기)을 요청하면, 아무도 기다리지 않게 된 이전 풀이·합성을 버린다. 예전에는 중간 모양·색마다 전체 작업이 줄을 서 마지막 결과가 수십 초 늦었다. 요청자 없이 부른 요청과 다른 요청자도 기다리는 작업은 버리지 않는다.
  - 합성과 풀이는 단위마다 번갈아 진행한다. 예전에는 합성이 늘 먼저라 색을 여러 번 바꾸는 동안 다른 획의 풀이가 굶었다.
  - 합성하는 사이 결과가 LRU에서 밀려나면 래스터를 보관하지 않고 다시 요청하게 한다.
  - 굽기가 끝나 획 노드가 다시 렌더되면, 캐시된 조상 그룹(블렌드·마스크·조정)을 가장 가까운 캐시 소유자부터 다시 만든다(늦게 도착한 이미지와 같은 규칙). 예전에는 캐시된 조상이 베이스 워시 픽셀을 계속 그렸다.
  - 캡처 준비(`waitForStudioCaptureReady`)는 대기 중인 굽기가 있으면 남은 시간의 절반 안에서 `waitForStudioWetPaperBakesIdle` 을 기다리고, 두 프레임을 더 그린 뒤 캡처한다. 그 안에 끝나지 않으면 베이스 워시로 캡처한다(굽기는 캡처 실패 사유가 아니다). 예전에는 페이지를 바꾼 직후 내보내면 굽기 전 베이스 워시가 찍혔다.
- **SVG 내보내기**
  - 같은 프로그램 해석과 같은 create → advance(1)·N → finish 순서를 동기로 돌린다. 같은 스레드의 호스트 캐시에 결과가 있으면 다시 쓴다. 제품 내보내기는 매번 새 Worker 에서 돌아 캐시가 비어 있으므로 모든 젖은 종이 획을 다시 굽는다.
  - 내보내기 한 번의 굽기 작업량은 격자 셀 × 스텝 1,000만으로 묶는다(`STUDIO_SVG_WET_PAPER_BAKE_CELL_STEP_BUDGET`, 개발 기기 최악 약 7초 — Worker 시간 한도 30초 안). 앞에서부터 한도까지 굽고, 넘는 획은 베이스 워시로 내보내며 근사(`wetPaperBakeBudget`)로 알린다. 캐시에 있던 결과는 작업량을 쓰지 않는다. 그래서 같은 문서는 Worker 내보내기에서 늘 같은 SVG 이고, 캐시가 있는 메인 스레드 경로는 더 많은 획을 구울 수 있다.
  - 렌더 경로에서 동기로 부르는 래스터 집계(인스펙터)와 목록 미리보기는 `wetPaperBake: "base-wash"` 로 굽지 않는다. 집계는 SVG 의 제외·근사 목록만 쓰고 픽셀은 쓰지 않는다. 예전에는 캐시에 없는 획마다 메인 스레드에서 풀어 획 40개 페이지의 집계 한 번이 약 8초 걸렸다.
  - 굽기가 다루지 않는 색 — 반투명·투명 색(알파 < 1), 가장 어두운 채널이 0.8 보다 밝은 거의 흰 안료 — 은 Canvas 와 SVG 모두 굽지 않고 베이스 워시를 낸다. 예전에는 'transparent' 가 검정 안료로 구워지고, 흰·파스텔 획이 굽고 나면 거의 투명해졌다.
  - 래스터는 무손실 PNG `<image>`로 싣는다(`data-brush-engine="wet-paper-bake-v1"`). PNG는 순수 JS `fflate` zlib(레벨 6, 필터 0)으로 만들어 플랫폼과 관계없이 바이트가 같다.
  - 다른 레인의 내보내기 출력은 바이트 그대로다.
- **저장 형식**: 새 문서 필드가 없다. 획에는 기존처럼 브러시 id만 저장되고, 굽기 결과는 렌더할 때 다시 만든다.

## 4. 모델

물리 모델은 아래 논문을 바탕으로 이 저장소에서 독립적으로 구현했다.

- **종이**: 문서 좌표에 고정된 시드 종이. 제품 종이 높이 샘플러에 4층 섬유 능선 노이즈를 더한다. 링크별 차단 계수 κ(섬유 나란/가로 이방성), 모세관 용량, 흡수율을 둔다.
- **물**: MoXi(Chu & Tai, SIGGRAPH 2005) D2Q9 격자 볼츠만. BGK τ=1, 링크별 κ의 다공성 부분 bounce-back, 젖음 전선 고정, 모세관 흡입·종이 기울기·가장자리 바깥 흐름 가속. Curtis et al.(SIGGRAPH 1997) 표면·흐름·모세관 3층 교환(흡수 분배, 문턱 모세관 확산, 전선 가중 증발, 건조 가속).
- **안료**: 굵은 입자와 고운 염료 두 종의 링크 단위 보존 수송(확산·상류 이류·가장자리 이동·골 미끄러짐·모세관 운반). 마를수록 빨라지는 흡착, 탈착, 착색, 지연 경화를 둔다. 가장자리 이동은 3×3 젖음 비율의 기울기만 따라 워시 안쪽에 dab 간격 줄무늬가 생기지 않는다.
- **갈필**: Chu & Tai(IEEE CG&A 2004)의 마른 붓 개념. 강모·다발 지도와 문턱 수식은 Sumi(MIT)에서 이식했다(5절).
- **합성**: Beer–Lambert(K = −ln C / D_ref, 직선 알파 변환). 문서 약 1.25 px 래스터로 굽는다. 젖음 전선은 덮임(0/1)을 [1,2,1] 이항 필터로 가로·세로 두 번 편 장(σ ≈ 1 셀, 결과의 `edge`)의 0.5 등고선이다. 안티앨리어스 반 폭은 그 점의 장 기울기(래스터 픽셀당)의 절반이라 전선 둘레가 늘 한 픽셀 폭이다.

## 5. 상한·결정성·출처

- **상한**: 셀 65,536개, 한 변 512셀, 추정 활성 셀 16,384개, 스텝 96 이하, 래스터 약 100만 픽셀. 긴 획은 셀을 굵게 잡아 격자에 맞추고, 래스터는 배율을 낮춰 상한 안에 맞춘다.
- **굽지 않는 경우(베이스 워시)**: dab 이 없을 때, 런타임 청크를 불러오지 못했을 때, 그리고 아래 두 경우다. 빈 래스터가 베이스 워시를 대신해 획이 사라지지 않게 한다.
  - 상한을 맞추려면 셀을 키워 core dab 평균 지름이 1.5셀보다 좁아지는 획(예: 굵기 4px 로 1,800px 를 그은 획). 셀 하한 1px 이 정한 해상도는 예외다. 셀이 dab 보다 굵으면 셀 중심 표본이 획을 놓치고, 셀 단위 물리가 획을 넓혔다.
  - 굽고 나서 들어간 안료가 0 이거나 덮인 셀이 없을 때.
- **셀보다 가는 dab**: 지름이 2셀보다 작은 dab 은 담긴 셀 하나에 넣는다. 물은 선이 셀을 덮는 비율(2r)만큼, 안료는 큰 dab 의 현 정규화 적분과 같은 면적(π r², 간격이 있으면 2r·간격 중 작은 값)만큼이다. 셀 경계를 따라가는 가는 가로·세로 직선이 비지 않는다.
- **메모리·시간**: 상태는 `Float32Array`다. 스텝 안에서 할당하지 않고, 4×4 타일 단위로 정확히 건너뛰며, 바깥 벽 타일로 경계 검사를 없앴다. 최대 격자 실행 시간은 성능 예산 시험(`studio-wet-paper-runtime-budget.test.ts`)이 지킨다.
  - 타일 생략은 모든 타일을 매 스텝 처리한 결과와 비트 단위로 같다. 한 번도 젖지 않은 셀의 마른 시점을 "스텝 0부터 마름"으로 두어, 지연 경화가 타일이 깬 순서에 따르지 않는다(시험이 고정한다).
  - 갈필 강모 지도는 처음 한 번 만드는 데 수십 ms 가 걸린다. 호스트는 다발 지도 32행·강모 8가닥·잡음·평활화를 한 단위씩 나눠 만들고, 동기 경로(SVG 내보내기)는 한 번에 만든다. 결과 바이트는 같다. 결정적 지수의 2^k 는 표로 구한다(반복 곱셈과 비트 단위로 같다).
- **결정성**: `Math.random`·`Date.now`를 쓰지 않고, 결과 경로에서 `Math.exp`·`Math.log`·`Math.sin` 대신 결정적 근사를 쓴다. 한 번에 굽든 조각으로 나눠 굽든 바이트가 같다.
- **획 방향**: 첫 core dab 과 그 앞 dab 도 획의 첫 진행 방향을 쓴다(현 정규화·강모 좌표). 예전에는 자리 표시 방향 (1, 0)을 받아 +x 가 아닌 획의 시작 끝이 비뚤었다.
- **이식(MIT)**: `brush/wet-paper/studio-wet-paper-bristle.ts`는 [Sumi](https://github.com/Aureliaar/sumi) 커밋 `89b8c443`의 `public/sumi.js` `buildBristleTexture`·`equalize`·`pnoise`와 `FS_DAB` 셰이더의 갈필 문턱 수식을 옮겼다. 지도 크기(128×512, 강모 64가닥, 다발 6개), 결정적 다항식, `Float32Array`와 쌍선형 샘플러로 바꿨다. 라이선스 사본과 이식 범위는 [`../../third_party/sumi/README.md`](../../third_party/sumi/README.md), 고지는 [`../../THIRD_PARTY_NOTICES.md`](../../THIRD_PARTY_NOTICES.md)에 있다.

## 6. 한계와 미구현

- 굽기는 커밋된 획에만 적용된다. 그리는 중의 라이브 초안과 썸네일은 언제나 베이스 워시다.
- 굽기가 끝나기 전 프레임은 베이스 워시를 그리므로, 획을 놓은 뒤 결과가 잠깐 늦게 바뀐다.
- 흐름층 WGSL 커널은 CPU 미러와 12스텝 동안 분포·밀도·속도가 상대 오차 1e-5 안에서 같은지만 시험했다. 제품 렌더러에 연결하지 않았고 실기기 GPU에서 실행하지 않았다.
- 젖음 전선은 셀 계단 대신 계단 가운데를 지나는 매끄러운 곡선을 따른다(실브라우저에서 먹 번짐 후광이 셀 크기 계단으로 보여 고침). 기울기 1/4 전선에서 곧은 선과의 최대 차이가 이진 덮임 1.3 px 에서 0.47 px 로 줄었다. 대신 셀 하나 폭보다 작은 돌출·구멍은 둥글게 줄어든다. 전선 안쪽 밀도는 셀 해상도의 쌍선형 보간이라, 굵은 붓에서는 셀 크기의 얼룩 결이 보일 수 있다. 백런·입자 침전 레인은 보이는 가장자리가 밀도가 0 으로 내려가는 곳이라 이번 변경의 영향이 거의 없다.
- 브러시 스튜디오 컴포저의 물리 노드 "물리 없음"·"웻 확산"은 레인에 고정된 젖은 종이 굽기를 끄지 않는다(다른 수채 레인의 레인 고정 효과와 같은 기존 의미). 컴포저 덮어쓰기가 굽기를 바꾸는 경우는 물리 "Inkwash 리빙 유체"(리빙잉크 `sumi-flow-bake`)와 표면 "섬유 방향 필드"(가장자리 번짐 `fiber-feather`)뿐이다. 굽기를 끄려면 다른 레인을 고른다.
- 내보내기 Worker 는 메인 스레드 캐시를 넘겨받지 않아, 화면에 이미 구운 획도 다시 굽고 작업량 한도를 넘으면 베이스 워시로 내보낸다. 결과를 Worker 로 넘기는 일은 남아 있다.
- 실브라우저 시각 확인은 하지 않았다. 시험은 jsdom과 순수 계산으로 했다.
- Sumi 업스트림 `LICENSE`의 저작권 줄은 템플릿 자리 표시자(`YOUR NAME`)다. 허가 문구를 바꾸지 않으려고 사본을 그대로 두었다. 저작권자 표기가 정해지면 사본을 바꾼다.
