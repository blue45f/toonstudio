## 2. 동작

- **열기**
  - 필터 ▸ 필터 갤러리…는 다른 필터와 같은 세션(`openStudioFilter("filter-gallery")`)으로 열린다.
  - 대상 규칙은 단일 필터와 같다: 선택 이미지, 선택 레이어 또는 현재 페이지 합성, 선택 영역 안/밖.
  - 세션 대화상자는 종류가 `filter-gallery`일 때만 갤러리 대화상자를 띄운다.
- **쌓기**
  - 왼쪽 목록에서 효과를 누르면 스택 맨 아래에 기본값으로 더해진다.
  - 스택은 위에서 아래 순서로 적용된다.
  - 겹마다 켜기·끄기, 위·아래 이동, 빼기, 불투명도(0~100%), 매개변수를 고친다.
  - "무늬 바꾸기"는 스택 시드를 바꿔 무작위 무늬가 있는 효과의 결과를 다시 뽑는다.
- **미리보기**
  - 캔버스 미리보기: 값이 바뀔 때마다 `{ filterGallery }` 패치로 캔버스에 바로 그린다. "캔버스 미리보기" 단추로 켜고 끈다.
  - 실제 필터 엔진이 같은 커널을 실행하므로, 미리보기와 적용 결과가 같다.
  - 대화상자 안 결과 미리보기: 대화상자가 넓어 캔버스를 대부분 가리므로 대화상자 안에도 결과를 보인다(넓은 화면은 왼쪽 열,
    좁은 화면은 위 띠).
    - 캔버스와 같은 계산이다. 요소의 문서 크기(반올림한 너비×높이)로 원본을 그리고(뒤집기 포함), 요소 필드 위에 초안
      스택을 얹어 이미지 필터 Worker 상주 세션으로 계산한다. 커널의 크기 매개변수가 이미지 px 단위라 축소본으로 계산하지
      않는다. 요소의 다른 필터도 캔버스처럼 함께 적용된다.
    - 계산은 마지막 변경 120ms 뒤 한 번에 하나씩 돌고, 도는 동안 바뀐 값은 마지막 것만 남겨 이어 돌린다.
    - "원본 비교"로 원본을, "실제 크기"로 1:1 픽셀을 스크롤해 본다.
    - 활성 이미지 필터 마스크가 있으면 Worker 결과와 원본을 캔버스의 공통 커버리지 커널로 합성한다. 마스크는 원본처럼
      콘텐츠 좌표의 좌우·상하 뒤집기를 적용한다. immutable surface의 로컬 src가 아직 없거나 마스크를 읽지 못하면
      마스크 없는 전체 결과를 표시하지 않는다. 명시적으로 꺼 둔 마스크와 활성 필터가 없는 대상은 기존 전체 계산을 유지한다.
    - Worker가 없는 환경에서는 같은 공통 작업량 판정으로 허용한 경량 스택만 direct로 계산한다. 갤러리 direct 한도를
      넘으면 기존 계산 불가 안내를 보이며, 동기 커널로 다시 실행하지 않는다.
    - 캔버스가 필터를 끄는 크기(16M 픽셀 초과)는 계산하지 않고, 작업량 상한을 넘는 스택은 빠진 결과라고 알린다. 원본을
      읽을 수 없으면(출처 제한 등) 캔버스 미리보기로 확인하라고 알린다.
  - 작업량 표시는 이 조합을 적용할 수 있는 가장 큰 이미지 크기(MP·정사각 px)를 함께 보인다(약 4000×4000 이상이면 등급만).
- **적용**
  - 이미지 대상은 요소에 `filterGallery` 필드를 저장한다(비파괴). 다시 열면 겹마다 고칠 수 있다.
  - 효과를 모두 빼고 적용하면 필드를 지운다.
  - 페이지 합성 대상은 다른 필터처럼 원본을 보존한 새 래스터 레이어로 굽는다.

## 3. 저장 형식과 실행 경로

```ts
interface StudioFilterGalleryStack {
  version: 1;          // 모르는 버전이면 실행하지 않는다
  seed: number;        // 32비트 부호 없는 정수. 겹마다 순번과 섞어 효과 시드를 만든다
  entries: {
    id: string;        // "분류.이름" (예: "artistic.dry-brush"). 문서에 저장되므로 바꾸지 않는다
    params: Record<string, number | string | boolean>;
    opacity?: number;  // 0~1, 생략하면 1
    enabled?: boolean; // false 면 건너뛴다
  }[];                 // 최대 8개
}
```

- **즉시 로드 경로**: `render/studio-konva-filter-fields.ts`는 type-only import만 둔다(모듈 경계 시험이 고정). 그래서 활성 여부는 이 파일 안의 가벼운 후보 판정(`hasActiveStudioFilterGalleryCandidate`)으로 보고, 캐시 키에 스택 전체를 넣는다.
- **정규화**: 필터 엔진 청크에 있는 등록부가 스택을 다시 정규화한다.
  - 모르는 id는 버린다.
  - 숫자는 스펙의 범위·간격에 맞춘다.
  - 선택값·색·토글은 형식을 확인한다.
  - 9번째 겹부터는 버린다.
- **실행**
  - Konva attrs에는 숫자·문자열만 실을 수 있어서 정규화된 스택을 JSON 문자열 하나(`attrs.filterGallery`)로 넘긴다. 같은 문자열은 다시 파싱하지 않는다.
  - 체인 위치는 비네트 뒤, 외곽선·테두리 앞이다.
- **예산**
  - 효과마다 픽셀당 상대 작업량 `cost`가 있다.
  - 측정상 cost 1 단위는 픽셀당 약 50ns(느린 효과는 216ns까지)다.
  - 픽셀 수 × 켜진 겹의 cost 합이 `STUDIO_FILTER_GALLERY_DIRECT_BUDGET`(512K, 약 25~110ms)을 넘으면 이미지 필터 Worker 경로를 쓴다. 메인 스레드에서 수백 ms~수 초 걸리는 스택이 편집기를 멈추지 않게 하기 위해서다.
  - `STUDIO_FILTER_GALLERY_WORK_BUDGET`(2048²×24, 가장 느린 경우 약 22초)을 넘으면 픽셀을 전혀 바꾸지 않는다. 부분 적용으로 결과가 뒤바뀌지 않게 하고, 이미지 필터 Worker 의 30초 시간 제한을 넘는 실행을 받지 않기 위해서다.
- **결정성**
  - 커널은 `Math.random`·시계를 쓰지 않는다. 모든 무작위성은 시드를 섞은 정수 해시다.
  - 그래서 같은 문서는 어느 기기, 어느 경로(Konva·Worker)에서 그려도 같은 픽셀이 된다.

## 5. 한계와 다음 차례

- 원작과 픽셀 단위로 같지 않다. 원작 코드·텍스처 이미지·프리셋을 쓰지 않았기 때문이다(캔버스·삼베·사암·벽돌·리넨·종이 재질도 절차적으로 새로 만들었다).
- 크기 매개변수는 이미지 픽셀 단위다. 축소한 미리보기 캐시와 원본 해상도에서 같은 값의 모양이 조금 다를 수 있다.
- 미구현:
  - 겹별 썸네일 미리보기
  - 사용자 프리셋 저장·공유
  - 보정 레이어(smart filter) 스택 편입
  - 효과별 GPU 경로
- 후속 원본 커밋의 기록에는 실브라우저(Playwright·Chromium, 게스트 `/studio/canvas`, 1440×900)에서 페이지 합성 대상으로
  맞춤·실제 크기·원본 비교와 작업량 안내를 확인했다고 적혀 있다. 이 과거 기록은 2026-10-31의 마스크·direct 후속 후보의
  경계 수정의 현재 검증 결과로 사용하지 않는다. 효과별 모양과 해당 브라우저 흐름도 후보에서 다시 검증해야 한다.
