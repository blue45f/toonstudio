- 상태: 1절은 기준 커밋의 **현재(current)** 사실이다. 2~9절은 이 변경(`claude/swq-fb` 브랜치)이 구현하고 테스트한 기능(current — 병합 전에는 이 브랜치에만 있다)이고,
  10절은 아직 하지 않은 일(target)과 알려진 공백(legacy exception)이다.
- 기준 커밋: `fe304a4586553f1961911a4f15bb98fa5c919685` (이 브랜치가 갈라진 지점)
- 작성일: 2026-10-16
- 대상: `/studio/ecosystem`의 "베타 독자" 구역(작가용 요약)과 `/studio/ecosystem/viewer`(독자용 폼)
- 함께 보기: [무료 우선 클라우드 AI와 창작 생태계 작업대](../user-funded-ai-and-creator-ecosystem.md)

독자가 회차마다 **재미·이해·멈춘 곳·감정·의견**을 구조화해 남기고, 작가가 여러 독자의 응답을 한 화면에서 합쳐 보는 기능이다.
**서버 저장도 DB 변경도 없다.** 기존 베타 독자 패키지의 "내보내기 JSON → 가져오기" 방식을 그대로 확장해, 응답은 독자가 만든 파일로만 오간다.

## 3. 응답 파일 계약 (current)

정본은 `apps/web/src/domains/creator/ecosystem/reader-feedback-schema.ts`의 zod strict 스키마다.
파일 하나는 `kind: "toonstudio-reader-feedback"`, `version: 1`, `exportedAt`, `responses`(1~50개)를 담는다.

| 필드 | 값 | 설명 |
| --- | --- | --- |
| `id` | `[A-Za-z0-9._:-]` 1~80자 | 응답 하나의 고유값. 같은 폼에서 **같은 작품·회차로** 고쳐 다시 내보내면 같은 값이라, 요약에서 최신 한 건으로 합쳐진다. 작품 이름이나 회차를 바꾸면 폼이 새 값을 쓴다. |
| `createdAt` | ISO 시각 | 내보낸 시각. 같은 응답(같은 `id`·같은 묶음)에서는 더 늦은 쪽이 이긴다. |
| `target` | `kind`: `package`·`work`·`manual`, `id`, `title`, `episode` | `manual`만 `id`가 없다. 패키지가 정한 대상이면 독자가 제목·회차를 바꿀 수 없다. |
| `nickname` | 문자열 또는 `null` | **선택 입력.** 20자까지. 이메일·전화번호처럼 보이면 비운다. |
| `ratings.fun`, `ratings.understanding` | `1`·`2`·`3` 또는 `null` | 3단계 척도. 처음에는 아무것도 고르지 않은 상태라 기본값이 결과를 쏠리게 하지 않는다. |
| `reading` | `unmarked` · `finished` · `left` + `point` | 읽은 정도. `left`면 멈춘 곳을 컷 번호(`cut`, 선택적으로 전체 컷 수 `cutCount`) 또는 스크롤 위치(`percent` 0~100)로 적는다. |
| `emotions` | 아래 10개 중 0~3개, 중복 없음 | 자유 입력이 없어 분포를 안정적으로 센다. |
| `comment` | 600자까지 | 한 줄로 접힌 글. 보이는 글자가 없으면(공백·보이지 않는 문자뿐이면) 의견이 아니다. |
| `spoiler` | 불리언 | 의견이 줄거리를 말하는지. 요약에서는 눌러야 펼쳐진다. |

점수·읽은 정도·감정·의견 중 **아무것도 답하지 않은 응답은 받지 않는다**(표본 수만 부풀리기 때문이다).
이메일·IP·계정 식별자 필드는 없고, 스키마가 strict라 몰래 실어 보낼 수도 없다.

감정 태그(`READER_EMOTION_IDS`와 화면 문구 `EMOTION_LABELS`):

| 값 | 한국어 | English |
| --- | --- | --- |

| `funny` | 웃김 | Funny |
| `touched` | 감동 | Touching |
| `satisfied` | 통쾌함 | Satisfying |
| `surprised` | 놀람 | Surprising |

## 5. 불러오기 방어 (current)

`reader-feedback-io.ts`의 `parseReaderFeedbackText`가 아래 순서로 거른다. 앞 단계에서 걸릴수록 뒤 단계의 비용이 들지 않는다.

1. **크기**: 파일 크기를 먼저 보고, 크면 내용을 읽지 않는다. 읽기 자체가 실패하면 "읽기 실패"로 따로 알려 다시 시도할 수 있게 한다.
2. **중첩 깊이**: 문자열을 한 번 훑어(따옴표·이스케이프를 고려) 괄호가 6단을 넘으면 `JSON.parse` 전에 거절한다.
3. **JSON.parse**: 실패하면 `not-json`.
4. **금지 키·노드 수**: 반복문으로 순회하며 `__proto__`, `constructor`, `prototype` 키가 하나라도 있으면 파일 전체를 거절하고, 값 개수가 상한을 넘어도 거절한다.
   zod의 `strictObject`는 own `__proto__` 키를 거절하지 않고 무시한다(이 저장소의 zod 4.4.3에서 실측). 그래서 스키마 앞의 이 검사가 필수이며, 검사를 건너뛰어도 스키마 출력에 그 키가 실리지 않는다는 점까지 테스트로 고정했다.
5. **kind·version**: 이전 `toonstudio-beta-feedback`이면 그 가져오기 위치를 안내하고, 더 높은 버전이면 "모르는 버전"으로 거절한다.
6. **zod strict 검증**: 알 수 없는 키, 범위 밖 숫자(`1e999` 포함), 비정수, 잘못된 id·시각·태그를 거절한다. 실패 위치는 스키마 경로만 알리고 입력의 키 이름을 되풀이하지 않는다.
7. **값 정리**: 눈에 보이지 않거나 빈 칸처럼 보이는 문자를 **목록이 아니라 유니코드 속성**으로 지운다 —
   제어(`Cc`)·서식(`Cf`)·미할당(`Cn`)·사용자 지정(`Co`)·짝 없는 서로게이트·`Default_Ignorable_Code_Point`, 그리고 속성으로 잡히지 않는 점자 빈칸(U+2800)과 객체 대체 문자(U+FFFC).
   방향 전환 문자(U+202E, U+061C, U+2066 등)·제로폭 문자·한글 채움 문자(U+3164, U+FFA0, U+115F, U+1160)·소프트 하이픈·결합 문자 접합자·태그 문자(보이지 않는 글을 실을 수 있다)·변형 선택자가 여기에 든다.
   **이모지는 보존한다**: 제로폭 접합자(ZWJ)는 이모지 사이에서만(👨‍👩‍👧, ❤️‍🔥이 갈라지지 않게), 표시 선택자(U+FE0F·U+FE0E)는 이모지 바로 뒤에서만 남기고, 그 밖의 ZWJ·ZWNJ와 겹치거나 홀로 있는 선택자는 지운다.
   보이는 글자(문자·숫자·구두점·기호)가 하나도 없는 의견·닉네임·작품 이름은 빈 값으로 본다. 줄바꿈은 공백으로 접고, 이메일·전화번호처럼 보이는 글은 `[연락처 가림]`으로 바꾼다(닉네임은 통째로 비운다).
   지우는 순서가 먼저라 보이지 않는 문자로 쪼갠 연락처도 가려지고, 길이를 자른 뒤에도 한 번 더 정리해 이미 정리된 값을 다시 정리해도 같다. 정규식 반복 횟수에는 상한을 두었다.

**XSS**: 사용자 문자열은 React 텍스트 노드로만 그린다. `dangerouslySetInnerHTML`, 사용자 값으로 만든 `href`·속성·`id`를 쓰지 않는다. HTML·`javascript:` 조각이 들어 있어도 요소가 되지 않고 글자 그대로 보인다는 것을 폼·요약 화면 테스트가 확인한다.
사용자 문자열을 객체 키로 쓰지 않는다(묶음은 `Map`).

**서버 전송 없음**: 이 기능의 소스는 `fetch`·`XMLHttpRequest`·`sendBeacon` 같은 네트워크 API와 HTML 문자열을 심는 API를 쓰지 않고,
가져오는 외부 모듈도 허용 목록(`react`, `react-router-dom`, `lucide-react`, `zod`, 공용 문구·유틸리티)뿐이고 같은 도메인에서는 파일 내려받기 도우미(`ecosystem-preview`)만 쓴다. 목록을 늘리려면 외부 전송·개인정보 영향을 검토하고 시험과 이 문서를 함께 고친다.
독자가 쓴 제목·닉네임·의견·파일 이름은 번역 문구 사전에도 브라우저 저장소에도 들어가지 않는다. 기존 런타임 번역은 문구 사전에 등록된 원문을 외부 번역 서비스로 보낼 수 있어서,
값이 끼는 문구는 `{이름}` 자리표시자로 두고(8절) 값 자체는 번역 뒤에 끼운다. 숨김이 기억하는 것은 응답 id 뿐이다.

이 약속은 소스를 문법 트리로 읽는 시험(`reader-feedback-privacy.test.tsx`)이 지킨다. 네트워크 API는 호출뿐 아니라 이름이 나오는 곳 전부(`window["fetch"]` 같은 문자열 키, `const send = fetch` 같은 별칭, `new Request`)를 찾고,
브라우저가 스스로 주소를 불러오거나 폼을 보내는 JSX(`<img src>`, `<iframe src>`, `<link href>`, `<form action>`, `formAction`, `ping` …)도 찾는다. 검사는 이 기능의 파일뿐 아니라 폼을 품은 뷰어 화면(`CreatorEcosystemViewerPage`)과 파일 내려받기 도우미(`ecosystem-preview`)에도 똑같이 적용한다.
허용 목록에는 뷰어가 패키지의 미리보기를 그리는 `<img src>` 두 곳뿐이고, 그 값은 패키지 스키마가 `data:image/(png|jpeg|webp);base64,…`로만 받는다는 것도 시험으로 고정했다. 정규식이 아니라 문법 트리를 읽으므로 주석과 문구에 적힌 말은 걸리지 않는다.

연락처 가림은 휴리스틱이다. 날짜(`2026-10-16`, `20261016`)나 컷 번호는 건드리지 않지만, 개인정보를 모두 찾아낸다고 약속하지 않는다.

## 6. 합치기와 중복 제거 (current)

`reader-feedback-summary.ts`의 `mergeReaderFeedback`:

- 같은 응답 = 같은 `id` **그리고 같은 묶음**(대상+회차, 7절): 더 늦게 만든 응답이 이긴다(갱신). 같거나 오래되면 중복이다.
  `id`가 같아도 묶음이 다르면 서로 다른 응답이다. 옛 폼은 작품 이름·회차만 바꿔 다시 내보내도 `id`를 그대로 이어서, `id`만으로 합치면 앞선 회차의 응답이 조용히 사라졌다.
  지금 폼은 묶음이 바뀌면 새 `id`를 쓰고, 합치기도 그렇게 내보낸 옛 파일을 잃지 않는다(숨김 표시는 `id` 단위라, 옛 파일처럼 `id`가 같은 다른 회차 응답은 함께 숨겨진다).
- 다른 응답이라도 대상·회차·닉네임·점수·읽은 정도·감정·의견·스포일러가 모두 같고 **의견이 8자 이상**이면 중복이다(`CONTENT_DEDUPE_MIN_COMMENT`).
  점수와 선택지만 있는 응답은 서로 다른 독자가 똑같이 고르기 쉬워서(예: 모두 3점에 끝까지 읽음) 내용이 같다는 이유로 지우지 않는다. 그런 응답은 같은 독자가 새 `id`로 다시 보내면 중복으로 잡지 못한다.
- 한 번에 들어온 같은 응답(같은 `id`·같은 묶음)의 여러 버전은 하나만 남는다.
- 총 1000개를 넘으면 기존 응답을 지키고 새 응답을 받지 않는다(이미 있는 응답의 새 버전으로 바꾸는 것은 막지 않는다).
- 결과는 만든 시각 순(같으면 `id` 순)이고, 입력 배열은 바꾸지 않는다.

화면은 "응답 N개 추가 · N개 갱신 · 중복 N개 제외"와 열지 못한 파일 수를 알린다.

## 7. 요약 계산 (current)

회차 묶음은 대상 `id`와 회차로 정한다. 직접 적은 작품 이름은 대소문자·전각·공백 차이를 무시한다.

| 항목 | 규칙 |
| --- | --- |
| 평균 | 1~3 척도를 답한 사람만의 평균. 답한 사람이 없으면 `—`. |
| 분포 | 단계별 개수. 개수는 항상 글자로 쓴다. |
| 끝까지 읽음 | 읽은 정도를 밝힌(끝까지+중간에 멈춤) 사람 중 비율. |
| 멈춘 곳 | 컷 번호와 스크롤 위치를 **섞지 않고** 따로 센다. 최빈 구간이 동률이면 모두 최빈으로 본다. 컷 번호는 전체 컷 수(알면)까지 축을 잡아 20구간 이하로 묶고, 스크롤은 10%씩 10구간이다. |
| 감정 | 고른 사람 수, 많은 순(같으면 위 표의 순서). |
| 표본 등급 | 5개 미만 `tiny`, 30개 미만 `small`, 그 이상 `moderate`. 통계적 기준이 아니라 읽는 사람을 위한 경고선이다. |
| 비율(%) | 그 비율의 분모, 곧 **그 질문에 답한 사람이 10명 이상일 때만** 보인다(재미·이해 분포는 각 질문에 답한 사람 수, 끝까지 읽음은 읽은 정도를 밝힌 사람 수, 감정은 전체 응답 수, 멈춘 곳은 그 방식으로 알린 응답 수). 그보다 적으면 개수만 보여(끝까지 읽음은 `3/5`처럼) 가짜 정밀도를 피한다. 응답이 10개를 넘어도 한 명만 답한 질문에 "100%"를 만들지 않는다. |

**대표 의견**은 다수결이 아니다. 숨긴 의견과 같은 말(구두점·대소문자만 다른 의견)은 빼고, 스포일러 아닌 의견·더 자세한 의견·더 최근 의견 순으로 줄을 세운 뒤
문제 신호(별로·헷갈림·중간에 멈춤) 하나와 긍정 신호(재밌었고 이해가 낮지 않음) 하나를 먼저 뽑고 남은 자리를 채워 최대 5개를 보인다.
스포일러 의견은 자리가 남을 때만 들어가며 눌러야 펼쳐진다. 의견 전체와 숨긴 의견은 각각 접힌 목록으로 볼 수 있다.

**숨김**은 이 브라우저에만 남는 표시(`toonspectrum:reader-feedback-hidden:v1`, 응답 id 1000개까지)다. 집계 숫자를 바꾸지 않고 파일로 내보내지도 않는다.
저장소가 막혀 있으면 이 화면을 닫을 때까지만 유지된다고 알린다.

## 8. 화면 상태와 접근성 (current)

| 상태 | 처리 |
| --- | --- |
| 비어 있음 | 사용 순서 3단계와 독자용 화면 링크, "예시 응답으로 체험하기"를 보인다. |
| 읽는 중 | `role="status"`, `aria-busy`, 스켈레톤. 모션 감소 설정이면 펄스를 멈춘다. 읽는 중에 "가져온 응답 비우기"를 누르면 그때 읽고 있던 파일의 결과는 버리고(비운 뒤에 새로 시작한 가져오기는 받는다), 읽는 중 표시도 함께 끈다. |
| 오류 | 파일별로 이름과 사유(빈 파일·너무 큼·JSON 아님·복잡함·허용되지 않는 항목·이전 형식·모르는 버전·형식 오류+위치)를 보인다. 나머지 파일은 계속 가져온다. |
| 다시 시도 | 읽기 자체가 실패한 파일에만 "다시 시도"를 둔다. 형식 오류는 다시 읽어도 같으므로 두지 않는다. |
| 붙여넣기 | 같은 검증을 거치고 실패하면 입력을 지우지 않는다. |

- 모든 입력은 `label`로 이름이 있고, 라디오·체크박스는 `fieldset`+`legend`로 묶인다. 선택 여부는 색뿐 아니라 체크 표시로도 드러난다.
- 오류는 필드 옆 문구(`aria-describedby`, `aria-invalid`)와 요약 `role="alert"`로 알리고, 저장에 실패하면 첫 문제 칸으로 초점을 옮긴다.
- 이탈 지점 그래프는 SVG(`role="img"`, 제목·설명)이며 값이 있는 칸 **위의 별도 줄**에 개수 글자를 쓴다. 글자가 칸 색 위에 놓이지 않아 칸 색의 농도와 무관하게 본문 글자(`fg`)와 같은 대비를 따른다. 같은 내용을 "표로 보기"(`details`, 캡션이 있는 `table`)로도 준다.
  강제 색상처럼 색이 무시되는 환경에서는 이 표가 대안이다.
- 회차 비교표의 회차 이름은 버튼이고 선택한 행에 `aria-current`가 붙는다. 터치 대상은 44px 이상이다.
  "가장 많이 멈춘 곳"이 동률이면 첫 구간만 보이지 않고 `3컷 외 1곳 동률 (각 2명)`처럼 동률인 곳 수와 인원을 함께 보인다(자세한 요약은 동률 구간을 모두 나열한다).
- 독자·패키지가 쓴 글(작품 이름·닉네임·파일 이름)은 `<bdi>`로, 의견 문단은 `dir="auto"`와 `<bdi>`로 격리해 그린다. 오른쪽에서 왼쪽으로 쓰는 글이 뒤따르는 "1화"나 구분 기호의 순서를 흩지 않는다.
- 폼 제목의 수준은 놓이는 곳에 맞춘다(`headingLevel`): 패키지 제목(h2) 아래에서는 h3, 패키지를 열지 않아 페이지 제목(h1) 바로 아래에 놓이는 뷰어에서는 h2 라서 제목 수준을 건너뛰지 않는다(axe `heading-order`).
- 한 줄 입력에서 Enter 를 눌러 폼이 제출돼도 파일이 저장되지 않는다. 저장은 "파일로 저장" 단추를 눌러서만 하고(단추는 Enter·Space 로 누를 수 있다), 답을 마치기 전에 파일이 내려가는 일을 막는다.
- 누르면 사라지는 단추는 초점을 body 로 떨어뜨리지 않는다: "선택 취소"는 그 묶음의 첫 선택지로, "새 의견 쓰기"는 첫 입력으로, 의견 "숨기기·다시 보이기"는 같은 목록의 이웃 의견 단추(이웃이 없으면 "대표 의견" 제목)로 초점을 옮기고 결과를 `role="status"` 안내로 알린다.
  "스포일러 보기"는 사라지지 않고 그 자리에 남아(`aria-expanded`) 다시 눌러 가릴 수 있다.
- 이탈 지점 그래프가 좁은 화면에서 가로로 밀리면 그 영역 자체가 키보드 초점을 받는다(`role="region"`, 이름에 "좌우로 스크롤"). 안에 초점을 받는 요소가 없어 키보드로 밀 수 없던 문제(axe `scrollable-region-focusable`)를 막는다. jsdom 은 레이아웃을 계산하지 않아 규칙 자체는 시험으로 돌리지 못하고, 영역의 `tabindex`·역할·이름만 고정했다.
- 색은 의미 토큰만 쓴다(`accent`, `raised`, `fg`, `warn` 등). 새 색을 만들지 않았다.
- 문구는 한국어/영어 쌍(`useBilingual("ReaderFeedback")`)이며, 값이 끼는 문구는 `{이름}` 자리표시자로 두어 값마다 번역 키가 생기지 않게 했다. 다른 언어는 기존 런타임 번역을 따른다.
  `bt()`에 값을 끼운 템플릿 문자열을 넘기지 않는다는 것은 소스를 문법 트리로 읽는 시험(`reader-feedback-privacy.test.tsx`)이 확인한다.
  연락처 안내가 말하는 가림 표시는 코드의 `CONTACT_MASK`를 자리표시자로 채워, 영어 화면에서도 파일에 실제로 담기는 값(`[연락처 가림]`, 영어 화면에서는 뜻풀이를 덧붙임)과 같다. 이름이 빈 가져오기 파일은 화면이 번역한 대체 이름("(이름 없음)")으로 보인다.

## 9. 한계와 해석 주의 (current)

이 요약은 화면에 항상 같은 안내를 띄운다(`aside`, "읽기 전에").

- **자체 선택 응답**: 파일을 보내 준 독자만의 의견이다. 읽은 사람 전체를 대표하지 않는다.
- **이탈 과소 추정**: 끝까지 읽지 않은 독자는 응답하지 않았을 가능성이 높아 멈춘 곳이 실제보다 적게 보일 수 있다.
- **작은 표본**: 응답이 적으면 평균과 분포가 한두 명에 좌우된다. 신뢰구간이나 유의성은 계산하지 않는다.
- **위조 가능**: 파일은 누구나 만들거나 고칠 수 있다. 서명이나 진위 확인이 없고, 닉네임은 신원 확인이 아니다. 같은 사람이 여러 번 보내거나 서로 다른 사람이 같은 닉네임을 쓸 수 있다.
- **글자 모양 손실**: 표시 위장을 막으려 이모지 밖의 제로폭 문자를 모두 지우므로, ZWNJ로 글자 모양을 정하는 글(예: 페르시아어)은 모양이 달라질 수 있다.
  미할당 글자는 실행 환경의 유니코드 버전 기준이라, 더 새 버전에서 배정된 글자는 지워질 수 있다. 태그 문자로 이은 지역 깃발(🏴 뒤의 영국 지역 깃발 등)은 기본 깃발로 줄어든다.
- **회차 구분**: 패키지를 다시 내보내면 `id`가 새로 생겨 같은 제목의 묶음이 둘 보일 수 있다(제목·회차가 같으면 `id` 끝 네 글자로 구분해 보인다).

## 10. 아직 하지 않은 일 (target)과 알려진 공백 (legacy exception)

- 공개 작품 독자 화면(`PublishedWorkReader`)에는 폼을 연결하지 않았다. 서버 저장 없는 파일 교환은 베타 검토에 맞는 흐름이고, 공개 독자 화면의 성능 예산과 서버 기반 리뷰·댓글과의 역할 분담은 별도 결정이 필요하다.
- 가져온 응답은 이 화면의 메모리에만 있어 화면을 떠나면 사라진다(파일이 정본이다). "이 브라우저에 보관"은 저장 한도·개인정보 정책을 정한 뒤 선택 기능으로 추가해야 한다.
- 요약을 파일(CSV·JSON)로 내보내는 기능이 없다.
- 이전 5점 척도 응답(`toonstudio-beta-feedback`)은 이 요약에 합치지 않는다. 척도가 달라 억지로 환산하면 오해를 부른다.
- 패키지가 정한 대상의 `id`는 패키지 쪽 규칙(1~200자 아무 문자열)을 따르지만, 이 기능의 응답 `id`는 영문·숫자·`._:-` 80자 이하여야 한다.
  앱이 만든 패키지(UUID)는 맞는다. 직접 고친 패키지의 `id`가 이 규칙을 벗어나거나 제목이 공백뿐이면 폼이 저장하지 못하고 "입력한 내용을 파일로 만들지 못했어요"만 보인다.
  원인을 알려 주는 안내나 직접 적는 대상(`manual`)으로의 대체는 아직 없다.
- 컷 번호는 패키지가 알려 준 전체 컷 수(이미지 패키지는 프레임 수, 텍스트 패키지는 페이지 이름 수)를 쓴다. 컷을 자동으로 세지 못하는 작품에서는 스크롤 위치를 쓴다.
- 영어·한국어 외 언어는 기존 런타임 번역에 의존하며 이 기능의 문구를 따로 검수하지 않았다.
- 뷰어 페이지(`CreatorEcosystemViewerPage`)의 기존 문구는 한국어 고정이다. 이 기능이 더한 문구(텍스트 검토 패키지 안내, "패키지 없이 회차 피드백만 남기기")만 쌍으로 써서 폼과 같은 언어로 보이고, 나머지(제목·파일 열기·이미지 검토 폼 등)는 영어 화면에서도 한국어로 남는다. 그 페이지 전체의 이관은 별도 작업이다.
- 실제 브라우저에서의 레이아웃·대비·모바일 확인은 컴포넌트 테스트가 아니라 별도 UI/UX 단계에서 한다.
