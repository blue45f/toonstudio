# 기억으로 작품 찾기

작성 기준일: 2026-10-16 · 대상: 작품 탐색 허브(`/discover`)의 접힌 안내 "제목이 기억나지 않으세요?"

이 문서는 제목이 기억나지 않을 때 장면·줄거리로 후보를 찾는 기능의 **현재 구현(current)**, 확신 단계의 정의, 한계를 나눠 적는다.
참조 사이트 분석(`reports/reference-sites-plotr-1toon-benchmark-2026-10-16.md`)에서 나온 아이디어를 독립적으로 구현한 것이며, 참조한 사이트의 문구·코드·이미지는 쓰지 않았다.

## 1. 상태 요약

| 항목 | 상태 |
| --- | --- |
| 입력 폼(제목 기억 정도·제목 조각·장면·시기) | current |
| 근거 표시(어느 단서가 어디와 맞았는지) | current |
| 확신 3단계(확인된 일치·추정 일치·약한 후보)와 "못 찾음" | current |
| 서버 변환·새 API·새 마이그레이션 | 없음 — 기존 카탈로그 검색 API(`/api/search`)의 첫 쪽만 쓴다 |
| 결말·작가 근황 같은 정보 | 제공하지 않는다(데이터가 없다) |
| 실제 사용자 데이터로 적중률 측정 | 하지 못했다 |

## 2. 사용 방법

`/discover`의 "제목이 기억나지 않으세요?"를 펼치면 폼이 내려받아진다(접혀 있는 동안은 코드도 받지 않는다).

1. **제목을 얼마나 기억하세요?** — 전혀(기본)·일부만·정확히. 전혀를 고르면 제목 칸이 나타나지 않는다.
2. **기억나는 장면이나 줄거리(필수)** — 두 글자 이상의 구체적인 낱말(인물·소품·장소)이 있을수록 잘 찾는다. 한 글자 낱말과 "주인공"·"장면" 같은 어디에나 나오는 말은 단서로 쓰지 않는다.
3. **대략 언제 보셨나요?(선택)** — 5구간. 걸러 내는 조건이 아니라 근거가 이미 있을 때만 거드는 참고다. 기억이 틀려도 후보에서 빠지지 않는다.

## 3. 확신 단계 — 이 기능이 지키는 약속

점수는 정렬에만 쓰고 사용자에게 퍼센트로 보이지 않는다. 시놉시스가 서비스가 직접 쓴 1~3문장 요약이라 점수가 정확도처럼 읽히면 안 된다.

| 단계 | 배지 | 조건 |
| --- | --- | --- |
| 확인된 일치 | `확인된 일치`(초록) | 사용자가 쓴 **제목 조각**이 제목 또는 다른 이름과 맞았다(두 글자 이상) |
| 추정 일치 | `추정 일치`(주황) | 제목은 확인되지 않았고, 장면 낱말이 둘 이상 겹치거나 한 낱말이라도 제목·다른 이름·작가에서 맞았다 |
| 약한 후보 | `약한 후보`(주황) | 장면 낱말 하나가 태그·장르·소개에서만 겹쳤다 |
| 못 찾음 | 배지 없음 | 근거가 하나도 없다. "맞는 작품을 찾지 못했어요"라고 말하고 제목 조각 검색·장르 탐색으로 안내한다 |

- 결과마다 근거 칩이 붙는다: "제목에 ‘…’", "다른 이름에 ‘…’", "작가·그림 이름에 ‘…’", "태그에 ‘…’", "장르에 ‘…’", "소개에 ‘…’", "보신 시기(…)와 가까워요".
- 결과 제목 아래에 "‘추정’은 제목이 아니라 장면·태그 같은 단서가 겹쳤다는 뜻이에요. 맞는지는 작품을 열어 직접 확인해야 해요."를 항상 둔다.
- 시기만 맞는 작품은 후보가 되지 못한다.
- 결과 목록은 최대 12편이다.

## 4. 구조

| 파일 | 역할 |
| --- | --- |
| `apps/web/src/domains/catalog/memory-finder/memory-finder-model.ts` | 순수 모델: 낱말 추출(조사를 뗀 형태 포함)·검색 질의 조립·작품별 근거 대조·정렬·전체 단계 |
| `apps/web/src/domains/catalog/memory-finder/MemoryFinderSection.tsx` | 폼·진행·오류·결과 표시(요청 중단, 결과 제목으로 초점 이동, `aria-live`) |
| `apps/web/src/shared/components/ui/honesty-badge.tsx` | 정직 표기 배지: 확인됨·추정·확인 못 함을 색이 아니라 글자와 모양으로 말한다 |
| `apps/web/src/domains/catalog/DiscoverHubPage.tsx` | 접힌 안내와 첫 펼침 때의 지연 로딩 |

질의는 제목 조각과 장면 낱말(조사를 뗀 형태 포함)을 이어 붙여 기존 검색 API에 한 번 보낸다. 서버 점수는 낱말별 합산(OR)이라 후보를 넓게 가져오고, 브라우저에서 가져온 작품을 다시 단서와 대조해 근거를 만든다.

## 5. 개인정보

이 기능은 입력을 저장하거나 계정에 연결하지 않는다. 검색에 쓰이는 낱말은 일반 검색과 같은 방식으로 서버에 전달돼 처리된다 — 화면도 같은 문장으로 알린다.

## 6. 한계 — 확인하지 못한 것

- **적중률을 측정하지 않았다.** 카탈로그 규모·시놉시스 품질에 따라 장면 단서로 찾을 수 있는 비율은 크게 다를 수 있다. 구현 뒤 실제 사용에서 "못 찾음" 비율을 봐야 한다.
- 시놉시스 요약이 짧아 장면 하나만으로는 후보가 없을 수 있다(화면에 같은 문장으로 알린다).
- 한국어 조사는 "붙인 형태와 뗀 형태를 모두 시도"하는 규칙으로만 다룬다. 형태소 분석이 아니므로 "고양이"는 "고양"으로도 시도되어 드물게 엉뚱한 부분 일치가 생길 수 있다. 그 경우도 근거 칩에 사용자가 쓴 말이 그대로 보여 틀린 근거를 알아볼 수 있다.
- 서버 검색이 첫 24건만 가져오므로 서버 점수 밖의 작품은 대조 대상이 되지 못한다.
- 실제 화면 읽기 프로그램·모바일 기기에서의 확인은 하지 않았다(jsdom 시험만).
