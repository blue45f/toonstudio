# 기억으로 작품 찾기

작성 기준일: 2026-10-16 · 대상: 작품 탐색 허브(`/discover`)의 접힌 안내 "제목이 기억나지 않으세요?"

이 문서는 제목이 기억나지 않을 때 장면·줄거리로 후보를 찾는 기능의 **현재 구현(current)**, 확신 단계의 정의, 한계를 나눠 적는다.
참조 사이트 분석(`reports/reference-sites-plotr-1toon-benchmark-2026-10-16.md`)에서 나온 아이디어를 독립적으로 구현한 것이며, 참조한 사이트의 문구·코드·이미지는 쓰지 않았다.

## 1. 상태 요약

| 항목 | 상태 |
| --- | --- |
| 입력 폼(제목 기억 정도·제목 조각·장면) | current |
| 근거 표시(어느 단서가 어디와 맞았는지) | current |
| 확신 3단계(확인된 일치·추정 일치·약한 후보)와 "못 찾음" | current |
| 시기(언제 보셨나요) 입력 | **없앴다** — 카탈로그의 출시 연도가 자리표시값이 많아 근거로 쓸 수 없다(§6) |
| 서버 변환·새 API·새 마이그레이션 | 없음 — 기존 카탈로그 검색 API(`/api/search`)의 첫 쪽(24편)만 쓴다 |
| 결말·작가 근황 같은 정보 | 제공하지 않는다(데이터가 없다) |
| 실제 사용자 데이터로 적중률 측정 | 하지 못했다 |

## 2. 사용 방법

`/discover`의 "제목이 기억나지 않으세요?"를 펼치면 폼이 내려받아진다(접혀 있는 동안은 코드도 받지 않는다. 내려받기에 실패하면 한 번 자동 복구한다).

1. **제목을 얼마나 기억하세요?** — 전혀(기본)·일부만·정확히. 전혀를 고르면 제목 칸이 나타나지 않는다.
2. **기억나는 장면이나 줄거리(필수)** — 두 글자 이상의 구체적인 낱말(인물·소품·장소)이 있을수록 잘 찾는다. 한 글자 낱말과 "같이"·"장면"·"주인공" 같은 어디에나 나오는 말, 영어 기능어(the·and 등), "ㅠㅠ" 같은 자모뿐인 말은 단서로 쓰지 않는다. 낱말은 앞의 8개까지만 쓰며, 넘치면 화면이 그렇게 알린다.

## 3. 확신 단계 — 이 기능이 지키는 약속

점수는 정렬에만 쓰고 사용자에게 퍼센트로 보이지 않는다.

| 단계 | 배지 | 조건 |
| --- | --- | --- |
| 확인된 일치 | `확인된 일치`(초록) | 사용자가 쓴 **제목 조각**이 제목 또는 다른 이름과 맞았다. "일부만"은 낱말 안에 그대로 들어 있거나 띄어쓰기를 빼서 4글자 이상 맞은 경우, "정확히"는 정규화한 뒤 **같은** 제목일 때만 |
| 추정 일치 | `추정 일치`(주황) | 제목은 확인되지 않았고, ① **서로 다른 내용어 둘 이상**이 제목·다른 이름·태그·소개에서 겹쳤거나 ② 제목 조각이 띄어쓰기를 무시해야만(그리고 3글자 이하로) 맞았거나 "정확히"인데 제목에 들어 있기만 하다 |
| 약한 후보 | `약한 후보`(주황) | 장면 낱말 하나가 겹쳤다(어느 칸이든, 제목이어도). 작가 이름만 겹친 경우도 여기다 |
| 못 찾음 | 배지 없음 | 근거가 하나도 없다. 장르만 겹친 것도 근거가 아니다. "맞는 작품을 찾지 못했어요"라고 말하고 제목 조각 검색(제목 조각을 넘겨 준다)·장르 탐색으로 안내한다 |

- 결과마다 근거 칩이 붙는다: "제목에 ‘…’", "제목에서 띄어쓰기를 빼면 ‘…’", "다른 이름에 ‘…’", "작가·그림 이름에 ‘…’", "태그에 ‘…’", "장르에 ‘…’", "소개에 ‘…’". **칩의 글자는 실제로 맞은 형태다** — "하늘을"을 쓰고 조사를 뗀 "하늘"이 맞았으면 "하늘"을 보인다.
- "서로 다른 내용어"를 셀 때: "우산을"·"우산이"처럼 조사만 다른 말은 하나로, "마법"과 "마법사"처럼 한쪽이 다른 쪽의 일부면 긴 쪽 하나로 센다. 장르와 작가 이름은 변별력이 낮아 세지 않는다.
- 낱말 경계: 낱말은 띄어쓰기를 지킨 채 대조한다("학교"가 "입학 교실"의 두 낱말에 걸쳐 맞지 않는다). 영문·숫자 낱말은 낱말 시작에서만 맞춘다("art"가 "party"에 맞지 않는다).
- 머리말의 편수는 **가장 확실한 단계만** 센다("제목 조각과 맞는 작품을 찾았어요 (3편)"). 나머지는 "그 밖에 …" 소제목 아래 따로 묶는다.
- 추정·약한 후보가 한 편이라도 있으면 "‘추정’과 ‘약한 후보’는 제목이 아니라 장면·태그 같은 단서가 겹쳤다는 뜻이에요. 맞는지는 작품을 열어 직접 확인해야 해요."를 둔다.
- 결과 목록은 최대 12편이다.

## 4. 구조

| 파일 | 역할 |
| --- | --- |
| `apps/web/src/domains/catalog/memory-finder/memory-finder-model.ts` | 순수 모델: 낱말 추출(조사·어미를 뗀 형태 포함)·검색 질의 조립·소개 자동 문구 제외·작품별 근거 대조·정렬·단계별 편수 |
| `apps/web/src/domains/catalog/memory-finder/MemoryFinderSection.tsx` | 폼·진행·오류·결과 표시(요청 중단, 결과 제목으로 초점 이동 또는 조용한 알림, 단계별 묶음) |
| `apps/web/src/shared/components/ui/honesty-badge.tsx` | 정직 표기 배지: 확인됨·추정·확인 못 함을 색이 아니라 글자와 모양으로 말한다 |
| `apps/web/src/domains/catalog/DiscoverHubPage.tsx` | 접힌 안내와 첫 펼침 때의 지연 로딩(`lazyRetry`) |

질의는 제목 조각과 장면 낱말(조사를 뗀 형태 포함)을 이어 붙여 기존 검색 API에 한 번 보낸다. 서버 점수는 낱말별 합산(OR)이라 후보를 넓게 가져오고, 브라우저에서 가져온 작품을 다시 단서와 대조해 근거를 만든다.

## 5. 개인정보

이 기능은 입력을 저장하거나 계정에 연결하지 않는다. 검색에 쓰이는 낱말은 일반 검색과 같은 방식으로 서버에 전달돼 처리된다 — 화면도 같은 문장으로 알린다.

## 6. 한계 — 확인하지 못한 것과 측정한 사실

**카탈로그 데이터 (2026-10-16, 저장소에 커밋된 스냅샷 `apps/api/data/catalog.json.gz` 60,234편을 직접 센 값).** 운영 카탈로그가 같다는 보장은 없다.

- 소개의 83.7%(50,420편)가 "{제목} · {출처 표기}." 꼴의 자동 문구다. 틀은 17종뿐이고(예: "네이버 시리즈 인기 웹소설.", "교보문고 공개 카탈로그 수집작.") 장면에 대해 아무것도 말하지 않는다. 그대로 비교하면 "네이버"·"인기"·"시리즈" 같은 낱말이 가짜 근거가 되므로(소개의 56~63%에 들어 있다) **대조에서 뺀다**. 서술형 소개는 약 9,800편(16.3%)이고, 태그가 있는 작품은 36.5%다. 자동 문구이면서 태그도 없어 제목·작가·장르만 신호인 작품이 62.1%다.
- 그래서 장면만으로는 못 찾는 작품이 많다. 화면도 "소개가 비어 있거나 출처 표기뿐인 작품은 제목·태그·장르로만 비교해요"라고 알린다.
- 출시 연도는 58.5%가 2022, 네이버웹툰 3,774편은 전부 2024인 자리표시값이다 → 시기 입력과 근거를 두지 않는다.
- 다른 이름(`altTitles`)은 한 편도 채워져 있지 않다. 코드는 있으면 쓰지만 없는 것을 전제로 하지 않는다.

**측정과 검증.**

- **적중률을 측정하지 않았다.** 실제 사용자 입력이 없다. 직접 만든 12개 장면을 위 카탈로그에 서버와 같은 점수기(`packages/core/src/search.ts`, 첫 24건)로 돌려 단계 분포만 확인했다: 약한 후보 8·추정 2·확인 2·못 찾음 0. 같은 12개를 이전 규칙(제목·작가에 낱말 하나만 부분 일치해도 추정)으로 돌리면 10개가 "추정 일치 12편"이었고 약한 후보·못 찾음은 한 번도 나오지 않았다(나머지 2개는 제목 조각을 준 경우의 확인) — 단계가 정보를 못 줬다.
- 한국어 조사·어미는 "붙인 형태와 뗀 형태를 모두 시도"하는 규칙으로만 다룬다(겹조사 "학교에서는", "복수하는"→"복수" 포함). 형태소 분석이 아니므로 "고양이"는 "고양"으로도 시도되어 드물게 엉뚱한 부분 일치("고양시")가 생길 수 있다. 그 경우도 근거 칩에 실제로 맞은 말이 그대로 보여 틀린 근거를 알아볼 수 있다. "회귀해서"처럼 명사+하다 외의 어미 활용은 다루지 않는다.
- 서버 검색이 첫 24건만 가져오므로 서버 점수 밖의 작품은 대조 대상이 되지 못한다.
- 실제 화면 읽기 프로그램·모바일 기기에서의 확인은 하지 않았다(jsdom 시험만).
