# 캐릭터 앵커 연구실 — 턴테이블 앵커와 후보 이미지 휴리스틱 점검

- 상태: **current(Labs·experimental)** — 소스와 테스트로 확인되는 현재 동작이다. 사람이 실제 브라우저에서 조작해 본 결과와 실제 작품으로 점수를 검증한 결과는 없다(→ "검증 범위").
- 확인일: 2026-10-22 (`apps/web/src/domains/creator/anchor-consistency/`)
- 범위: 3D 캐릭터의 정/반측 턴테이블 앵커 세트 사양·읽기·점검·내보내기, 앵커와 샷 포즈·구도 이미지를 AI 컴포저 이미지 참조 팩(v1)에 더하는 어댑터, 후보 이미지와 앵커의 휴리스틱 참고 점수, 이 기능을 여는 Labs 화면(`/studio/anchor-lab`). 편집기 호스트·AI 컴포저 화면에 직접 연결하는 일은 범위 밖이며 하지 않았다(→ "현재와 목표").
- **한계 고지(이 문서와 화면 어디에서도 바뀌지 않는다):** 앵커를 써도 컷마다 같은 캐릭터로 그려진다는 **보장은 없다.** 점수는 같은 캐릭터인지 **판정하지 않는** 휴리스틱 참고 값이다. 이미지 생성 쪽도 같은 한계를 이미 밝히고 있다(`services/creator-inference/README.md` 의 "shot 간 character consistency를 보장하지 않는다", "face·hand·character identity를 수학적으로 보장하지 않는다").

## 현재와 목표

### 현재(current)

- 화면은 독립된 Labs 페이지다. 편집기 호스트·AI 컴포저·샷 보드와 연결하지 않는다.
- 앵커 이미지는 사용자가 3D 작업에서 저장해 둔 이미지를 **각도 칸에 끌어다 놓거나 골라서** 넣는다. 여러 장을 한꺼번에 놓으면 파일 이름에서 각도가 하나로 정해질 때만 칸에 넣고(예: `front`, `left-3-4`, `정면`), 정하지 못한 파일은 넣지 않고 개수를 알린다. 짐작으로 넣은 각도는 확인해 달라고 안내한다. 내보낸 파일 이름 규칙(`<앵커id>.<각도>.<해시 8자>.<확장자>`)과 정확히 맞는 이름은 짐작이 아니라 규칙 읽기로 처리한다.
- 읽기는 각도를 정본 순서로 **한 번에 하나씩** 진행하고, 진행 표시·취소·실패한 칸만 다시 시도를 지원한다. 읽는 동안에는 새 파일을 받지 않는다.

### 목표(target) — 이번에 하지 않았다

1. **3D 스테이지 자동 캡처.** 읽기 세션의 출처는 `AnchorFrameSource` 인터페이스 하나로 추상화되어 있어(`kind: "stage" | "file"`), 스테이지 출처를 같은 인터페이스로 구현하면 진행·취소·재시도 화면을 그대로 쓴다. 하지 않은 이유: 스테이지 캡처는 편집기 호스트(`StudioCuttoonEditorHost.tsx`)가 소유한 공유 3D 스테이지 문서와 렌더 루프 안에서만 호출할 수 있고, 호스트 파일은 줄 수 래칫(29,482줄)에 걸려 있어 줄을 늘릴 수 없다. 별도 페이지에 VRM 뷰포트를 새로 띄워 캡처하면 캐릭터 불러오기·권리·자원 수명을 이 기능이 다시 구현하게 되어 범위를 넘는다. `studio-shared-3d-stage-capture-intent.ts` 는 "어떤 변경에서 캐릭터를 캡처에 넣을지"만 정하는 함수라 호출 가능한 캡처 경로가 아니다.
2. **컴포저 참조 팩에 직접 투입.** 현재는 같은 형식(`StudioAiImageReferenceDocument` v1)의 문서를 `reference-pack.json` 으로 내려받는다. 컴포저의 참조 저장소에 쓰려면 호스트 쪽 연결이 필요하다.
3. **컴포저 후보 비교·승인 화면에 점수 표시**, **연속성 검사(continuity)와의 연계.** 연결하지 않았다.
4. **점수 가중치·경계의 실제 작품 검증.**

## 앵커 세트 사양

### 각도와 좌우 쌍 규칙

`azimuthDeg` 는 캐릭터가 카메라를 볼 때를 0°로 하고 캐릭터 몸의 세로축 주위로 카메라를 돌린 각도다. 좌/우는 항상 **캐릭터 몸 기준**이다(보는 사람 기준이 아니다).

| id | 이름 | 방위 | 종류 | 좌우 짝 |
| --- | --- | --- | --- | --- |
| `front` | 정면 | 0° | frontal | — |
| `left-34` | 좌 3/4 | -45° | half-side | `right-34` |
| `left` | 좌측 | -90° | side | `right` |
| `back` | 후면 | 180° | rear | — |
| `right` | 우측 | +90° | side | `left` |
| `right-34` | 우 3/4 | +45° | half-side | `left-34` |

짝은 3/4 쌍과 옆 쌍이다. 한쪽만 있으면 비대칭 소품·헤어·의상이 한쪽에서만 보여 참조가 한쪽으로 치우치므로 세트 점검이 알린다.

### 캡처 규약(스테이지에서 캡처할 때 지키는 값)

수치는 **사람이 정한 기본값**이며 실측으로 검증한 최적값이 아니다. 파일을 끌어다 놓는 경로에서는 강제하지 않고 어긋남을 "참고"로 알리기만 한다.

| 항목 | 값 |
| --- | --- |
| 프레임 | 2:3 세로, 768×1152px |
| 카메라 | 원근 투영, 세로 시야각 30°, 고도 0°(눈높이), 롤 0°, 목표점은 캐릭터 키의 절반 높이, 위아래 여백 6% |
| 배경 | 단색 `#bfbfbf`(흰색·검정은 캐릭터 색과 섞여 구분이 어렵다) |
| 조명·그림자 | 중립 평면 조명, 그림자 없음 |
| 포즈·표정 | 중립 A 포즈, 중립 표정 |
| 형식 | PNG, sRGB, 알파 없음 |

### 한도

| 항목 | 값 |
| --- | --- |
| 이미지 한 장 | 8MiB 이하, PNG·JPEG·WebP |
| 세트 전체 | 30MiB 이하 |
| 이미지 변 | 짧은 변 256px 이상, 긴 변 4096px 이하, 1677만 화소 이하. 긴 변 512px 미만은 "작다"고 참고로 알림 |
| 세로/가로 비 | 2:3 과 0.06 넘게 다르면 참고로 알림 |
| 앵커 id | 영문 소문자·숫자·하이픈, 40자 이하, 하이픈으로 시작·끝 불가 |
| 원본 캐릭터 id | 영문·숫자로 시작, `.` `_` `:` `-` 포함 가능, 64자 이하 |

형식과 크기는 디코딩 **전에** 헤더로 먼저 검사한다(`studio-upload-image-safety` 의 헤더 파서). 큰 이미지를 풀다가 탭이 멈추는 일을 막으려는 것이다.

### 파일 이름·메타데이터·결정적 해시

- 파일 이름: `<앵커id>.<각도>.<이미지 해시 앞 8자>.<확장자>`. id 와 각도에는 점이 없어 구분자로 쓴다.
- 항목 해시와 세트 해시는 **앵커 id · 원본 캐릭터 id · 각도 · 방위 · 형식 · 크기 · 이미지 SHA-256** 처럼 내용에서 오는 값만 키를 정렬한 정본 JSON 으로 직렬화해 SHA-256 한다. **생성 시각·표시 이름·권리 확인 시각은 넣지 않는다.** 같은 이미지를 다시 내보내면 해시가 같다.
- 세트 완전성 검사 결과: `empty`·`partial`·`complete` 상태, 빠진 각도, 경고(`missing-angle`, `missing-mirror-pair`, `size-mismatch`, `duplicate-image`), 참고(`aspect-off-convention`, `below-recommended-size`). 정면이 있으면 참조 팩에 쓸 수 있다고 본다.

## 참조 팩 투입

`addAnchorReferencesToPack` 은 기존 이미지 참조 문서(v1)를 정본화한 뒤 앵커와 샷 캡처를 더한 **새 문서**를 돌려준다. 입력 문서는 바꾸지 않는다.

- **역호환:** 옛 배열 형식도 받는다. 이 어댑터가 만들지 않은 참조(3D 현재 샷 구도 참조, 화풍 참조 등)와 `style` 역할은 건드리지 않는다.
- **역할:** 앵커 → `character`(정체성), 샷 포즈·구도 → `method`. 샷 이미지의 안내문은 "포즈·구도만 참고하고 정체성·화풍·문자를 복제하지 말라"고, 앵커의 안내문은 "정체성만 참고하고 포즈·배경·조명·화풍은 따라 하지 말라"고, 둘 다 "결과가 같은 캐릭터로 그려진다는 보장은 없다"고 밝힌다.
- **크기 상한(기존 참조 팩 모듈의 값을 그대로 쓴다):** 역할당 6개, 제공자 한 번에 보낼 수 있는 이미지 16개, 이미지 한 장 12MiB, 전체 50MiB. 넘치면 조용히 자르지 않고 이유(`role-limit`·`provider-limit`·`pair-rule`·`byte-budget`·`invalid-shot`·`duplicate-content`)와 함께 `skipped` 로 돌려주고 화면이 보여 준다. 앵커 여섯 장은 character 역할 상한(6)을 정확히 채우므로 이미 character 참조가 있는 문서에는 모두 들어가지 않을 수 있다.
- **쌍 규칙:** 좌우 짝은 둘 다 들어갈 자리가 있을 때만 넣는다. 한쪽만 넣으면 참조가 한쪽으로 치우친다. 넣는 순서는 정면 → 3/4 쌍 → 후면 → 옆 쌍이라 자리가 모자라면 뒤쪽 묶음부터 빠진다.
- **멱등:** 같은 앵커 id 로 다시 더하면 이전에 더한 참조를 먼저 걷어 낸다.
- **이진 데이터 없음:** 문서에는 소재 id 와 SHA-256 만 담는다. 소재 라이브러리에 저장할 메타데이터 초안(`assets`)을 함께 돌려준다.
- **권리 문구:** 모든 참조 안내문과 소재 메타데이터(`rightsConfirmed: true`, 라이선스 id `user-owned-virtual-character`)에 "사용자가 권리를 가졌거나 이용 허락을 받은 가상 캐릭터 이미지(실존 인물 아님)"라는 확인이 남는다. 확인이 없으면 문서를 만들지 않는다.

## 후보 이미지 일관성 점검(휴리스틱)

### 무엇을 재는가

이미지는 이 기기 안에서 긴 변 1024px 이하로 줄여 풀고(`createImageBitmap` 의 줄여 풀기), 분석 직전에 면적 평균으로 긴 변 256px 로 다시 줄인다. 피사체는 알파 또는 단색 배경으로 분리하며, 분리하지 못하면 이미지 전체로 견주고 그 사실을 알린다. 부위(머리·피부·의상)를 가정하지 않는다.

| 특징 | 계산 | 점수 가중치 |
| --- | --- | --- |
| 색 분포 | Lab 공간 L\* 16칸, a\*b\* 12×12칸 히스토그램의 Hellinger 거리 → 유사도 = 1 − (0.7×a\*b\* + 0.3×L\*) | 0.30 |
| 전체 주요색 팔레트 | Lab 결정적 k-means(최대 5색, 비율 3% 미만 제외) 두 팔레트의 양방향 가중 최근접 ΔE → 유사도 = 1 − ΔE ÷ 40 | 0.30 |
| 실루엣·비율 | 점유 격자 겹침·가로세로 비·상중하 질량·채움 비율의 가중 평균(둘 다 피사체를 분리했을 때만) | 0.25 |
| 구조 해시 | dHash 9×8 격자 64비트 해밍 거리 → 유사도 = 1 − 2×거리 ÷ 64 | 0.15 |

쓸 수 없는 특징은 빼고 남은 가중치를 다시 정규화한다. 최종 점수는 0~1 이고 화면에는 0~100점으로 보인다. 후보는 앵커 여섯 각도와 모두 견주고 가장 비슷한 각도를 기본으로 보여 주며, 사용자가 견줄 앵커 각도를 직접 고를 수 있다.

### 휴리스틱 임계값

아래 값은 모두 **사람이 판단해 정한 값**이다. 실제 작품 모음으로 검증하거나 보정한 적이 없다. 시험은 합성 도형 그림(색·포즈·배경·좌우·크기를 하나씩 바꾼 사람 모양 그림)으로 **점수가 기대한 방향으로 움직이는지**만 확인하며, 실제 작품에서의 정확도·재현율·오탐률을 뜻하지 않는다.

| 이름 | 값 | 쓰임 |
| --- | --- | --- |
| 구간 경계 | 높음 0.75 이상, 보통 0.55 이상, 그 아래 낮음 | 화면 구간 글("특징이 가까운 편" 등). 정확도나 판정 기준이 아니다 |
| 피사체가 작다는 경고 | 화면의 3% 미만 | 점수 신뢰 경고 |
| 거의 단색 | L\* 표준편차 3 미만 | 색 비교 불안정 경고 |
| 명도 차이 | 6 이상 참고, 14 이상 큼 | "무엇이 달랐나" |
| 채도 차이 | 8 이상 참고, 18 이상 큼 (두 이미지 중 한쪽의 평균 채도가 5 이상일 때만) | 〃 |
| 색상 차이 | 25° 이상 참고, 60° 이상 큼 (두 이미지 모두 평균 색 세기가 8 이상일 때만) | 〃 |
| 피사체 크기 비 | 0.75배 미만 또는 1/0.75배 초과 | 〃 |
| 가로세로 비 변화 | 1.25배 이상 참고, 1.6배 이상 큼 | 〃 |
| 위치 이동 | 가로 또는 세로 15% 이상 | 〃 |
| 실루엣 유사도 | 0.45 미만 | 〃 |
| 구조 유사도 | 0.2 미만이면 구조가 많이 다름, 색·팔레트·구조 모두 0.9 이상이면 "거의 같은 그림" | 〃 |
| 팔레트 "없는 색" | ΔE 22 이상이고 비율 8% 이상 | 〃 |

점수의 의미와 한계:

- 포즈·조명·구도가 다르면 **같은 캐릭터도 낮게** 나올 수 있다. 색이 비슷한 **다른 그림도 높게** 나올 수 있다.
- 구조 해시는 같은 포즈·구도의 복제를 가려내는 데 주로 쓰며 같은 캐릭터인지와는 관계가 없다.
- "무엇이 달랐나"는 이미지 전체의 통계 차이다. 어느 부위가 달랐는지 말하지 않는다.
- 후보 정렬은 점수·이름·올린 순서·특징별 유사도 순을 지원하고, 점수가 없는 후보(분석 전·실패)는 어떤 점수 기준에서도 맨 뒤에 둔다.

### 실행 위치

특징 계산은 요청마다 새 Worker 로 돌리고 끝나면 종료한다. 취소와 시간 상한(15초)을 강제하며, Worker 가 시작되지 않거나 실패하면 그 요청은 실패로 끝나고 **메인 스레드로 몰래 다시 시도하지 않는다.** Worker 생성자가 없는 환경에서만 메인 스레드 실행을 기본으로 쓴다. 후보 한 장의 전체 분석에는 30초 상한이 따로 있고, 후보는 최대 24장이다.

## 개인정보·권리 경계

- **로컬 처리.** 이미지는 서버로 보내지 않고 이 기기 안에서만 읽고 푼다. 이 기능은 네트워크를 쓰지 않는다. Worker 는 같은 브라우저 안의 별도 스레드다.
- **얼굴 인식·생체 정보 추출을 쓰지 않는다.** 점수는 색 분포·팔레트·실루엣 비율·구조 해시뿐이며 사람을 식별하거나 동일인을 판별하는 값이 아니다. 이 기능의 대상은 **가상 캐릭터**다.
- **실존 인물의 사진·초상을 올리는 용도가 아니다.** 이미지를 받기 **전에** 사용자가 "내가 권리를 가졌거나 이용 허락을 받은 가상 캐릭터의 이미지이며 실존 인물의 사진이나 초상이 아니다"라고 직접 확인해야 하고, 확인 전에는 파일 입력이 닫힌다. 이 확인은 체크한 순간의 시각과 함께 `rights.json` 에, 같은 문장이 `anchor-set.json`·`README.txt`·참조 팩 안내문에 남는다. 이 확인은 **법적 권리 인증이 아니다.**
- **저장하지 않는다.** 이미지·세트·후보를 브라우저 저장소(localStorage·IndexedDB·OPFS)나 서버에 저장하지 않는다. 새로고침하거나 화면을 떠나면 사라지고 미리보기 URL 은 모두 해제한다. 내려받은 파일의 보관은 사용자의 몫이다.
- **내보낸 파일의 내용.** 같은 입력은 같은 바이트의 ZIP 을 만든다(ZIP 시각은 고정). 시각은 `rights.json` 의 확인 시각에만 있다. 파일 내용은 화면 언어와 무관하게 같다.

## 문구(i18n)와 접근성

- 문구는 `anchorLab` 네임스페이스(`public/i18n/app/anchorLab/`)의 키로만 쓴다. 셸 내장 사전에는 넣지 않고 화면 모듈이 평가될 때 등록하는 지연 묶음이다(`anchor-lab-i18n.ts`). 파일 이름·앵커 id·수치 같은 사용자 값은 번역 원문이 아니라 `{자리표시}` 값으로만 넘긴다. 시험이 코드가 쓰는 키와 사전의 키가 정확히 같음을 확인한다.
- 키보드: 모든 조작은 버튼으로 할 수 있다(끌어다 놓기는 보조). 후보 목록은 선택한 후보만 탭 정지점인 목록이며 방향키(위·왼쪽 = 이전, 아래·오른쪽 = 다음, Home·End)로 옮긴다. 이전·다음 후보 버튼도 있다.
- 입력란은 `label` 과 힌트·오류를 `aria-describedby` 로 잇고, 오류는 이유와 예시를 알린다. 읽기·분석 오류는 이유와 다음 행동을 함께 쓴다. 진행 문구는 `role="status"` 이고 오류는 `role="alert"` 다.
- 상태는 색에만 기대지 않고 글로 쓴다. 버튼은 공용 버튼 스타일을 써서 터치 환경에서 44px 대상이 된다. 진행 표시는 스켈레톤과 `<progress>` 이며 모션을 쓰지 않는 보조 표시(`motion-reduce`)를 따른다.
- 이미지 미리보기는 이름을 가진 `img` 이고, 후보 목록 썸네일은 이름이 따로 보이므로 장식으로 숨긴다.

## 검증 범위

실행한 것: 위 모듈의 단위 시험, 화면의 컴포넌트 시험(jsdom: 권리 확인 전 입력 잠금, 파일 이름 짐작, 읽기 실패·재시도·취소, 세트 해시 재현, ZIP 내용과 오류·취소, 샷 이미지, 후보 점수·정렬·키보드 이동·나란히 보기·취소·재시도·개수 상한), 라우트 계약 시험(권위·메타데이터·등록부·제목·시각 분류·캠퍼스 분류·사이트맵), i18n·언어 가드 시험, 변경 파일 린트, 범위 타입체크, `validate:architecture`.

하지 않은 것(→ 위 "목표"와 같이 읽는다):

- 실제 브라우저에서 사람이 조작한 검증, 스크린리더·모바일 실기기·light/dark/contrast 화면 확인(브라우저 화면 검증은 별도 단계).
- 실제 캐릭터 작품으로 점수가 같은 캐릭터를 가려내는지 측정하는 일. 이 문서의 가중치·경계는 그런 근거가 없다.
- 큰 이미지(4096px 급)와 후보 24장에서의 실측 성능·메모리.
- 3D 스테이지 캡처, 컴포저 연결.
