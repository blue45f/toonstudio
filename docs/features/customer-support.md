# AI 고객센터와 비공개 1:1 문의

- 상태: **current** — AI 고객센터·비공개 1:1 문의의 코드 구현 완료. 운영 배포와 실제 Claude 연결 검증은 별도 확인 항목이다.
- 기준일: 2026-10-30
- 사용자 진입: `/support`
- 관리자 진입: `/admin/growth/inquiries`

## 이용 흐름

로그인한 사용자는 고객센터에서 AI 상담 또는 비공개 1:1 문의를 만든다. 대화와 메시지는 서버의 PostgreSQL에 보관하며 본인과 관리자만 조회할 수 있다. 공개 질문·버그 게시판은 기존 경로로 유지한다.

AI 상담은 기존 서버용 Claude 설정으로 사용 방법과 문제 해결을 안내한다. 실제 계정·원고·결제 상태를 조회하거나 변경하지 않는다. 화면에서 1:1 문의로 전환하면 대화 기록을 유지한 채 관리자 상담 대기 상태가 된다. 관리자는 고객지원 화면에서 기록을 읽고 답변하거나 문의 상태를 변경한다. 사용자 화면은 상담원 답변을 주기적으로 확인한다.

AI 설정 누락·호출 실패·한도 초과 시 자동 답변을 만들어 성공으로 표시하지 않는다. 사용자 메시지를 보존하고 오류 안내, 명시적 재시도 또는 상담원 전환을 제공한다. 키가 없어도 비공개 1:1 문의는 이용할 수 있다. 비밀번호·인증 코드·API 키·결제 수단은 문의에 보내지 않는다.

## 서버 설정

실제 비밀값은 [인프라 지도](../operations/infrastructure-map.md)의 기존 비밀 저장소에서 서버에 주입한다. 소스·문서·브라우저 변수에 복사하지 않는다.

| 변수 | 동작 |
| --- | --- |
| `STUDIO_AI_ANTHROPIC_API_KEY` | 기존 ToonStudio 서버의 Claude 키. 비어 있으면 `ANTHROPIC_API_KEY` 사용 |
| `STUDIO_AI_ANTHROPIC_MODEL` | 기존 서버용 Claude 모델 설정 사용 |
| `STUDIO_AI_ANTHROPIC_WORKSPACE_ID` | 조직 전체 키에 필요한 워크스페이스 헤더 |
| `CUSTOMER_SUPPORT_AI_ENABLED` | `false`이면 AI 상담만 중지. 비공개 문의와 관리자 답변은 유지 |
| `STUDIO_AI_PREMIUM_AUTO` | 기존 설정이 `false`이면 고객센터 AI도 중지 |
| `STUDIO_AI_PREMIUM_*_LIMIT` | 기존 사용자·전체 요청·토큰 한도가 고객센터 기본 상한보다 낮으면 낮은 값 적용. 0이면 AI 중지 |

고객센터 Claude 호출은 30초 제한이며 자동 재시도하지 않는다. 대화 입력과 출력 크기를 제한하고 자체 PostgreSQL 원장에서 UTC 일일 사용자 30회·전체 400회·예약 토큰 300만을 상한으로 통제한다. 기존 Studio 운영 설정의 더 낮은 한도와 중지 설정을 따르며, 사용량이 불명확한 실패도 예약을 유지한다. 고객센터와 Studio AI 요청 원장은 별도이므로 두 기능의 합산 사용량이나 같은 키를 사용하는 조직 전체 비용·크레딧 잔액을 보장하지 않는다. 새 문의·메시지에도 시간당 제한을 적용한다.

## 저장소와 권한

추가형 마이그레이션 `0118_customer_support.sql`이 문의·메시지·AI 사용 원장 테이블을 만든다. API 요청 중 DDL을 실행하지 않는다. 사용자 API `/api/support/*`는 세션 인증과 문의 소유권을 확인하며 관리자 API `/api/admin/support/*`는 관리자 권한을 별도로 확인한다. 공통 CSRF 보호를 따른다.

이 번호형 SQL 파일 한 개의 추가에 맞춰 `architecture-source-ratchet.json`의 `apiDatabaseFiles`를 170에서 171로 조정했다. 기존 migration 이력과 다른 source-layout 한도는 유지한다.

메시지의 `clientMessageId`로 네트워크 재전송을 중복 저장하지 않는다. 같은 문의의 AI 실행과 상태 변경은 DB 잠금·실행 소유권으로 조정한다. 제목은 2~120자, 사용자 메시지는 1~4,000자이며 한 문의의 메시지는 최대 200개다. 상담원 전환 후에는 AI가 새 답변을 붙이지 않는다.

사용자와 관리자의 문의 목록은 `limit`·`offset` 페이지 이동으로 이전 문의까지 조회한다.

## 운영 반영과 복구

운영 담당자가 [DEPLOY.md](../../DEPLOY.md)의 승인 범위와 필수 검사를 확인한 뒤 기존 migration runner의 `apply` 절차로 0118을 먼저 적용하고 같은 SHA의 API·웹을 반영한다. 입력은 검증된 SHA와 운영 migration 전용 연결이며, 성공 기준은 migration/readiness 통과와 사용자·관리자 대화 왕복 확인이다. 이 문서의 작성 자체로 운영 DB·키·배포를 변경하지 않는다.

장애 시 기존 정상 API·웹 이미지로 되돌리고 추가된 테이블과 상담 기록은 유지한다. 테이블 삭제나 문의 데이터 삭제는 자동 롤백에 포함하지 않는다. AI만 중지해야 하면 기존 운영 설정 변경 절차에 따라 `CUSTOMER_SUPPORT_AI_ENABLED=false`를 적용한다.

## 검증 범위

관련 단위 테스트는 인증·소유권·관리자 경계, 입력 검증, 중복 처리, Claude 요청·오류·시간 초과, 사용자 대화·전환 및 관리자 답변을 다룬다. PostgreSQL 통합 테스트와 브라우저 검증의 실제 실행 결과는 작업 완료 보고를 따른다. 모의 Claude 응답을 사용하는 검증은 실제 API 키·네트워크·조직 잔액 검증과 구분한다.

2026-10-30 로컬 검증에서 서버 단위 테스트 43개, 사용자 웹 테스트 15개, 관리자·경로 테스트 18개, 실제 PostgreSQL 17.11 통합 테스트 17개가 통과했다. migration·bootstrap·권한·준비성 관련 테스트도 통과했다. `pnpm harness:verify --base=HEAD`는 변경 lint·Secretlint·아키텍처·전체 Web/API 타입 검사를 포함해 통과했다. 최종 사용자 화면 보완에서 제목의 공백 제외 최소 2자 검증을 서버와 맞췄고, 직접 form 제출과 잘못된 입력의 차단을 회귀 테스트로 확인했다. 브라우저 HTTP 경계에 모의 응답을 주입한 12개 시나리오에서 AI 응답, 전송 재시도, 상담원 전환·답변 갱신, 종료, 권한 해제 시 기록 제거를 확인했다. 390px 화면의 가로 넘침이 없고, 테마 전환 애니메이션을 종료한 정적 팔레트 검사에서 사용자·관리자 상담 영역의 light·dark·contrast·starlight serious·critical 접근성 위반은 0개였다. 이 과정에서 활성 전송 버튼의 테마 대비와 긴 대화의 키보드 스크롤·목록 의미 구조를 수정했다.

전달된 키의 서버 설정 인식은 확인했지만, 이 실행 환경의 프록시가 `api.anthropic.com` 연결을 403으로 거절해 실제 키 인증·모델 조회·Claude 응답은 검증하지 못했다. 이후 사용자가 키의 크레딧 소진을 알려 로컬 비밀 저장소에 `CUSTOMER_SUPPORT_AI_ENABLED=false`를 적용했고 서버 상태가 `disabled`임을 확인했다. 비공개 1:1 문의는 AI 설정과 독립적으로 동작한다. 실제 비밀값은 Git에서 제외되는 로컬 저장소에만 보관했으며 운영 환경에 등록하거나 배포하지 않았다.

재실행 가능한 `e2e/customer-support.spec.ts`의 세 회귀 시나리오도 최종 일괄 실행에서 모두 통과했다(`3 passed`, 1.5분). AI 대화·재전송·상담원 전환·답변 확인·종료, 관리자 답변·권한 해제, 51개 문의의 페이지 이동과 초안 보존을 다룬다. 테마 대비는 애니메이션이 없는 정적 최종 팔레트와 완전히 보이는 제어 요소에서 검사하며, 390px 모바일 레이아웃 검증은 별도로 유지한다. 임시 PostgreSQL과 Vite 서버는 검증 후 종료했다.

main 병합 준비에서는 기존 `0116_studio_review_comment_pen_strokes.sql`·`0117_studio_scoped_write_policy.sql`을 보존하고 고객지원 SQL을 `0118`로 통합했다. migration manifest 118개, bootstrap 원장 119개, PostgreSQL suite 25개를 확인했다. 최신 main 통합 후 DB·정책·준비성 9개 파일의 테스트 249개, 사용자·관리자 테스트 28개, 브라우저 테스트 3개가 통과했다. 기존 main의 scoped-write 표 2개도 준비성·후기 릴레이션 등록에 포함했다.
