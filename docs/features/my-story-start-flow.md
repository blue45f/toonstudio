# 내 이야기를 웹툰으로 — 시작 동선, 주제 템플릿 팩, 책(PDF) 프리셋

- 상태: **current** (2026-10-15 기준 구현된 범위). 구현하지 않은 항목은 "한계와 후속"에 `target`으로만 적었다.
- 영역: `apps/web/src/domains/creator/my-story/`, `apps/web/src/domains/creator/CreateStartPage.tsx`,
  `apps/web/src/domains/creator/export/`
- 관련 문서: [창작자 적응형 작업공간](../creator-adaptive-workspace.md)

## 1. 왜 만들었나

모두의 창업 웹툰 아이디어 목록에서 개인 경험·기억의 웹툰화가 가장 많은 하트(24)를 받았고, 비슷한 제안
(동네 이야기, 시니어 경력 기록, 금융·안전 교육용 만화)이 모였다고 이번 작업 요청서가 전한다. 이 수치는
저장소의 소스·테스트로 확인할 수 없는 외부 입력이라 근거로만 적는다. 초보자가 도구가 아니라 **내 이야기**에서
시작해 첫 컷 초안까지 가는 안내 흐름이 필요하다는 뜻으로 읽었다. 제품 원칙 4번("초보자가 바로 이해할 기본 흐름,
고급 제어는 점진 노출")을 따라, 새 편집기를 만들지 않고 기존 대본·콘티 시작 경로로 연결한다.

적응형 작업공간 문서의 원칙대로 이 흐름은 경험 수준·작업공간 모드로 막거나 숨기지 않는다. 시작 시트에서
누구에게나 같은 카드로 보이며, 전문 도구를 잃게 하는 단계도 없다.

## 2. 사용자 흐름

진입 주소는 별도 라우트가 아니라 시작 시트(`/create`)의 쿼리다. 라우트·내비 계약은 바뀌지 않는다.

| 주소 | 동작 |
| --- | --- |
| `/create` | "내 이야기로 시작하기" 의도 카드(기존 5개 레인 위). 주제 6개는 바로가기 링크. |
| `/create?intent=my-story` | 질문형 인터뷰를 지연 로딩으로 연다(주제 선택 화면). |
| `/create?intent=my-story&topic=<id>` | 해당 주제의 첫 질문에서 바로 시작. 이어 쓸 진행이 이 기기에 있으면 덮어쓰지 않고 주제 선택 화면에서 이어 쓸지 묻는다. 모르는 `topic`은 무시. |

1. **주제 고르기** — 6종 중 하나를 라디오 그룹으로 고른다. 질문 미리보기, 기본 컷 수, 안전·금융 주의 문구가 보인다.
2. **질문 6~8문항** — 한 번에 하나. 이전 / 건너뛰기(비어 있을 때) · 다음(쓴 뒤) / "여기까지로 초안 보기",
   질문 목록 버튼으로 임의 이동, `Ctrl+Enter`(또는 `⌘+Enter`)로 다음. 건너뛴 칸은 빈칸으로 남는다.
3. **초안 미리보기** — 컷별 장면 요약·나레이션 후보·말풍선 후보·연출 힌트. 제목, 컷 수(4/8), 톤을 바꿀 수 있고
   빈칸은 해당 질문으로 바로 돌아가 채울 수 있다. 선택 기능으로 텍스트 AI 보강, 마지막으로 **스튜디오에서 열기**.

## 3. 주제 템플릿 팩 6종

데이터는 순수 모듈 `my-story-templates.ts`에 있고(이웃 템플릿 카탈로그의 `…Ko`/`…En` 쌍 관례), 한 팩은
질문 세트 + 컷 구조 골격 + 톤 프리셋 + 나레이션/말풍선 기본값이다.

| id | 주제 | 질문 수 | 컷 수 | 기본 톤 | 주의 문구 |
| --- | --- | --- | --- | --- | --- |
| `retrospective` | 회고 | 8 | 8 / 4 | 따뜻한 회상 | - |
| `family` | 가족 | 8 | 8 / 4 | 따뜻한 회상 | - |
| `neighborhood` | 동네 | 7 | 4 | 정겨운 이웃 | - |
| `career` | 경력 | 8 | 8 / 4 | 담담한 기록 | - |
| `safety` | 안전 수칙 | 6 | 4 | 또렷한 안내 | 수칙 내용은 도구가 만들지 않는다. 관련 기관의 최신 안내로 직접 확인. |
| `finance` | 금융 상식 | 7 | 4 | 또렷한 안내 | 투자·상품 권유가 아니다. 금리·한도·제도는 공식 자료로 직접 확인. |

질문 칸은 `who · when · where · event · turn · feeling · ending · message` 8개 중 6~8개를 템플릿이 골라 쓴다.
모든 팩이 "누가·언제·어디서·무슨 일·그때 감정·결말·전하고 싶은 한 줄"을 포함하는 것은 아니다. 안전·금융 팩은
교육용이라 `turn`을 "올바른 행동/알아 둘 상식"으로 쓰고 일부 칸을 뺀다. 입력칸 예시는 화면에 보이는
안내일 뿐 답변으로 저장되거나 초안에 섞이지 않는다.

테스트가 지키는 불변식: 질문 6~8문항·칸 중복 없음, 골격 컷 수 = 지원 컷 수, **모든 질문 칸이 골격의 어느 컷에든
배치**(답변이 버려지지 않음), 나레이션·말풍선 칸은 같은 컷의 요약 칸 안에 있음.

## 4. 초안 규칙 — 결정적, 지어내지 않음

`my-story-draft.ts`는 같은 답변이면 항상 같은 초안을 만든다.

- 컷 요약 = 골격이 가리키는 답변을 사용자의 글자 그대로 " / "로 이은 것.
- 나레이션 후보 = 골격이 가리키는 답변을 한 상자 한도(템플릿별 28~44자)로 문장 경계 → 띄어쓰기 순으로 나눈
  것. 넘치는 부분은 버리지 않고 "이어서 쓸 후보"로 남긴다.
- 말풍선 후보 = 사용자가 `“…”`, `"…"`, `「…」`, `『…』`, `‘…’`로 직접 묶은 말만. 없으면 빈칸.
- 빈 답변은 `(빈칸)`으로 표시하고 어떤 문장도 대신 채우지 않는다.
- 사용자의 글자는 공백 정리(연속 공백·제어 문자) 외에는 바꾸지 않는다.

인터뷰 엔진(`domains/character-interview`)의 "캐논 시트 근거 고정, 시트에 없는 값은 지어내지 않고 드러낸다"는
원칙과 같은 규율이다. 다만 그 엔진은 캐릭터와 대화하는 LLM 어댑터라서 코드를 재사용하지는 않았다(도메인 간
deep import도 만들지 않았다). 여기서는 답변이 곧 근거 시트다.

## 5. 임시저장과 개인정보

- **저장 위치**: 이 기기 브라우저의 `localStorage` 키 `toonstudio:my-story-session:v1` 한 곳. 서버로 보내지
  않는다. 쓰는 대로 300ms 뒤 저장하고, 화면을 떠날 때는 즉시 저장한다.
- 저장소가 막혀 있어도(사생활 보호 모드·용량 초과) 흐름은 계속되고 "임시 저장에 실패했어요"를 알린다.
  저장본은 신뢰하지 않는다: 형식·버전이 어긋나면 버리고, 알려진 칸·길이·컷 수·톤으로만 복원한다.
- 저장된 진행이 있으면 자동으로 덮어쓰지 않고 "이어서 쓰기 / 지우고 새로 시작"을 묻는다. 다른 주제를 눌러
  보기만 하고 답을 적지 않으면 저장본은 그대로 남고(돌아오면 다시 이어 쓸 수 있다), 새 주제에 첫 답변을 적는
  순간 새 이야기로 대체된다. 이 결과는 이어 쓰기 안내 문구에도 적혀 있다.
- **화면 안내**: 모든 단계에서 "이 기기에만 저장돼요", 실명·연락처·주소·계좌번호를 적지 않는 것이 안전하다는
  점, 가족·이웃은 이름 대신 호칭을 쓰라는 점을 보여 준다. 전화번호·이메일·주민등록번호·계좌번호처럼 보이는
  입력은 **안내만 하고 막지 않는다**(휴리스틱이므로 놓치거나 잘못 잡을 수 있다).
- 사용자가 쓴 글은 번역 사전 키(`useBilingual`)에 넣지 않는다. 제목 등 사용자 문장은 문구 밖에서 이어 붙인다.
- 스튜디오로 전달이 성공하면 같은 내용이 따로 남지 않도록 임시저장을 지운다.

## 6. 스튜디오로 전달 — 기존 대본·콘티 시작 경로 재사용

`my-story-handoff.ts`가 새 저장 형식 없이 기존 모듈만 호출한다.

1. 새 작품 양식(`/studio/new`)과 같은 `createStudioProjectWithInitialDocument`로 **컷툰** 프로젝트를 만든다.
   4컷 → `cuttoon-square-4`, 8컷 → `cuttoon-portrait-8`. 시작점은 "대본이 있어요(script)", 목적은 포트폴리오.
2. 대본 패널(`StudioStoryDevelopmentPanel`)이 읽는 스토리 개발 문서(`toonstudio:story-development:v1:<id>`)에
   원고를 쓴다. 한 줄 = "전하고 싶은 한 줄" 답변, 줄거리 = 사건·순간·결말 답변만, 본문 = 연출 메모 문단 + 컷별 문단.
3. 프로젝트 기능 묶음의 `storyBeats`를 컷 수만큼 채운다. 컷 역할이 비트 종류(setup/action/dialogue/reaction/
   transition/reveal)가 되고 말풍선 후보는 비트의 `dialogue`가 되어, 기존 콘티 플래너
   (`planStudioStoryboard`)가 4컷/8컷 골격 그대로 샷·카메라·여백을 계획한다.
4. `/studio/p/<id>/story?view=script`로 이동한다(`navigate(…, { replace: true })`).

중간에 실패하면 만들다 만 프로젝트를 되돌려 보관함에 빈 작품이 남지 않게 한다.

한계: 대본 화면의 "컷 계획으로 적용"은 원고를 **문장 단위로 다시** 나누므로 누르면 컷 수가 달라질 수 있다.
컷 계획은 이미 채워져 있으므로 누를 필요가 없고, 화면에도 그렇게 안내한다.

## 7. 텍스트 AI 보강 — 사용자가 누를 때만

- 화면을 열거나 질문에 답하는 것만으로는 아무 것도 전송되지 않는다. "AI로 다듬기" 버튼을 누를 때 한 번 호출한다.
- 호출 경로는 기존 무료 우선 클라우드 텍스트 AI(`completeStudioServerText`, task `scenario`)다. 로그인 필요·무료
  소진 같은 실패 코드는 공용 `AiRecoveryNotice`로 안내하고 다시 시도를 제공한다. 새 AI 경로·키 입력 UI는 없다.
- 전송 내용은 **나레이션이 될 칸의 답변 원문뿐**이며 보내기 전에 "보낼 내용 미리 보기"로 볼 수 있다.
- 응답은 후보일 뿐이다. 규칙 기반 초안은 그대로이고 컷별로 "이 문장 쓰기"를 눌러야 반영되며 언제든 되돌릴 수 있다.
  해당 칸의 답변을 고치면 채택은 풀린다.
- 후보 검증(휴리스틱): 빈 문장, 상자 한도 초과, **원문에 없던 숫자가 생긴 문장**은 버리고 몇 개를 제외했는지 알린다.
  지어내기를 줄이는 장치일 뿐 보증은 아니다.
- 실패·형식 오류·취소는 예외 없이 값으로 처리하고 초안은 그대로 둔다.

## 8. 책으로 내보내기 프리셋 — A5 세로 제본 책

기존 경로를 확장했다: `StudioExportMenuPanel` → `exportPagesToPdf` → `renderPagesToPdf({ book })` →
`buildBookPrintPdf`. 단행본 조판(신국판·B6·A5 판형, 도련, 재단 마크)이 이미 있었고 쪽 번호·표지·여백 배치가
없었다. 이번에 책 구성(binding)을 선택 확장으로 더했다. 켜지 않으면 PDF 출력이 이전과 같다: binding 생략과
빈 binding이 같은 바이트이고 글꼴·텍스트 연산자가 생기지 않는 것을 테스트로 고정했고, 변경 전 빌더와의
바이트 동일(판형 3종 × 마크 × 쪽 수 × 제목, 54건)은 작업 중 일회성 비교로 확인했다(저장소 테스트는 아니다).

- **여백 안에 맞추기(`inside-safe`)**: 페이지 이미지를 안전 영역 안에 비율을 지켜 가운데 맞춘다. 제본 여백이
  실제로 보장되고 비율이 다른 원고도 늘어나지 않는다(이때 비율 경고는 내지 않는다). A5의 여백은 기존 프리셋
  값(안전 11mm + 제본 5mm)이다.
- **쪽 번호**: 본문 쪽마다 바깥쪽 아래(왼쪽 면은 왼쪽, 오른쪽 면은 오른쪽)에 PDF 표준 글꼴 Helvetica 숫자로
  찍는다. 표지는 번호를 세지 않고, 첫 본문 쪽이 1이다.
- **표지**: 작품 제목(내보내기 제목)과 선택 입력 지은이만 놓는 글자 표지. 한글은 표준 글꼴로 쓸 수 없어서
  브라우저 캔버스로 판형(도련 포함) 크기에 그려 JPEG로 맨 앞에 붙인다. 글자는 모두 안전 영역 안에 두고, 긴
  제목은 줄 길이를 고르게 나눠(마지막 줄에 낱말 하나만 남기지 않는다) 그리며, 네 줄을 넘으면 글자를 줄인다.
  글자를 자르거나 말줄임하지 않는다. 한글 웹폰트 조각은 그리기 전에 불러오고, 실패해도 대체 글꼴로 계속한다.
- **프리셋 "A5 세로 제본 책 (148×210)"**: A5 + 재단 마크 + 300dpi + 위 세 가지를 한 번에 맞춘다. 세 항목은
  각각 켜고 끌 수 있다.

한계(화면에도 같은 취지로 적었다): 세로로 긴 스크롤 원고를 쪽으로 나누지 않는다(한 장에 작게 들어간다) ·
일러스트 표지는 만들지 않는다(첫 페이지로 직접 넣어야 한다) · 쪽 번호는 숫자만 · 책등 폭 계산·PDF/X·CMYK 변환·
인쇄소별 규격 검증은 없다. 여백 값은 일반적인 무선 제본 기본값이며 인쇄소 규격이 우선이다. 단행본 조판 2단계
모델(`studio-book-layout-stage2-model.ts`의 스프레드·부모 페이지)은 아직 PDF 출력에 연결되지 않았고 이번에도
연결하지 않았다.

## 9. `StudioSimpleProductionWizard` 점검 결과 — 재사용하지 않고 보존

점검: `StudioSimpleProductionWizard.tsx`, `studio-simple-production-wizard.ts`와 두 테스트 파일은 자기들끼리만
참조한다. 저장소 전체(소스·문서·설정·e2e)에서 외부 import, 라우트, 문서 참조가 0건이다. 반면
`StudioQuickComicWizard`는 컷툰 에디터 대화상자(`StudioCuttoonEditorDialogs`)에 연결되어 있다.

판단: 이 흐름에는 쓰지 않는다. 근거 네 가지.

1. 단계가 배경 → 캐릭터 → 대사 → 효과라서 **그림 조립 순서**이고, 입력은 장면 템플릿·포즈·표정 id 선택이다.
   이 흐름의 입력은 사용자가 쓴 이야기 문장이다.
2. 출구가 조립 입력(`ComipoAssemblyInput`)과 씬 레시피를 만들고 전문 에디터로 가는 것이라 대본·콘티 문서를
   만들지 않는다.
3. 모든 단계에 **기본값을 자동 적용**한다. 이 흐름은 반대로 빈 답변을 채우지 않는다.
4. 삭제는 이번 범위 밖의 무관한 정리다(데드코드 정리는 별도 작업으로 다룬다).

차용한 것은 설계 원칙뿐이다: 단계 순서 고정과 뒤로 가서 고치기, 건너뛰어도 끝까지 갈 수 있음. 이 위저드를
컷 조립 단계로 잇는 일은 `target`이며 구현하지 않았다.

## 10. 접근성과 키보드

- 주제 선택은 네이티브 라디오 그룹(방향키), 컷 수도 라디오, 톤은 `<select>`. 질문 입력칸은 질문 제목이
  `aria-labelledby`, 예시·글자 수·도움말·개인정보 안내가 `aria-describedby`.
- 진행 막대는 `role="progressbar"`와 `aria-valuetext`, 질문 목록은 `nav` + `aria-current="step"`, 답함 상태는
  색이 아니라 체크 아이콘과 숨은 텍스트로도 전달한다.
- 질문이 바뀌면 새 입력칸으로, 주제·검토 단계는 단계 제목으로 초점을 옮긴다(페이지 첫 진입에서는 빼앗지 않는다).
- 모든 조작은 최소 44px, 진행 막대 전환은 `motion-reduce`에서 멈춘다. 색만으로 의미를 전하지 않는다.
- 로딩은 스켈레톤(`LoadingState`), 빈 상태·오류·재시도는 컴포넌트 테스트로 고정했다.

브라우저 화면 검증(light/dark/contrast, 모바일/데스크톱)은 별도 UI/UX 단계에서 수행한다. 이 문서의 시점에는
컴포넌트 테스트까지만 근거가 있다.

책 PDF는 작업 중 일회성으로 외부 도구로도 확인했다(저장소 테스트 아님): Node 캔버스로 만든 표지·본문 JPEG을
빌더에 넣어 만든 PDF를 poppler의 `pdfinfo -box`(쪽수·TrimBox·BleedBox), `pdftotext`(쪽 번호 1·2·3, 표지는 없음),
`pdffonts`(표준 Helvetica)로 읽고 `pdftoppm`으로 렌더해 표지 줄바꿈·여백 안 배치·쪽 번호 위치를 눈으로 봤다.
실제 인쇄소 입고 검증은 하지 않았다.

## 12. 한계와 후속

- `target` 인터뷰 답변을 컷별 이미지 생성이나 컷 조립(QuickComic/SimpleProduction)으로 잇는 단계는 없다.
- `target` 사용자 지정 질문, 6개 밖의 주제, 다국어 질문 세트의 사람 번역 검수. 현재 영어 문구는 직접 쓴 번역이며
  기타 언어는 기존 번역 파이프라인 폴백에 의존한다.
- 개인정보 감지는 정규식 휴리스틱이다. 주소·실명은 감지하지 못한다(안내 문구에 의존).
- 쪽 나눔·일러스트 표지·책등·PDF/X는 없다(8절 참고).
