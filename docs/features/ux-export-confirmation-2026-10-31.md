# 이미지 다운로드의 설정 확인·모바일 복귀 개선

상태: **구현 후보·앱 통합 검증 전**. 작성일 2026-10-31.

## 사용자 경험 변경

기존 파일 형식·배율·현재 페이지 저장 기능을 유지하면서, 다운로드 직전에 실제 설정을 설명한다. PNG/JPG/WebP의 차이를 짧게 표시하고 예상 픽셀 크기는 배율 버튼과 분리해 좁은 패널에서 줄바꿈할 수 있게 한다. 생성·저장 기능을 새로 만들지 않는다.

- 출력 요약: 형식·예상 크기, 배경 설정, **문구** 워터마크의 상태. 페이지 픽셀·최종 파일 크기·내보내기 완료를 추정하지 않는다.
- JPG를 선택하면 투명 배경이 지원되지 않음을 항상 알린다. 기존 투명도 요청값을 지우지 않으며, PNG/WebP로 돌아오면 기존 선택을 다시 반영한다.
- 서명이 켜졌지만 문구가 비어 있거나 투명도가 0인 경우를 별도로 안내한다. 별도 보호·노이즈 옵션의 켜짐 여부로 문구가 있는 것처럼 표시하지 않는다.
- 수정 링크는 네이티브 접기 영역을 열고 실제로 조작 가능한 입력에 초점을 둔다. JPG에서는 비활성 투명도 입력을 건너뛴다. 설정 끝의 복귀는 기존 다운로드 버튼 또는 안전한 요약 영역으로 이동한다.
- 파일 준비 중에는 형식·배율·배경·서명 설정을 잠근다. 여러 페이지 패키지의 취소·진행 영역은 disabled fieldset 밖에 있어 잠그지 않는다. 작업 중 취소가 없는 기능에 새 취소 동작을 있다고 주장하지 않는다.
- 클립보드 복사는 선택한 다운로드 형식과 관계없이 PNG라는 기존 구현을 설명한다.
- 입력·선택의 모바일 글자 크기, 좁은 화면 줄바꿈, 고유 도움말 ID, 한국어·영어 문구와 서명 위치 이름을 보완한다.

## 변경하지 않는 경계

캔버스 캡처·파일 인코더·다운로드 파일명·저장소·인쇄/PDF·페이지 범위·계정 권한은 수정하지 않는다. 내보내기 콜백과 형식·배율 setter를 재사용한다. 새 의존성·워크플로·CI 상태·보호 규칙·운영 환경 변경은 없다. 원본 UX 14파일과 이전 실패 증거는 보존한다.

## 실제 검증과 제한

- 별도 컨테이너의 Node.js에서 제품 상태판정 함수를 실행한 **17개** 사례 통과: PNG/WebP 배경, JPG의 미지원, 꺼진·빈·투명한·비정상 서명, 입력 불변성.
- 같은 컨테이너의 실제 번역 등록 코드에서 **3개** 계약 확인: 한/영 키 집합, 기존 다운로드 문자열 치환, 클립보드 PNG 안내. 등록 저장소 경계는 대역이다.
- 합계 **20개 통과·실패0·skip0**. React 렌더·브라우저·실제 파일 생성의 증거가 아니다.
- 변경 TS/TSX 7파일의 TypeScript 5.8.3 AST 구문 진단 0. 저장소가 사용하는 전체 타입 검사와 다르다.
- Vitest용 상태판정 17개 및 React 컴포넌트 회귀 **19개** 작성. React 회귀와 저장소 전체 검사는 **미실행**.
- 실제 앱 320/390/1440px, 밝음/어두움/고대비, 키보드·접기·포커스·이미지 다운로드 검증은 **미실행**. 사용자가 올린 독립 UX 검토 시안을 실제 앱 실행 증거로 사용하지 않는다.

## 통합 검증

중앙에서 지정된 순서에 따라 단일 worker로 기존 내보내기 회귀와 신규 테스트를 실행한다. 원본 assertion·timeout을 유지하며 실패를 건너뛰지 않는다. 전체 Web/API·lint·Secretlint·관련 gate, 실제 좁은 패널과 큰 이미지 크기 표시, JPG 투명도 안내, 빈 서명 수정·복귀, 내보내기 중 설정 잠금·패키지 취소, 같은 콜백의 실제 파일 바이트를 확인해야 한다. 원격 PR 게시와 main 병합은 운영 배포가 아니다.
