## 2. 기획 흐름 분석 (핵심 여정 4개)

### 여정 A — 독자 발견: 홈 → 탐색 → 작품 상세 → 외부 플랫폼/읽기
- 강점: 랭킹·캘린더·추천·태그 등 발견 표면이 풍부하고, 출처·산식을 드러내는 제품 원칙이 실제 카피에 반영됨.
- 마찰: 발견 입구가 너무 많다. `/discover`, `/explore`(별칭 관계), `/ranking`, `/recommend`, `/random`, `/now`, `/hub`가 각각 "발견"으로 읽힌다. 첫 방문자는 어디서 시작해야 할지 모른다.
- 마찰: `/` (공개 홈), `/home`(내 홈), `/hub`(둘러보기) — "홈"이 3개다. 이름만으로 구분이 안 된다.

### 여정 B — 창작 시작: 홈 → /create 시작 시트 → Studio
- 강점: `/create` 단일 시작 시트(새 작품·템플릿·이어가기)로 모은 결정은 옳다. `/make`, `/new`는 별칭으로 정리됨.
- 마찰: 시작 전에 겹치는 관문이 많다 — 진입 인트로, 연령 게이트, 창작자 적응형 온보딩 게이트, 취향 온보딩(`/onboarding/taste`), 캐릭터 온보딩(`/onboarding/character`), PWA 넛지. "첫 그림을 그리기까지"의 클릭·모달 수가 여정 자체보다 길어질 수 있다.
- 마찰: GNB에서는 "제작"이 곧 `/studio`이지만 전체 메뉴에서는 "작품 시작하기(/create)"와 "스튜디오(/studio)"가 같은 그룹에 나란히 있어, 초보자는 둘의 차이를 설명받지 못한다.

### 여정 C — 제작 → 검수 → 게시: Studio → /studio/publish → /publish(연재 센터)
- 강점: 로컬 저장·복구(SQLite/OPFS), RouteFallback의 실루엣 스켈레톤 + 4.5초 지연 안내 + 빠른 이동 링크는 동급 제품 대비 우수하다.
- 마찰: 게시 관련 표면이 셋이다 — `/studio/publish`(검수·내보내기), `/publish`(연재 센터), `/publishing`(별칭). 코드 주석(O-06)이 스스로 "본문이 다른 분화 표면"이라 적을 만큼 사용자 멘탈 모델과 어긋나기 쉽다.
- 마찰(기존 백로그 P1): 백엔드 다운 시 공개 페이지 셸이 초기 세션/헬스 체크에 매달려 멈출 수 있다. 게스트-퍼스트 가치와 정면 충돌. (이후 워밍업 상태 등이 도입됐으나 `/market` 재현 검증이 남아 있다.)

### 여정 D — 협업: /production, /team, /collaborate, /community
- 마찰: "협업"이라는 한 단어가 네 목적지를 가리킨다 — 제작 관리(`/production`), 팀·권한(`/team`), 구인·의뢰(`/collaborate`), 커뮤니티(`/community`). 헤더 드롭다운은 이 중 셋을 "협업" 아래 묶고 커뮤니티는 따로 둬서, 사용자는 매번 추측해야 한다.

## 5. 90점까지 남은 로드맵 (우선순위 순)

아래는 기존 테스트·문서가 "의도된 결정"으로 고정했거나 구조 변경이 커서, 별도 PR로 결정 변경과 함께 진행해야 하는 항목이다. 각각 완료 기준을 함께 적는다.

### P1. 내비 분류체계 단일화 (정보구조 +6점 예상)
- 현재 4벌: 헤더(`site-header.tsx` 자체 7개), 모바일 탭 5개, 전체 메뉴 그룹(`SITE_NAVIGATION_GROUPS` 6그룹), 사이트맵 전용 IA(`site-directory-data.ts`).
- 작업: 헤더와 사이트맵이 `SITE_NAVIGATION_GROUPS`를 소비하게 만들고, 표면별 차이는 "몇 개까지 보여줄지"로만 둔다. 그룹·순서·라벨은 전 표면 동일.
- 완료 기준: 분류체계를 정의하는 코드가 1곳. 같은 목적지가 표면마다 다른 그룹에 있는 경우 0건.

### P2. "홈/협업/게시" 동음이의 정리 (+3점)
- `/`(공개 홈)·`/home`(내 홈)·`/hub`의 라벨을 이름만으로 구분 가능하게: 예) 내 홈 → "내 작업실". `/hub`는 내비 라벨에서 "둘러보기" 유지하되 홈 계열로 읽히지 않게 한다.
- 게시 3표면(`/studio/publish`, `/publish`, `/publishing`)의 관계(검수·내보내기 → 연재 센터)를 각 화면 상단에 한 줄로 상호 링크한다.
- 완료 기준: 신규 사용자가 이름만 보고 세 홈/세 게시 화면의 차이를 말할 수 있다(5명 테스트).

### P3. 첫 진입 게이트 통합 (+3점)
- EntryIntro·연령 게이트·온보딩 게이트·PWA 넛지·계정 넛지의 노출 우선순위를 단일 큐로 통합하고, 첫 세션에는 최대 1개만, 나머지는 맥락 시점으로 미룬다.
- 완료 기준: 첫 방문 → 첫 편집 가능 상태까지 방해 요소 최대 1회.

### P4. 운세·놀이터의 격리 — ✅ 2차에서 완료
- "쉬어가기" 그룹 신설로 완료. 남은 검증은 사용자 테스트뿐이다.

### P5. 백엔드 장애 폴백 검증·완결 (상태 커뮤니케이션 +2점)
- UX_FLOW_BACKLOG P1 재현: API 다운 상태에서 `/market`, `/market/browse`, `/` 진입 시 5초 내 게스트 렌더링을 E2E로 고정한다.

### P6. 테마 행렬 축소 (+1점)
- 사이트 테마 10종+ 중 사용률 하위 테마를 정리하거나, 테마×표면 매트릭스 검증을 핵심 표면으로 축소해 QA 비용을 핵심 여정에 재투자한다.

### P7. 브레드크럼 잔여 커버리지 (+1점)
- 동적 상세(작품·카페·프로젝트)는 각 셸이 데이터 기반 브레드크럼(제목 삽입)을 표시하게 한다. 정적 커버리지 48% → 체감 커버리지 80%+가 목표.

**예상 도달: 79 + 6(P1) + 3(P2) + 2(P3) + 2(P5) + 1(P6) + 1(P7) = 94점** — P1은 분류체계 정의를 1곳으로 합치는 변경이라 PR의 CI 결과를 보며 반복 수정하는 방식으로 진행할 것.
