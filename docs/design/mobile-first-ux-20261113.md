## 1. 사용자 요청과 설계 결정

**모바일에서 다음 행동을 쉽게 고를 수 있게 하고, 하나의 긴 화면에 모인 기능을 목적별 화면으로 나눈다.** PC도 같은 정보 구조를 사용하며, 넓은 공간은 긴 기능 목록을 추가하는 대신 읽기 폭과 카드 배치를 조정하는 데 쓴다.

첨부 시안의 공통 방향은 잉크색 배경, 보라색 주 행동, 창작 아트, 콘텐츠·결과 우선 배치, 보조 기능 접기다. 현행 사이트의 테마·Pretendard·아이콘·브랜드 아트를 이어 쓰고 새 테마나 새 제작 엔진은 만들지 않는다. 시안에 보이는 보라색은 화면 계층을 설명하는 예시이며 실제 제품은 기존 `--color-*` 정본을 따른다.

| 원칙 | 모바일 적용 | PC 적용 |
| --- | --- | --- |
| 한 화면의 목적을 먼저 제시 | 제목 + 핵심 행동 1~2개 | 동일한 제목·행동, 제한된 본문 폭 |
| 목적 선택과 기능 목록 분리 | 전체 메뉴 → 목적 페이지 → 기능 | 같은 경로, 카드만 2열 배치 |
| 결과를 먼저 읽기 | 검색·정렬·필터 진입 뒤 실제 목록 | 추가 도구는 명시적으로 열기 |
| 이동할 때 맥락 보존 | URL·브라우저 뒤로가기·선택·초점 유지 | 동일 |
| 전문 도구는 작업 중에 열기 | 메뉴·패널·보조 페이지에서 진입 | 전체 기능에 동일하게 도달 |
| 상태를 구분 | 로딩·오류·빈 결과·기기 저장 위치 표시 | 동일 |

## 2. 현행 구조에서 확인한 문제

`SitemapPage.tsx`는 검색, 개인화, 규모 통계, 6개 맥락 허브, 제작 파이프라인, 서비스 단계, 목적별 시작, 개인 공간, 확장 목록을 한 화면에 쌓는다. 전체 메뉴 drawer도 7개 그룹을 펼쳐 목적지를 찾게 한다. 사용자는 메뉴를 열기 전 기능이 어느 그룹에 있는지 알아야 한다.

Workspace는 주 메뉴 5개와 제작 바로가기 6개를 함께 노출한다. 작업 내용이 적어도 메뉴의 시각적 무게가 유지된다. 같은 `/help`·`/settings`·`/studio`가 표면에 따라 다른 이름으로 보이고 `/home` 복귀를 가상 스튜디오로 부르는 지점도 있다.

Studio의 일반 새 작업 CTA는 기본 상태에서는 `/create`를 열지만, 보관함·휴지통·오류·검색 빈 결과에서는 `/studio/new`를 직접 연다. 같은 행동의 시작 화면이 달라진다. `/create`는 이미 두 가지 시작 선택을 제공하므로 이 흐름을 정문으로 유지한다.

## 3. 나눌 페이지와 구현 동선

```text
전체 메뉴 /sitemap
 ├─ 작품 시작하기 /create
 │   ├─ 이야기부터 시작 → 기존 기획 양식
 │   ├─ 바로 그리기 → 기존 캔버스 생성
 │   ├─ 템플릿 → /studio/templates
 │   └─ 파일 가져오기 → /studio/import
 ├─ 내 작업 /studio → 최근 작업 이어 하기 → 기존 문서 편집기
 ├─ 목적별 페이지 /sitemap/:section
 │   ├─ 작품 찾기 /sitemap/discover
 │   ├─ 만들기 /sitemap/create
 │   ├─ 자료·성장 /sitemap/grow
 │   ├─ 연재·내보내기 /sitemap/publish
 │   ├─ 함께 보기 /sitemap/connect
 │   ├─ 쉬어가기 /sitemap/rest
 │   └─ 내 기록 /sitemap/personal
 └─ 상세 디렉터리 /sitemap/all
```

`/sitemap`에서는 7개 목적과 두 가지 핵심 행동을 고른다. 목적별 화면에는 해당 그룹의 2~8개 목적지만 표시한다. 목적 페이지에는 전체 메뉴 복귀를 제공한다. 전문적인 전체 디렉터리는 `/sitemap/all`로 분리해 필요할 때 연다. 정식 목적지 주소와 기존 기능은 유지한다.

메뉴 검색은 기존 정본 이름·설명·주소를 검색한다. 일치 항목을 바로 열고, 없으면 검색어 지우기와 전체 디렉터리로 이어진다. 검색은 외부 API가 필요 없는 로컬 탐색이다. 계정·팀·프로젝트 접근 제어는 기존 라우터와 도메인이 계속 수행한다.

`/create`의 보조 시작 방법과 제작 도구는 URL로 구분한 화면에서 선택한다. 기본 화면은 이야기·그리기 두 선택, 템플릿·가져오기, 최근 작업을 우선한다. 결과 목록에서 상세 필터를 여는 기존 전체 화면 패널도 하나의 작업만 수행하는 보조 화면으로 유지한다.

| 시작 위치 | 사용자 행동 | 도착 화면 | 보존할 맥락 |
| --- | --- | --- | --- |
| 전체 메뉴 | 만들기 선택 | `/sitemap/create` | 전체 메뉴로 돌아가기 |
| 만들기 목적 페이지 | 작품 시작하기 | `/create` | 기존 생성·저장 소유자 |
| 작업 목록·보관함·오류 | 새 작업 | `/create` | 일반 생성의 일관성 |
| 작업 목록 | 이어서 작업 | 기존 문서·페이지 경로 | 문서 ID·마지막 페이지·저장 상태 |
| 탐색 결과 | 필터 열기·닫기 | 기존 필터 전용 패널 | URL 조건·선택·목록 위치·초점 |
| 작업 보조 페이지 | 작업 홈으로 | `/home` + 기존 허용 맥락 | 프로젝트 또는 개인 scope |

## 4. 첨부 16개 시안과 현행 구현의 정합성

아래 평가는 코드 구조 확인 결과다. 브라우저에서 16개 화면 전체를 검증했다는 의미는 아니다.

| 시안·경로 | 소스에서 확인한 현재 상태 | 재설계 적용·실현 가능성 |
| --- | --- | --- |
| 홈 `/` | `ReferenceCreatorDashboard`의 시작·둘러보기, 제작 순서, 접힌 보조 입력 | 주 행동을 유지하고 전체 기능 탐색을 목적별 메뉴로 연결. 이미지 추가 생성 없이 현행 아트 재사용 가능 |
| 시작 `/create` | `CreateStartPage`의 이야기·그리기 2개 카드, 별도 템플릿·가져오기, URL 구역 전환 | 기본·보조 구역의 중복 노출을 줄이고 한 구역만 읽게 구성 가능 |
| 내 작업 `/studio` | 최근 작업 강조, 새 작업·가져오기, 검색, 보관함·휴지통 | 상태별 새 작업 정문을 `/create`로 통일. 기기 저장·복구 안내 유지 |
| 캔버스 | 기존 tool rail·메뉴·레이어 패널·모바일 편집 크롬 | 시안의 콘텐츠 우선 원칙과 기존 모바일 구조를 유지. 브러시·저장·문서 엔진 교체 없이 메뉴 외곽 개선 가능 |
| 마켓 `/market` | `MarketHomePage`의 여러 추천·종류·사용권 섹션, `/market/browse` 별도 검색 | 구매·사용권 판단은 유지하면서 검색·소재 선택 우선으로 안내. 전문 분류는 별도 browse 목적지 사용 가능 |
| 제작 `/production` | guest 랜딩·샘플 진입·기존 프로젝트 화면과 접힌 도구 | 샘플과 실제 프로젝트를 구분하며 작업별 기존 프로젝트 하위 경로 활용 가능 |
| 탐색 `/discover` | 검색, 추천 상태, 탐색 도구 링크·선택 트랙 | 탐색 시작 허브로 유지. 검색·조건·랭킹·캘린더는 기존 별도 페이지로 연결 가능 |
| 조건 탐색 `/explore` | `ExplorePage`의 결과, URL 필터, 모든 장르·상세 필터 dialog | 주 조건만 노출하고 나머지를 전용 패널에서 조정하는 구조 재사용 가능 |
| 검색 `/search` | 별도 검색 경로와 목록·필터·URL 상태 소유 | 검색 결과를 앞에 두는 원칙 유지. 외부 API 실패와 빈 결과를 합치지 않음 |
| 랭킹 `/ranking` | 랭킹 보드 우선, 산식·시뮬레이터 `SiteDisclosure` | 핵심 순위 목록과 세부 설명 분리가 이미 존재. 별도 메뉴 분리와 함께 유지 가능 |
| 캘린더 `/calendar` | 선택 요일·일별 목록, 필터, `.ics`, 안내 접기 | 모바일 하루 목록·요일 선택 유지. 로딩·오류 시 편수를 확정하지 않음 |
| 작품 `/title/:slug` | 회차 우선, 소개·리뷰·추가 도구·관련 도구 details | 읽기·서재 주 행동 우선 유지. 관련 콘텐츠·기록은 보조 구역에서 접근 가능 |
| 읽기 `/title/:slug/read/:episode` | 자체 헤더·회차 이동·외부 플랫폼 안내 | 시안의 읽기 우선 구조 유지. 미제공 컷을 가상으로 생성하거나 진도를 성공 처리하지 않음 |
| 커뮤니티 `/community` | 통합 피드와 구역 전환, 안내·리그·홍보 접기 | 피드·구역별 기존 URL 상태 재사용. API 오류를 글 없음으로 표시하지 않음 |
| 학습 `/learn` | `LearnPage`가 홈·학습 경로·강좌·자료·기록을 별도 URL로 분리 | 이미 분리된 페이지들을 목적 메뉴에서 직접 연결 가능. 학습 기록 저장 경계 유지 |
| 리서치 `/research` | `CreatorHubPage`의 작업 단계·메모·보드 상태, 별도 자료·비교 경로 | 자료 검색 → 근거 저장 → 노트 흐름 유지. 상세 공급자·도구를 첫 화면에서 분리 가능 |

## 5. 화면·상호작용 명세

- 우선 검증 폭은 390px이며 320px·834px·1440px도 확인한다. 작은 화면에서 가로 스크롤을 만들지 않는다.
- 본문은 한 열, 목적 카드는 화면당 하나의 행으로 읽고 전체 행을 누른다. PC는 최대 두 열로 확장한다.
- 터치 조작은 기본 44px 이상, 검색 입력은 모바일 확대를 피하는 16px 이상을 사용한다. 키보드 포커스와 현재 위치를 색상 외에도 표시한다.
- 보라색은 주 행동·현재 위치에 사용한다. 새 팔레트 하드코딩 대신 기존 테마 토큰으로 light/dark/contrast를 함께 지원한다.
- 뒤로가기는 브라우저 기록과 명시적 상위 링크를 함께 제공한다. 문서 편집기는 기존 미저장 확인을 거친다.
- 메뉴 열기·닫기 초점 복귀, Escape, Tab 순환, 배경 inert를 보존한다. 화면 분리는 세션·문서 상태를 새로 만들지 않는다.
- 선호 모션 감소 설정을 존중한다. 이동·패널 열림에 180ms 이하의 짧은 피드백만 사용한다.

## 6. 구현·검증 경계

구현은 기존 단일 메뉴 지도, 라우터의 lazy 경계, Studio runtime authority를 재사용한다. 새 URL은 route manifest·캠퍼스 binding·공개 셸 판정에 함께 등록한다. 이전 디렉터리 query 주소는 상세 디렉터리로 이어져 필터·공유 링크를 보존해야 한다.

계획 검증: 메뉴 그룹별 목적지 보존·중복 제거, 일반 생성 정문, URL 상태·뒤로가기, drawer 접근성, 새 하위 route 매칭·unknown group 처리, 공통 하네스, 모바일/태블릿/PC 화면 증거. 실행 결과와 CI·PR·병합 여부는 작업 완료 보고에서 별도로 기록한다.

API 정상 데이터·로그인 계정·실제 GPU 브러시·외부 결제·실제 다중 사용자 협업은 정적 시안으로 검증할 수 없다. 정적 시안의 상태 예시는 연결 성공이나 운영 배포를 증명하지 않는다.
