## 화면을 나누는 기준

한 화면에는 한 가지 주 작업을 둔다. 작업이 바뀌면 URL이 바뀌는 화면으로 이동하고, 보조 메뉴·사용 설명·예시 이미지는 이름을 보고 펼친다. 단순히 색과 간격만 바꾸거나 기능을 접어 두고 완료로 세지 않는다. 모바일과 PC의 작업 순서와 메뉴 이름은 같다.

일반 공개 페이지의 하단 탐색은 정본 네 목적 **내 작업 `/studio` · 작품 찾기 `/discover` · 소재 찾기 `/market` · 내 정보 `/my`**와 별도 유틸리티 **전체 메뉴 `/sitemap`**를 유지한다. 7목적은 전체 메뉴 안의 기능 분류이며 하단 목적 체계를 새로 7개로 교체한 것이 아니다. 전문 편집기·리더·작업공간은 기존 표면 크롬과 현재 위치 계약을 유지한다.

## 드로잉과 전문 편집기

- 원고: 캔버스를 중심에 두고 펜·지우개·선택 등 핵심 도구를 유지한다. 전체 도구는 분류 선택 후 도구를 고른다. 더보기는 원고/그리기/출력/화면 목적별로 나눈다.
- 레이어·선택 속성: 이름이 드러나는 진입점을 제공하고 기존 패널과 명령을 호출한다. 그림 상태·Undo/Redo·렌더러·저장 권위는 원래 경계를 유지한다.
- 브러시 랩: 고르기/조절/입력·엔진/질감·톤을 URL별로 분리한다. 미저장 Workbench는 화면 전환 중 보존한다.
- 3D: 정밀 편집 안에서 장면/구도·작화/레이어의 3목적으로 속성 진입을 줄인다. 정밀 모드는 실제 버튼으로 여는 로컬 UI 상태이며 URL만으로 켜지는 화면과 구분한다. 기존 빠른 배경 작업의 정문은 유지한다.
- 캐릭터: 새 태블릿 레일은 15개 슬롯을 관련된 3분류로 나눈다. PC·모바일은 기존 6분류를 유지하며 기존 결과와 슬롯 조작을 잇는다. 3분류를 모든 폭에 새로 구현했다고 쓰지 않는다.
- Poser의 기존 전체화면 mannequin 정문은 목적에 맞아 유지했다. 뒤쪽 안내를 접으려던 변경은 철회했으며 캡처를 신규 본문 구현으로 집계하지 않는다.

## 레이아웃과 톤의 일관성

잉크 배경·보라 강조·전경/경계 색은 기존 테마 토큰, 글꼴은 Pretendard, 외곽 폭·거터는 공통 Container와 레이아웃 토큰을 우선 소비한다. 작업형 제목은 `--site-task-heading-size`를 쓰고, 연동 3화면은 `data-site-page-header-size="default"`로 일반 hero 크기와 구분했다. 문서 읽기·명시적 hero·몰입형 편집기까지 같은 큰 제목이나 카드로 덮지 않는다.

2026-11-13 표본 11주소 × 390/1440px에서 공통 글꼴·색상·거터 토큰과 가로 넘침 0을 확인했다. 후속 `/my`·API 키·연동·개발자 4주소 × 두 폭에서는 일반 작품 시작 경로와 작업형 제목 통일을 다시 확인했다. 이는 실제 관찰한 표본의 근거이며 443주소 모든 상태의 시각·조작 실험 통과를 뜻하지 않는다.

## 구현 적용과 검증을 구분한다

정본 감사 URL **443개**에서 실제 lazy page, 공통 UI와 분기를 추적했고 연결된 page source는 **243개**다. 구조 판정은 본문 직접 **59**, 공유 소비 **194**, 기존 목적 분리 유지 **135**, 별칭 **44**, 권한·표면별 검증 분리 **11**로 합계 443개다. 공유 헤더 한 개를 바꾼 것을 모든 본문 재설계로 세지 않고, 11개 밖의 경로에도 남아 있는 실계정·API·GPU·저장 권위 검증 조건을 별도로 유지한다.
