# 전수 경로 UI/UX 검사 · 2026-11-13

- 상태: **migration** — 후보 소스의 등록 경로 전수 관측과 최종 동결 소스의 핵심·신규 화면 보충 검사를 완료했다. 렌더링 관측을 전체 기능·인지 부하 개선 완료로 해석하지 않는다.
- 대상: 사용자 웹·Studio·관리자 경로의 등록 인벤토리 및 모바일·PC 렌더링 경계.
- 연결 문서: [모바일 재설계](./mobile-first-ux-20261113.md), [REA 공개 서비스 관찰](./mobile-ux-rea-20261113.md).

## 1. 검사 조건과 범위

기존 `scripts/audit-sitewide-visual-ux.mjs`와 정본 소스를 읽는 `scripts/lib/sitewide-audit-route-inventory.mjs`를 재사용한다. 기본 dark 테마에서 **390×844·1440×1000**, worker 2개, 전체 스크롤 관찰을 실행한다. 테마 전체·모든 저장 데이터·모든 권한 조합을 검사한다는 뜻이 아니다.

이 실행은 `http://127.0.0.1:5178`의 Vite 개발 서버를 사용한다. 게스트 세션 응답은 200 fixture이고 나머지 API는 503 fixture다. GPU·service worker를 비활성화한다. API 정상 데이터·로그인 계정·권한 내부 화면·실제 펜/3D·운영 번들의 성공을 증명하지 않는다. 색 대비는 별도 접근성 검증과 분리해 이 전수 실행에서는 제외했다.

## 2. 정본 인벤토리

| 분류 | 수 |
| --- | ---: |
| 인벤토리에서 생성한 고유 감사 URL | 443 |

정적 경로·명시 콘텐츠 ID 350개에는 학습 정본에 선언한 수업 ID가 포함된다. placeholder 93개는 실제 작품·사용자·팀 데이터가 아니라 `/visual-audit` 표본이다. 본문이 열려도 해당 리소스의 실데이터 동작 성공으로 집계하지 않는다. wildcard 소유 경로와 제외 사유·소스 파일·선언 위치는 원본 인벤토리에 남긴다.

경로 수집만으로 잡히지 않는 새 `/sitemap/:section`의 7개 실제 목적과 `/create`·`/market`·`/studio`의 명시적인 화면 선택 query는 보충 목록에서 별도로 확인한다.

## 3. 링크 점검

실제 클릭 여정과 별도로 비테스트 TSX **2,809파일**의 정적 JSX `href`를 수집했다. 628개 문자열 링크가 151개 고유 경로를 가리킨다. 명시 route 선언과 일치하는 경로는 138개, Studio/Admin wildcard 소유자에게 위임되는 경로는 7개다. 나머지 6개는 이미지·PDF·PPTX·라이선스·독립 오프라인 HTML이며 로컬 파일 존재와 HTTP 200을 확인했다.

이 검사에서 미구현 링크로 확정한 경로는 0개다. 동적 JSX 값 922개, 컴포넌트 내부에서 만드는 주소·조건부 실행·인증 후 주소·외부 사이트는 이 정적 검사로 검증하지 않았다. wildcard 일치만으로 하위 기능이 구현됐다고 판정하지 않는다.

## 4. 렌더링 결과 기록 기준

- `rendered`: 의미 있는 본문 준비를 관찰했다. 기능 전체 성공과 구분한다.
- `auth-gate`: 게스트에서 권한 안내 또는 인증 이동을 관찰했다. 권한 내부 페이지를 검사한 것으로 세지 않는다.
- `blocked`·`degraded`: 차단·대체 안내를 관찰했다. 정상 기능 성공과 구분한다.
- `not-ready`·`unobserved`: 제한 시간 안에 준비되지 않았거나 관찰할 수 없었다. 오류 원문·redirect·원본 화면을 보존한다.
- 작은 타깃·텍스트 잘림은 자동 탐지 후보이며 별도 화면 검토를 요구한다. 기존 스크립트의 40/44px 경고 기준을 WCAG 위반 확정 수치로 쓰지 않는다.
- 이 도구의 작은 타깃 검사는 주로 현재 viewport에서 조작 가능한 button·tab·select·textarea에 적용된다. 모든 링크·펜 동작의 기하 검사를 포함하지 않는다.

## 5. 진행 상태와 근거

본 감사 **886/886관측 완료, 누락 0**이다. 정적·명시 ID 경로 350개를 두 폭에서 700회, placeholder 경로 93개를 186회 방문했다.

| --- | ---: | ---: | ---: |
| 의미 있는 본문 관측 | 403 | 404 | 807 |
| 권한·인증 게이트 | 22 | 22 | 44 |
| 미준비·오류 | 17 | 16 | 33 |

가로 넘침, 고정 요소의 가로 넘침, 보이는 깨진 이미지, 조작 가능한 이름 없는 버튼은 각각 **0관측**이다. pathname이 바뀌는 redirect는 92관측이며 정본·레거시 이동과 함께 기록했다.

자동 도구의 issue 37관측은 다음 조건에서 발생했다. 이 37개를 운영 기능 결함 37개라고 해석하지 않는다.

- 프로젝트 placeholder와 API 503에서 `/production/projects/visual-audit/...` 16개 주소가 두 폭 모두 오류 상태를 표시했다: 32관측. 실프로젝트·인증 API 성공은 확인하지 않았다.
- GPU를 끈 상태에서 `/studio/{remix,work}/visual-audit/poser`, `/studio/character`의 일부 관측에 WebGL 컨텍스트 생성 오류가 발생했다: 4관측, 최종 수집 이벤트 15개. 실제 GPU 동작과 분리한다.
- 초기 `/canvas`가 `/studio/canvas`로 이동한 뒤 20초 안에 준비되지 않았다: 1관측. 같은 실행의 뒤쪽 직접 주소와 최종 동결 소스 보충의 fresh-context alias는 준비 상태에 도달했다. 초기 실패 근거는 지우지 않는다.

경고는 409관측이다. 작은 타깃 39, 10px 미만 텍스트 150, 텍스트 잘림 124, 이미지 준비 대기 42, 투명 텍스트 2관측 등이 포함되며 한 관측에 여러 경고가 중복될 수 있다. 다음은 원인별 해석이다.

- 모바일의 `공개 화면`과 Studio의 반응형 `sr-only` span은 의도적으로 1px·clip-path로 숨긴 접근성 이름이다. 감사기의 `.sr-only` 단일 클래스 제외만으로 반응형·CSS 숨김을 모두 판별하지 못한다. 이를 제품 텍스트 잘림으로 일괄 수정하지 않았다.
- PC Studio의 32~38px 고밀도 조작은 감사의 40px 경고 기준에 걸린다. spacing 등 세부 조건을 확인하지 않고 WCAG 위반으로 확정하지 않았다.
- 동결 전 모바일 검색의 43px 폭은 후속 코드에서 48px로 보완했으며 최신 핵심 화면에서 다시 확인한다. 최초 관측 수를 삭제하지 않는다.
- 가져오기 안내의 `whileInView` 애니메이션은 화면 밖에서 opacity 0일 수 있다. 실제 입력·오류 안내와 구분하고 reduced motion에서도 정보가 남는지 별도 검토 대상으로 기록한다.
- 외부 자료 이미지의 5초 준비 대기는 이미지 파손 확정과 구분한다.

최신 보충은 **78/78 완료·본문 준비 78·issue 0·누락 0**이다. 가로/고정 넘침·깨진 이미지·이름 없는 버튼은 0이고, 모바일 작은 타깃 경고도 0이다. PC `/search`의 31~37px 폭 장르 칩·36px 새로고침, `/market?section=explore`의 25.3px 높이 기존 미리보기 전환 버튼이 40px heuristic 경고에 해당한다. 모두 24px 이상이며 이 관측만으로 접근성 적합성을 확정하지 않는다. 그 외 경고는 의도적인 반응형 숨김 텍스트 3관측, 이미지 준비 대기 5관측, 작은 텍스트 10관측 등이며 중복된다. 런타임 48파일은 보충 실행 중 해시 변경이 없었다.
