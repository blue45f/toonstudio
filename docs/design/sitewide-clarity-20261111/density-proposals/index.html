길이와 정보 밀도 · 기존 시안 보완

기존 Starlight·Clarity 방향을 재사용한 세 가지 제안입니다. 실제 앱 캡처·기능 검증 완료가 아닙니다. 큰 분할 구현 전 화면을 공유하기 위한 정적 비교안입니다.

스토리 기획 목업작품 탐색 목업게시 정보 목업

스토리 기획 · 목적별 입력 묶음

A. 모든 입력 + 요약 고정

전체 항목을 동시에 비교하기 쉽지만, 모바일 긴 입력·저장 왕복은 남습니다.

B. 세 묶음 + 단계 직접 이동

비교 우선안. 인물·목표 → 갈등·세계 → 전환·결말. 저장과 초안 상태를 계속 보여주고8개 필드와 미저장 입력은 유지합니다.

C. 입력 / 미리보기 별도 화면

작업 목적은 명확해지지만 왕복과 초안 복원 부담이 큽니다. 현재 작은 워크시트에는 과도할 수 있습니다.

작품 탐색 · 검색과 추천의 순서

A. 검색 → 짧은 추천 → 결과

비교 우선안. 첫 화면에서 검색과 작품을 함께 찾고, 추천의 시각적 매력을 작은 카드로 유지합니다.

목업 열기 →

B. 추천 / 작품 목록 탭

두 목적이 분리되지만 실제 작품을 보려면 탭을 더 눌러야 합니다. 기존 검색·조건 상태를 두 탭에서 공유해야 합니다.

C. 추천을 별도 소개 화면

규모 있는 편집 콘텐츠에는 적합합니다. 현재 한 카드 때문에 경로를 추가할 근거는 아직 없습니다.

게시 정보 · 준비 순서

A. 기존 한 화면 + 결과 접기

수정량이 작고 PC 비교가 쉽습니다. 모바일의 입력→채널→상단 실행 왕복은 남을 수 있습니다.

B. 작품 → 정보·채널 → 결과

비교 우선안. 입력과 실패 상태를 보존하며 실제 JSON 준비와 외부 게시를 구분합니다.

목업 열기 →

C. JSON / 피드를 목적별 화면

사용 목적은 분명하지만 경로와 복귀 계약이 늘어납니다. 실제 사용하는 빈도와 복잡도를 먼저 확인해야 합니다.

작업 목록 신규 상태

실제390/1440 기존 캡처와 같은 소스에서 중복 시작 행동을 확인했습니다. 새작업·복구는 유지하고 대체 방식은 기존 native 접기 패턴을 재사용합니다. 구현 담당은 별도 배정됐습니다.

학습 상세

본문을 먼저 읽게 하고 목차·단축키만 이름 있는 보조로 접는 안입니다. PC sticky 보조와 긴 수업 본문은 유지합니다. 실제 새 렌더로 확인 후 판정합니다.

길이 수치는 판정의 보조

원고·수업 본문의 긴 길이는 사용 목적에 맞을 수 있습니다. auth gate·503·로딩 화면과 정상 populated 화면을 섞지 않습니다.
