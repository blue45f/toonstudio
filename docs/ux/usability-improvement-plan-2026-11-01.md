## 1. 목표와 범위

사용자가 설명서를 읽지 않아도 작업을 찾고, 시작하고, 제작하고, 안전하게 저장한 뒤 결과물을 꺼낼 수 있게 한다. 초보자에게는 필요한 선택만 먼저 보여 주고 숙련자에게는 기존 단축키·세부 설정·작업공간을 유지한다. 새로운 기능의 개수보다 과업 성공, 오류 복구, 작업 보존을 우선한다.

전체 범위는 공개 페이지, 로그인·계정, 프로젝트 목록·생성, 2D/컷·대사·브러시·레이어, 에셋, 캐릭터·3D, 저장·버전·가져오기·내보내기, 제작·협업·검수, 게시, 마켓·구매·구독·사용량, 메시지·알림, 커뮤니티·학습·도움말, 설정, 관리자·권한별 화면이다. 코드에 존재하더라도 미공개·레거시·실험 경로는 숨기지 않고 별도 상태로 등록한다. 결제·공유·게시·삭제는 운영 실데이터로 시험하지 않는다.

사용자에게 보이는 시작점은 **내 작업 → 새로 만들기/이어하기 → 편집 → 저장·복구 → 내보내기/공유**로 정돈한다. 전문 3D/협업 기능은 별도 과업군으로 검증하며 기본 흐름의 점수를 전체 서비스 점수로 표현하지 않는다.

## 3. 화면·기능 전수 목록의 정본

정본 입력은 `apps/web/src/app/routes/route-manifest.ts`, `groups/*.routes.tsx`와 실제 내비게이션·편집기 패널이다. 마지막으로 관측한 `apps/web/src/domains`에는 creator, auth, account, collaboration, market, monetization, messages, community, learn, integrations, admin 등 영역이 존재한다. 과거의 고정 URL 개수를 최신 전체 화면 수로 재사용하지 않는다.

전수 목록의 한 행은 단순 URL이 아니라 **경로/패널 × 역할 × 대표 과업**이다. 동적 project/document/team/work ID는 합성 데이터로 채운다. 도달할 수 없는 화면은 `blocked`로 남기고 점검 수에서 빼지 않는다.

## 5. 우선순위와 실행 배치

배치 순서는 아래와 같다. 기간을 확정한 일정표가 아니며, 각 단계는 선행 gate의 실제 결과에 따라 착수한다. 담당은 역할 기준이며 특정 다른 채팅에 일방적으로 작업을 배정하지 않는다.

### P0 — 기존 과업의 실패·작업 손실부터 제거

UI/상태 담당과 검증 담당이 함께 처리한다. 프로필390px 설정왕복, 저장 성공 오표시·중복 제출·세션 경합, 키보드로 빠져나오지 못하는 화면, 일반 사용자의 접근 불가를 최우선으로 둔다. 재현 테스트가 실패하는 것을 먼저 확인하고 원인을 최소 범위로 고친다. 저장·권한·결제 장애는 단순 시각 감점으로 축소하지 않는다.

### P1 — 기본 제작 동선과 시각 위계 통일

탐색→생성→편집→저장→재열기→내보내기를 같은 합성 프로젝트로 묶는다. 한 화면에 하나의 주 행동을 두고, 상세설정은 선택적으로 연다. 오류가 있는 입력으로 이동하는 링크와 작업으로 돌아오는 링크를 통일한다. 주요 화면의 제목·버튼·입력·패널 간격·선택/비활성/오류 토큰을 대조해 인라인 예외를 줄인다. 초기 화면은 작업 캔버스와 다음 행동을 가리지 않도록 한다.

### P2 — 모바일·키보드·접근성 품질 마감

320/390/768/1440px, 필요한 가로 화면·짧은 높이, light/dark/contrast, 확대·긴 문구를 대조한다. 조작 대상·초점 표시·가상키보드 가림·safe area·본문 스크롤·패널 스크롤을 확인한다. 한글 조합의 Escape/Enter와 선택/접기/textarea의 기본 동작을 보존한다. 이번 PR의 팔레트 보완은 이 단계의 일부이며 전체 단계 완료가 아니다.

### P3 — 전문 도구·협업·비용 수반 과업

실제 3D/Worker/WASM·외부 DCC와 일반 2D 검증을 구분한다. 협업은 두 사용자·두 문맥의 동작으로, 결제는 샌드박스와 승인된 합성 계정으로 검사한다. 고급 기능도 입력 범위·처리 상태·실패 복구·지원 환경을 기본 흐름과 같은 문구 규칙으로 정리한다.

### P4 — 사용자 관찰·최종 통합·회귀 방지

초보자와 숙련 사용자가 설명 없이 대표 과업을 수행하도록 관찰한다. 초기 제안은 초보자8명·숙련자4명, 수정 후 별도 회차이며 모집·동의 전에는 실행된 것으로 기록하지 않는다. 이 작은 표본은 문제 발견용으로 사용하고 전체 사용자 성공률95%를 통계적으로 입증했다고 해석하지 않는다. 한 번의 final main에서 관련 통합 검사를 묶고 배포 여부는 별도 승인·상태로 관리한다.

## 7. 디자인·상태·문구의 공통 규칙

**정보 위계:** 화면 제목→현재 문맥→주 행동→선택 설정 순서를 기본으로 한다. 비슷한 버튼을 여러 번 복제해 생성·결제를 중복시키지 않는다. 버튼은 결과가 드러나는 동사+대상으로 쓴다. 예: `현재 페이지 PNG 다운로드`, `프로필 저장`, `초안 버리기`.

**상태:** 준비 중·빈 화면·필터 결과 없음·권한 없음·연결 끊김·저장 중·저장 실패·동기화 충돌을 같은 ‘오류’로 합치지 않는다. 각 상태에서 재시도·필터 초기화·이전 화면·지원 경로 중 실제 가능한 행동을 제시한다. 완료 안내는 서버/파일/문서의 실제 결과 뒤에만 표시한다.

**밀도·가독성:** 기존 디자인 토큰을 쓰고 화면별 글자·버튼·간격을 제멋대로 바꾸지 않는다. 긴 한영 문구·파일명·페이지 수가 레이아웃을 밀지 않도록 줄바꿈·축약·전체보기 기준을 정한다. 색상만으로 선택·오류·저장 상태를 전달하지 않는다.

**조작:** 제품 내부 목표로 주요 터치 조작은44 CSS px 이상을 지향한다. WCAG2.2 AA의2.5.8 최소24×24 또는 간격/예외와 이 내부 목표를 구분한다.[R3] 초점은 시각적으로 찾을 수 있어야 하고 작성자 콘텐츠에 완전히 가려지지 않아야 한다.[R2] 팝업의 Tab 순서·Escape·닫은 뒤 복귀는 모달의 소유 관계를 유지한다.[R1]

**움직임·기기:** reduced motion을 존중하고 장식 연출이 입력 가능 상태를 늦추지 않게 한다. 새 모바일 기능이나 권한 요청을 먼저 늘리지 않고 이미 가능한 과업과 제한을 짧게 알린다. 펜·터치·키보드가 같은 결과를 내는지 확인하고 드래그 전용 조작에는 실행 가능한 대안을 둔다.

## 8. 검증 설계

### 단계별 증거

1. **정적/순수 로직:** 변환·상태·타입·금지 경계. 코드 파싱은 전체 타입 검사로 표현하지 않는다.
2. **컴포넌트:** 실제 React/DOM의 입력·초점·오류·취소·키보드. jsdom은 화면 배치·가상키보드·실파일 성공을 증명하지 않는다.
3. **브라우저:** 실제 앱에서 문서 저장·재열기·다운로드·화면 이동. 테스트용 계정·데이터와 장애 주입 범위를 명시한다.
4. **실기기/사용자:** OS 한글 입력기, 모바일 키보드, 펜 입력, 스크린리더, 처음 쓰는 사람의 이해를 관찰한다.
5. **최종 통합:** 같은 코드/lock/빌드의 증거를 연결하고 PR 병합·실배포를 분리한다.

### 대표 환경

- 화면: 320, 390, 768, 1440px; 작은 높이/가로 화면; 필요 과업의 200% 확대.
- 테마/언어: light/dark/contrast, 한국어·영어, 긴 이름·빈 값·대량 목록.
- 브라우저: Chromium/Firefox/WebKit. WebKit 자동화가 실물 iPhone 검증을 대체하지 않는다.
- 입력: 마우스, 터치, 키보드/Shift+Tab, 한글 조합, 펜. 보조기술은 최소 실제 VoiceOver 경로를 따로 기록한다.
- 상태: 신규/기존 데이터, offline/느린 응답/5xx/권한 없음/만료/취소/뒤로가기/재열기.

모든 조합을 무작정 병렬 실행하지 않는다. 모든 주요 과업은 모바일·데스크톱 기본 조합을 통과시킨 뒤 변경 위험에 따라 추가 조합을 선택하고, 미실행 조합은 목록에 남긴다. 중앙의 단일 중량 검사·병합 순서를 유지한다. 실패시 원인 분석 없이 제한시간을 늘리거나 skip으로 처리하지 않는다.

## 9. 95점 평가 방법과 종료 조건

내부 전문가 평가이며 WCAG 인증 점수나 테스트 통과율이 아니다. 항목20개×5점으로 평가한다. 미관만으로 데이터 손실을 상쇄하지 않는다.

| 영역 | 세부 항목 | 배점 |
| --- | --- | --- |
| 과업 성공·작업 안전 | 생성, 편집, 저장, 재열기/복구, 내보내기, 권한/협업 안전 | 30 |
| 동선·용어의 직관성 | 진입/찾기, 다음 단계, 되돌아오기, 용어/도움말 | 20 |
| 시각 위계·가독성 | 주 행동, 정보 밀도, 글자·대비, 상태·컴포넌트 일관성 | 20 |
| 모바일·접근성 | 화면/키보드 가림, 키보드/보조기술, 터치/펜/IME | 15 |
| 오류 복구·피드백 | 예방/입력 복구, 비동기 상태·취소, 재시도/오프라인 | 15 |

점수 앵커는 0=과업 불가/손실, 1=중대한 장애, 2=빈번한 도움 필요, 3=일반 상황 가능하나 혼선, 4=주요 상황 독립 수행·경미한 불편, 5=해당 범위의 실제 검증·사용자 관찰에서 중대한 혼선 없음이다. **미확인은 null**로 두며 분모를 줄여95점으로 만들지 않는다. 현재 모든 항목의 종합 평가는 미산정이다.

95점 완료는 다음을 모두 충족해야 한다.

- 고정한 전체 범위의20항목에 근거를 부여하고 합계95 이상. 역할·전문 기능·실험/제한 환경의 남은 범위를 공개한다.
- 핵심 제작 과업 실패·데이터 손실·권한 오인·거짓 저장완료·접근 불가·중복결제의 미해결 항목0.
- 이번 변경의 관련 회귀와 최종 main의 필수 gate에 미확인 실패 없음. 자동 a11y만으로 전체 준수를 선언하지 않는다.
- 모바일·데스크톱의 주요 과업을 실제 결과(문서/파일/서버)로 확인하고, 사용자 관찰에서 발견된 치명적 혼선을 닫는다.
- 합쳐진 소스의 점수와 운영 서비스의 점수를 구분한다. 운영 미배포라면 운영95점이라고 쓰지 않는다.

## 10. 이번 PR 구현과 검증 경계

구현은 (1) 팔레트 Tab 경계에서 기본 스크롤 허용, (2) 하위 dialog/alertdialog/native dialog의 Tab·Escape·Shift+Q 소유권 보존, (3) 숨김/inert 팔레트와 비활성 복귀 대상 제외, (4) 짧은 화면에서 최소14rem이 최대높이를 덮는 클래스 제거다. 기존 명령 실행·문서/세션 저장·캔버스 동작·타이머 수·외부 의존성은 바꾸지 않는다.

새 회귀 파일에는23개 React/DOM 사례를 작성했다. 이 문서 작성 시점에는 **저장소 React 실행·전체 Web/API·실제 앱 브라우저 검증은 미실행**이다. 독립 컨테이너에서 실제 훅 소스의 콜백을 React lifecycle/DOM 대역으로 실행한36시나리오는 원본13통과·23기대위반, 수정본36통과다. 23위반은 서로 다른 제품 결함23개를 뜻하지 않는다. 레이아웃·OS 입력기·React 렌더의 증거로 사용하지 않는다. 화면 높이 보정은 브라우저에서 별도 확인해야 한다.

처음 게시하는 PR은 검토용 Draft다. 최신 사용자 요청에 따라 먼저 게시하되 로컬 commit/push 훅을 실행한 것처럼 표시하지 않는다. 정식 gate와 별도 중앙 배정 전까지 Ready/배포 완료로 올리지 않는다.

## 11. 운영 방식과 보고

각 PR에는 문제→재현→최소 변경→실제 증거→미실행 항목→영향 범위→되돌릴 커밋을 적는다. 기능1단위와 그 테스트를 같은 PR에 묶고, 이번 마스터 계획으로 후속 일을 추적한다. 거대 단일PR과 같은 범위의 중복PR 모두 피한다.

진행 보고는 구현/단위/브라우저/사용자검증/병합/배포를 별도 열로 둔다. 현재95점을 선언하기보다 무엇이 남았고 어떤 증거로 닫을지를 제시한다. 본 계획은 백그라운드 자동 실행이나 무기한 작업 예약이 아니다.
