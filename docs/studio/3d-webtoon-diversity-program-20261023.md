# 3D 웹툰 다양성 고도화 프로그램 (2026-10-23)

- 문서 상태: **목표(target) + 현재(current) 혼합** — 2절만 현재 사실(2026-10-23 조사, HEAD `049b1ed94`)이고 나머지는 목표다. 코드·테스트가 이 문서와 다르면 코드가 기준이다.
- 짝 문서: `docs/studio/3d-asset-intake-reuse-map-20261023.md`(반입 체계 지도), `docs/evidence/render-qa/2026-10-23-metal-baseline/`(Metal 기준선), `apps/character-lab/docs/webtoon-style-guide.md`(웹툰 L1 지표).
- 범위: `apps/character-lab`(캐릭터 랩), Studio 의 캐릭터 셰이퍼·3D 데생 인형·VRM 포저·3D 배경(BG3D). 경쟁 도구는 Clip Studio Paint(CSP) 3D 와 네이버웹툰 SHAPER.

## 1. 요구 (사용자 2026-10-23 지시)

1. 일본·한국 웹툰 풍의 **다양한 캐릭터와 다양한 배경**으로 고도화할 방향을 설계하고 진행한다.
2. character-lab 을 3D 세이퍼 도구와 함께 최대한 고도화하고, 3D 데생 인형을 포함한 모든 3D 기능의 고도화 계획을 세워 **더 고도화가 필요 없을 때까지** 진행한다. 목표는 CSP 3D·SHAPER 대비 "200% 우수", 다양성 확보.
3. 헤어 설정, 의상 변경 등 **모든 기능의 현황을 실제로 파악**한다("어설픈 게 한둘이 아니다") — 문서가 아니라 조작해 본 결과로.
4. 캐릭터가 **다양한 화풍(art style)** 에 맞게 다양성을 지원한다.
5. **3D 배경이 너무 단순**하다 — 최대한 고도화한다.
6. VARCO 포인트는 아끼지 않고 소진한다(생성물은 PRIVATE, 다운로드·저장소 커밋 없음).
7. **커스터마이즈 우선(2026-10-23 18:13 추가 지시)**: "만든 캐릭터들은 의상이나 헤어 등등 최대한 커스텀 가능하도록, 배경도 마찬가지로 많이 만들기보다는 다양하게 커스텀 가능하게". 완성품 개수가 아니라 **조합·파라미터로 만들 수 있는 구성 공간의 크기**가 다양성의 1차 지표다. 이 지시는 6항(VARCO 대량 생성)보다 뒤에 온 것이므로 완성품 대량 생성은 중단하고, 커스터마이즈 가능한 구조에 힘을 싣는다(VARCO 산출물은 헤어·의상이 한 덩어리로 융합된 단일 메시라 조합이 불가능하다).

### 2.3 경쟁 (C, 2026-10-23 웹 확인)

- CSP 5.0(2026-03-11): 3D 손 모델·핸드 스캐너·UV 객체 직접 그리기·퍼스자 정렬. PRO $63 / EX $277(LT 변환은 EX). 포즈 소재 30,000+ 는 공식 주장. 포즈 스캐너는 기술 프리뷰·서버 업로드.
- SHAPER: 2026-04-23 정식 출시(Windows/macOS 설치형, 무료는 보도 1건). 프리셋·포즈·캐릭터 수는 공개 정보가 없다.
- **공개 근거로는 "동등 이상"을 주장할 수 없다.** 동일 과제 실측·SHAPER 실행 비교·외부 앱 PSD 열기 검증이 0건이다. 우위는 폭(가져오기 형식, 64샷 일괄 렌더, 무설치 웹, 권리 원장), 열세는 깊이(웹툰 미형 얼굴, authored 헤어·의상, 배경 규모, 원근 정렬, 손 모델, 포즈 규모)다.

### 2.4 콘텐츠 공급과 권리 (D)

- 키트 어휘 32 중 **24칸(헤어 7·상의 5·하의 5·신발 4·소품 3)이 비어 있고 계약 변경 없이 채울 수 있다**.
- 일본·한국 웹툰풍 캐릭터 본체를 합법적으로 들일 외부 소스는 사실상 없다 → 키트 베이스(HBM CC0 파생) 위 자작 파츠가 스타일이 맞는 길이다.
- 배경·조명·재질은 Poly Haven·Kenney CC0(2026-10-23 재확인)가 가장 빠르고 깨끗하다. HDRI 는 3종뿐.
- **새 위험**: Quaternius 현행 라이선스 페이지가 CC0 가 아니라 QAL v1.0(자산 재배포 금지)으로 읽힌다. 저장소에 VRM 25개(57.6 MiB)가 이미 있다. Tripo `mcp-free-v1` 10종이 카탈로그에 노출 중이고 자체 LICENSES.md 가 CC0 아님을 선언한다. 병합된 GLB 는 다음 정적 배포 때 R2 로 나가고 철회해도 R2 객체가 남는다.
- 생성 AI 산출물(Hyper3D·Tripo·Meshy·VARCO)은 공개 저장소에 반입할 수 없다.

## 5. 설계 원칙

1. **권리**: 반입 콘텐츠는 `original`(자체 제작) 또는 증빙된 CC0 만. 생성 AI·경쟁 도구 에셋·구입 번들(hold)은 쓰지 않는다. VARCO 산출물은 사용자 계정 안의 비공개 참고 라이브러리이며 저장소와 정적 배포에 들어가지 않는다.
2. **품질은 눈으로**: 수치 통과는 품질이 아니다. 파츠·화풍·배경은 접촉 시트를 만들어 사람이 보고 고친다(절차 생성 캐릭터 폐기 전례).
3. **연결 우선**: 이미 있는 순수 모듈(렌즈·소실점·스크린톤·MToon·장면 구성 프리셋)을 먼저 화면에 연결한다.
4. **구조**: 800줄 래칫 헤드룸 0 파일에는 줄을 더하지 않고 새 모듈로 빼낸다. 계약 변경은 한 묶음(레시피 v3·마이그레이션·검증기·Blender 도구)으로 core 가 먼저 한다. 새 영역은 `architecture.test.ts` 규칙부터 바꾼다.
5. **한 회차 한 논리 변경**: 에이전트마다 파일 소유권을 분리하고 커밋은 메인이 한다.
6. **구성 공간 우선**: 완성품을 늘리기 전에 모듈·역할 색·형태 슬라이더·레이어·화풍 파라미터를 만든다. 새 파츠는 독립 재질 역할 2~3개, `shape:*` shape key, 균일 UV(TEXCOORD_1)를 갖춰야 반입한다. 완성품(고정 캐릭터·고정 장소)은 시작 레시피로만 둔다.
