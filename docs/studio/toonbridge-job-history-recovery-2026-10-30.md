# ToonBridge 작업 이력 복구와 범위 보존 — 2026-10-30

상태: **migration**. 로컬 구현과 집중 회귀를 검증하는 변경이며 원격 병합·운영 제공 완료 기록이 아니다.

## 현재 변경의 목적

기존 작업 큐는 이 기기에 이미 저장된 실행 중 작업만 조회했다. 연결된 로컬 실행기에만 남아 있는
작업은 새 화면에서 발견하지 못했고, 이전 프로젝트의 늦은 저장·조회 결과가 현재 프로젝트 목록이나
저장 상태에 반영될 수 있었다. 새 복구는 이력 로드를 마친 뒤 실행기 목록을 조회해 현재 프로젝트의
작업을 기존 이력과 합친다. 진행 중 추가한 로컬 기록과 더 최신인 상태를 유지한다.

프로젝트·저장소·연결 client가 바뀌거나 화면이 닫히면 해당 세대의 요청을 취소한다. A→B→A 전환에서도
첫 A의 결과를 새 A에 적용하지 않는다. 이미 수락한 저장은 원래 저장소·정규화된 프로젝트 key의
queue에서 끝내되, 완료·실패가 새 범위의 목록·저장 상태·알림을 바꾸지 않게 한다. 같은 key로
돌아온 화면은 앞서 수락한 저장을 기다린 뒤 읽고, 다른 프로젝트의 이력 로드를 함께 막지 않는다.

## 로컬 이력과 지운 기록

기존 `studio-production-jobs-v1`의 배열 JSON과 프로젝트 key를 유지한다. 오래된 로컬 기록의 inline
`projectId`가 key와 다르다는 이유로 이력을 지우지 않는다. 새 실행기 목록은 현재 프로젝트와 정확히
일치하는 작업만 받으며, 개별 상태 조회는 요청한 ID·remoteId·기존 기록의 프로젝트를 대조한다.

사용자의 “기록 지우기”는 실행기 작업이나 산출물을 삭제하지 않는다. 별도 로컬 namespace
`studio-production-jobs-removed-v1`에 같은 범위의 숨김 ID를 기록해 늦은 목록 응답·재연결·화면 재진입이
지운 기록을 되살리지 못하게 한다. 같은 ID여도 다른 프로젝트의 기록은 독립적으로 유지한다.
숨김 원장을 먼저 쓰고 이력 배열을 갱신한다. 두 KV 쓰기는 원자적이지 않으며, 두 번째 쓰기가
실패해도 다음 읽기는 숨김 원장을 적용한다. 저장 실패는 이 탭에만 보관한다는 안내로 드러낸다.
이력이나 숨김 원장을 읽지 못하면 삭제 여부를 추측해 자동 목록 복구를 진행하지 않는다.
숨김 저장이 실패한 세대는 뒤의 일반 저장이 성공해도 영속 저장 완료로 표시하지 않는다.
같은 저장소·프로젝트에서 실행기 연결만 바꾸면 현재 탭의 미저장 이력·숨김 상태도 새 요청 세대에
인계한다. 연결을 바꿨다는 이유로 임시 작업을 버리거나 저장 완료로 바꾸지 않는다.

## 실행과 재시도

자동 복구와 주기적인 상태 갱신은 목록·상태 조회만 한다. `createJob`·`uploadInput`·`startJob`을
자동으로 재전송하지 않는다. 진행률 응답이 polling 간격을 우회하거나 같은 조회를 중복 시작하지 않는다.
사용자가 시작한 준비 요청 도중 범위를 바꾸면 이후 업로드·실행을 이어 보내지 않는다. 실행기에
이미 만들어진 작업은 나중에 조회로 확인하며, 처리 여부가 불명확한 요청을 자동 재실행하지 않는다.
연결 해제·주소 편집·다른 연결 확인 뒤 도착한 이전 연결 응답도 현재 설정이나 탭 저장 값을 복원하지 않는다.

## 검증 범위

집중 회귀는 repository·복구 hook·연결 hook·실제 작업 큐의 네 파일을 단일 worker로 실행한다.
이전 저장의 성공·실패와 A→B→A, repository·연결 교체, 닫힌 목록·poll 응답, 삭제 기록 보존,
StrictMode와 polling 간격, 이전 준비 요청이 업로드·실행으로 이어지지 않는 동작을 검증한다.
전체 타입 검사·전체 하네스·Web 빌드·원격 CI와 운영 배포는 별도 실행 결과로 구분한다.

`3cc8e878dccc53bd96b72052173d3d7b56954dde` 기준의 별도 작업트리에서 네 집중 테스트 파일
41개가 단일 worker로 종료 코드 0을 반환했다. 이 실행에는 전체 타입 검사·전체 하네스·빌드와
브라우저·GPU·Blender 검증을 포함하지 않았다.
