# 회의 우선 로컬 효과음 검수 — 2026-11-04

상태: current. 클라우드에서 재현·수정한 범위다. 실제 마이크·상대 미디어 연결 성공을 뜻하지 않는다.

## 재현한 문제와 변경

- 환경음은 기존 회의 우선순위 원장을 구독하지만 효과음 엔진은 구독하지 않았다. 회의 입장 후에도 발소리·작동음의 마스터 음량이 그대로였다.
- 기본 2D 입장·착석 알림음의 `talking` 옵션은 실제 호출에서 빠져 있었다. 같은 회의 원장을 읽어 새 알림음을 기존 대화 감쇠 비율로 낮춘다.
- 효과음 끄기는 이후 소리만 막고 이미 재생 중인 마스터 게인은 낮추지 않았다. 꺼짐을 실제 출력 0에 반영한다.
- 효과음 엔진은 회의 입퇴장 시 기존 게인을 부드럽게 바꾼다. 설정한 음량은 덮어쓰지 않으며 마지막 회의가 끝나야 원래 음량으로 복귀한다. 회의 종료가 사용자 음소거를 해제하지 않는다.
- 모바일 청음 버튼의 터치 영역을 44px 이상으로 맞췄다.

새 미디어 권한·네트워크 전송·자동 재생·음원 다운로드는 추가하지 않는다. 엔진 생성·회의 상태 변경만으로 AudioContext를 만들지 않고 기존 사용자 제스처 경로를 유지한다. 엔진 해제 시 회의 구독도 정리한다.

## 검증

- 새 회귀 시험은 수정 전 3건 실패, 기존 31건 통과였다. 수정 후 효과음·2D 공간 큐·환경음·설정 컴포넌트 4개 파일 54개 시험이 통과했다.
- 실제 Chromium에서 실제 설정 컴포넌트·WebAudio·회의 우선순위 원장을 사용했다. 통화 자체는 만들지 않고 검증 화면에서 로컬 회의 상태만 전환했다.
- 효과음 기본 음량 0.7은 회의 중 0.105, 사용자가 0.4로 바꾸면 0.06이었다. 효과음을 끄면 0, 회의를 끝내도 0을 유지했다. 다시 켜면 저장한 0.4로 돌아왔다.
- 2D 새 알림음은 회의 중 0.01625, 종료 후 0.065였다. 설정·레이아웃은 실제 UI로 조작하고 네이티브 AudioParam 호출을 계측했다.
- 다시 열었을 때 사용자가 고른 효과음 음량 40%가 유지됐다. 첫 사용자 조작 전 AudioContext 생성은 0개였다.
- 320px·1440px 화면에서 청음 버튼 높이 44px 이상, 가로 넘침 0, page error 0을 확인했다.

재현 화면: 개발 서버의 `/tools/browser-harnesses/virtual-studio-audio-focus.html`. 실제 설정 UI와 소리 엔진을 사용하며 통화·서버·장치 권한 검증은 대신하지 않는다.

실제 두 기기 통화, 화면 공유, 장치 제거·재접속과 모든 테마의 독립 공간 검수는 후속 범위다. 기존 클라우드 UDP 정책은 변경하지 않았다. 전체 타입·사전 푸시와 원격 CI 결과는 PR 실행 기록으로 구분한다.
